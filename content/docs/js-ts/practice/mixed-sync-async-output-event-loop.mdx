title: "Mixed Sync + Async Output (Event Loop)"
---

> Sync code, microtasks (promises, `await`, `queueMicrotask`) and macrotasks (timers) mixed together — with a queue walkthrough for every answer.

## M1. A zero-delay timer still waits for sync code · `easy` · 🖨️ Output

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
console.log('3');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1
3
2
```

**Queues walkthrough**

| Step | Call stack / action | Microtask queue | Macrotask queue | Output |
|---|---|---|---|---|
| 1 | `log('1')` | – | – | 1 |
| 2 | `setTimeout` registers callback | – | [log 2] | |
| 3 | `log('3')` | – | [log 2] | 3 |
| 4 | Stack empty → run timer | – | – | 2 |

**Order:** `1 3 2`

**Takeaway:** `setTimeout(fn, 0)` means "run after the current script finishes and the timer is due", never "run now".

</details>

## M2. Promise callback beats a timer · `easy` · 🖨️ Output

```js
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('sync');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
sync
promise
timeout
```

**Queues walkthrough**

| Step | Call stack / action | Microtask queue | Macrotask queue | Output |
|---|---|---|---|---|
| 1 | `setTimeout` | – | [timeout] | |
| 2 | `.then` on a fulfilled promise | [promise] | [timeout] | |
| 3 | `log('sync')` | [promise] | [timeout] | sync |
| 4 | Script done → drain microtasks | – | [timeout] | promise |
| 5 | Next macrotask | – | – | timeout |

**Order:** `sync promise timeout`

**Takeaway:** After each macrotask (the script itself is one), the whole microtask queue is drained before the next timer runs, even if the timer was scheduled first.

</details>

## M3. The promise executor runs synchronously · `easy` · 🖨️ Output

```js
console.log('A');
const p = new Promise((resolve) => {
  console.log('B');
  resolve('C');
  console.log('D');
});
p.then((v) => console.log(v));
console.log('E');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
A
B
D
E
C
```

**Queues walkthrough**

1. `A` is logged.
2. `new Promise` calls the executor **immediately**: logs `B`, fulfils `p` with `'C'` and keeps going (`resolve` does not return early), logs `D`.
3. `p.then(...)`: `p` is already fulfilled, so the callback goes straight into the microtask queue → `[log C]`.
4. `E` is logged; the script ends.
5. Microtasks drain → `C`.

**Order:** `A B D E C`

**Takeaway:** The executor is plain sync code; only the `.then` callbacks are asynchronous.

</details>

## M4. `queueMicrotask` and `.then` share one FIFO queue · `easy` · 🖨️ Output

```js
queueMicrotask(() => console.log('1'));
Promise.resolve().then(() => console.log('2'));
queueMicrotask(() => console.log('3'));
console.log('4');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
4
1
2
3
```

**Queues walkthrough**

| Step | Action | Microtask queue | Output |
|---|---|---|---|
| 1 | `queueMicrotask` | [1] | |
| 2 | `.then` on fulfilled promise | [1, 2] | |
| 3 | `queueMicrotask` | [1, 2, 3] | |
| 4 | `log('4')` | [1, 2, 3] | 4 |
| 5 | Drain in FIFO order | – | 1, 2, 3 |

**Order:** `4 1 2 3`

**Takeaway:** `queueMicrotask` has no priority over promise reactions; both append to the same queue and run in insertion order.

</details>

## M7. An async function body runs sync until the first `await` · `easy` · 🖨️ Output

```js
async function placeOrder() {
  console.log('2');
  return 'ok';
}
console.log('1');
placeOrder().then((r) => console.log('4 ' + r));
console.log('3');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1
2
3
4 ok
```

**Queues walkthrough**

1. `1` is logged.
2. `placeOrder()` runs its body right away → `2`. It returns `'ok'`, so the returned promise is already fulfilled.
3. `.then` queues its callback → microtasks `[log 4]`.
4. `3` is logged; the script ends.
5. Microtask → `4 ok`.

**Order:** `1 2 3 4 ok`

**Takeaway:** `async` does not make the body asynchronous; it only wraps the result in a promise, so `.then` callbacks still run later.

</details>

```text

```

| Step | Call stack / action | Microtask queue | Output |
|---|---|---|---|
| 1 | `log('A')` | – | A |

## M9. A promise settles only once · `easy` · 🖨️ Output

```js
new Promise((resolve, reject) => {
  resolve('first');
  resolve('second');
  reject(new Error('ignored'));
}).then(
  (v) => console.log(v),
  (e) => console.log('error ' + e.message)
);
console.log('sync');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
sync
first
```

**Queues walkthrough**

1. The executor runs synchronously. The first `resolve('first')` fulfils the promise; later `resolve`/`reject` calls do nothing.
2. `.then` sees a fulfilled promise → microtasks `[onFulfilled('first')]`.
3. `sync` is logged.
4. Microtask → `first`. The rejection handler never runs.

**Order:** `sync first`

**Takeaway:** Once a promise is settled its state is fixed; extra `resolve`/`reject` calls are silently ignored.

</details>

## M10. Values flowing through a `.then` chain · `easy` · 🖨️ Output

```js
Promise.resolve(1)
  .then((x) => {
    console.log(x);
    return x + 1;
  })
  .then((x) => {
    console.log(x);
  })
  .then((x) => console.log(x));
console.log('0');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
0
1
2
undefined
```

**Queues walkthrough**

1. Only the first `.then` is queued now (its promise is fulfilled); the others wait on promises that are still pending.
2. `0` is logged.
3. Microtask 1: logs `1`, returns `2` → next `.then` queued.
4. Microtask 2: logs `2`, returns nothing (`undefined`) → next `.then` queued.
5. Microtask 3: logs `undefined`.

**Order:** `0 1 2 undefined`

**Takeaway:** Each `.then` passes on its return value; if you forget to `return`, the next step gets `undefined`.

</details>

## M13. A rejection skips `.then` until a `.catch` · `easy` · 🖨️ Output

```js
Promise.reject(new Error('rejected'))
  .then(() => console.log('skipped'))
  .catch((e) => console.log('caught: ' + e.message))
  .then(() => console.log('after catch'));
console.log('sync');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
sync
caught: rejected
after catch
```

**Queues walkthrough**

1. `sync` is logged; the first reaction (the `.then` without a rejection handler) is queued.
2. Microtask 1: no `onRejected` → the rejection passes to the next promise.
3. Microtask 2: `.catch` handles it → `caught: rejected`; it returns `undefined`, so its promise is **fulfilled**.
4. Microtask 3: the last `.then` runs → `after catch`.

**Order:** `sync → caught: rejected → after catch`

**Takeaway:** `.catch` recovers the chain; everything after it continues as fulfilled unless the handler throws again.

</details>

## M15. An error thrown in one timer does not stop the others · `easy` · 🖨️ Output

```js
setTimeout(() => console.log('tick 1'), 0);
setTimeout(() => {
  throw new Error('feed down');
}, 0);
setTimeout(() => console.log('tick 3'), 0);
console.log('subscribed');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
subscribed
tick 1
Uncaught Error: feed down
tick 3
```

**Queues walkthrough**

| Step | Macrotask | Output |
|---|---|---|
| 1 | Script: register 3 timers | subscribed |
| 2 | Timer 1 | tick 1 |
| 3 | Timer 2 throws → error reported, task ends | Uncaught Error: feed down |
| 4 | Timer 3 still runs | tick 3 |

</details>

```js
Promise.resolve()

  .then(() => console.log('a3'));
```

## M17. A chain started inside a `.then` · `medium` · 🖨️ Output

```js
Promise.resolve()
  .then(() => {
    console.log('1');
    Promise.resolve()
      .then(() => console.log('2'))
      .then(() => console.log('3'));
  })
  .then(() => console.log('4'))
  .then(() => console.log('5'));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1
2
4
3
5
```

**Queues walkthrough**

| Microtask run | Output | Queue after |
|---|---|---|
| outer step 1 | 1 | [2] then, when the step returns, [2, 4] |
| inner 2 | 2 | [4, 3] |
| outer 4 | 4 | [3, 5] |
| inner 3 | 3 | [5] |
| outer 5 | 5 | – |

The inner chain is started (not returned) inside step 1, so `2` is queued **before** step 1 finishes and queues `4`.

**Order:** `1 2 4 3 5`

**Takeaway:** An inner chain that isn't returned runs alongside the outer chain, taking turns with it; `return` it if the outer chain should wait for it.

</details>

## M18. Microtasks that queue more microtasks · `medium` · 🖨️ Output

```js
setTimeout(() => console.log('timer'), 0);
let n = 0;
function spin() {
  n++;
  console.log('micro ' + n);
  if (n < 4) queueMicrotask(spin);
}
queueMicrotask(spin);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
micro 1
micro 2
micro 3
micro 4
timer
```

**Queues walkthrough**

1. Script: timer registered (macrotask), `spin` queued (microtask).
2. Drain: `spin` logs `micro 1` and queues itself again. The queue is not empty, so draining continues.
3. The same repeats for `micro 2`, `micro 3`, `micro 4`. At `n = 4` nothing new is queued and the queue is empty.
4. Only now does the timer run → `timer`.

**Order:** `micro 1 → micro 2 → micro 3 → micro 4 → timer`

**Takeaway:** Microtasks added while draining run in the same drain; a microtask that keeps re-queuing itself forever would block timers and rendering.

</details>

## M21. Two async functions interleaving · `medium` · 🖨️ Output


## M24. `forEach` with an async callback does not wait · `medium` · 🖨️ Output

```js
const orders = ['INFY', 'TCS'];
orders.forEach(async (sym) => {
  console.log('placing ' + sym);
  await null;
  console.log('placed ' + sym);
});
console.log('all done?');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
placing INFY
placing TCS
all done?
placed INFY
placed TCS
```

**Queues walkthrough**

1. `forEach` calls the async callback for `INFY`: it logs `placing INFY`, hits `await` and returns a promise that `forEach` ignores → `[resume INFY]`.
2. Same for `TCS` → `[resume INFY, resume TCS]`.
3. `forEach` returns right away → `all done?` (too early!).
4. Drain: `placed INFY`, `placed TCS`.

**Order:** `placing INFY → placing TCS → all done? → placed INFY → placed TCS`

**Takeaway:** `forEach` ignores the promises its callback returns; use `for...of` with `await` (one at a time) or `await Promise.all(arr.map(...))` (all together).

</details>

```js
}
run();
console.log('sync end');
```

<summary><b>Output & explanation</b></summary>

**Output**

```text
placing INFY
sync end
placed INFY
placing TCS
placed TCS
all done
```

**Queues walkthrough**

| Time | Action | Output |
|---|---|---|
| 0 | loop step 1 starts, 20 ms timer, pause | placing INFY |
| 0 | caller continues | sync end |
| ~20 | timer resolves → resume, step 2 starts, new 20 ms timer | placed INFY, placing TCS |

</details>

## M26. `Promise.all` keeps input order, not finish order · `medium` · 🖨️ Output


## M49. Polling order status with an async `setInterval` callback · `hard` · 🖨️ Output

```js
let polls = 0;
const statuses = ['open', 'open', 'complete'];
const getStatus = () =>
  new Promise((resolve) => setTimeout(() => resolve(statuses[polls++]), 10));
const id = setInterval(async () => {
  console.log('poll');
  const s = await getStatus();
  console.log('status ' + s);
  if (s === 'complete') {
    clearInterval(id);
    console.log('stopped');
  }
}, 40);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
poll
status open
poll
status open
poll
status complete
stopped
```

**Queues walkthrough**

| Time (ms) | Macrotask | Output |
|---|---|---|
| ~40 | interval #1 → starts 10 ms fetch timer, pauses | poll |
| ~50 | fetch timer resolves → resume (microtask) | status open |
| ~80 | interval #2 | poll |
| ~90 | fetch → resume | status open |
| ~120 | interval #3 | poll |
| ~130 | fetch → resume → `clearInterval` | status complete, stopped |

**Order:** `poll → status open → poll → status open → poll → status complete → stopped`
