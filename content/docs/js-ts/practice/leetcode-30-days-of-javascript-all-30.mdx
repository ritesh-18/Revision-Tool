## L1. Day 1 · #2667. Create Hello World Function · `easy` · 💻 Coding

**Group:** Closures · [LeetCode 2667](https://leetcode.com/problems/create-hello-world-function/)

Write `createHelloWorld`. It returns a new function, and that function always returns the string `"Hello World"`, whatever arguments you pass to it.

**Example (own):** `const f = createHelloWorld(); f(1, {}, null)` returns `"Hello World"`.

```js
/**
 * @return {Function}
 */
var createHelloWorld = function() {
  // return a function
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var createHelloWorld = function() {
  return function(...args) {
    return "Hello World";
  };
};

// Alternative: arrow function (no own "arguments"/"this", which is fine here)
var createHelloWorldArrow = () => () => "Hello World";
```

**Test**

```js
const f = createHelloWorld();
console.log(f());
console.log(f(1, {}, null));
console.log(typeof f);
const g = createHelloWorldArrow();
console.log(g("ignored"));
console.log(createHelloWorld() === createHelloWorld());
```

**Output**

```text
Hello World
Hello World
function
Hello World
false
```

**Approach:** the outer function returns an inner function. The inner function ignores its arguments and returns the constant string.

**Why it works:** in JavaScript, functions are **first-class values**. You can return them, store them and pass them around like any other value. This problem is the warm-up for **higher-order functions**, which every other problem in the plan uses.

**Key concept:** a function that returns a function. Here the inner function does not capture any outer variables yet. Day 2 adds that part (a real closure).

**Edge cases:**
- Any number or type of arguments is ignored.
- Each call to `createHelloWorld()` creates a **new** function object, so two results are never `===`. The test prints `false` for that.

**Complexity:** O(1) time and O(1) space.

**Common mistakes:**
- Returning `"Hello World"` directly instead of a function.
- Returning `console.log("Hello World")`, which gives `undefined`.

**Interview follow-up:** *What's the difference between `function(){}` and `() => {}` here?* In this problem there is none. In general, an arrow function has no own `this`, `arguments`, `prototype` or `new` support. It takes `this` from the surrounding (lexical) scope.

**Takeaway:** functions are values. Returning one from another function is the base of closures, currying and decorators.

</details>

## L2. Day 2 · #2620. Counter · `easy` · 💻 Coding

**Group:** Closures · [LeetCode 2620](https://leetcode.com/problems/counter/)

Given an integer `n`, return a `counter` function. Its first call returns `n`, and each later call returns one more than the call before (`n`, `n + 1`, `n + 2`, ...).

**Example (own):** `const c = createCounter(-2); c(); c(); c();` gives `-2, -1, 0`.

```js
/**
 * @param {number} n
 * @return {Function} counter
 */
var createCounter = function(n) {
  return function() {
    // ...
  };
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var createCounter = function(n) {
  return function() {
    return n++; // return current value, then increment the captured variable
  };
};

// Alternative: explicit private counter variable
var createCounterExplicit = function(n) {
  let count = n - 1;
  return function() {
    count += 1;
    return count;
  };
};
```

**Test**

```js
const c = createCounter(10);
console.log([c(), c(), c()].join(','));

const neg = createCounter(-2);
console.log([neg(), neg(), neg()].join(','));

// Two counters do not share state
const a = createCounter(0);
const b = createCounter(0);
a(); a();
console.log(a() + ' ' + b());

const e = createCounterExplicit(5);
console.log([e(), e()].join(','));
```

**Output**

```text
10,11,12
-2,-1,0
2 0
5,6
```

**Approach:** the inner function **closes over** the parameter `n`. Each call returns `n++`. The post-increment returns the old value and then saves `n + 1` in the captured variable.

**Why it works:** a closure keeps a live reference to the variables of its outer scope, not a copy. So `n` stays alive after `createCounter` has returned, and every call sees the updated value.

**Key concept:** **closures and private state.** Each call to `createCounter` creates a new scope. That's why `a` and `b` in the test count independently (`2 0`).

**Edge cases:** negative starting values work fine. Parameters are ordinary local variables, so changing `n` is allowed.

**Complexity:** O(1) per call and O(1) space per counter.

**Common mistakes:**
- `return ++n`, which skips the first value (it returns `n + 1` first).
- Declaring the counter **outside** `createCounter`, so every counter shares one value.

**Interview follow-up:** *How would you add a `reset`?* Return an object with several methods that share the same captured variable. That's Day 4 (Counter II), and it's the classic **module pattern**.

**Takeaway:** a closure is a function plus the variables it remembers. It's the simplest way to get private, per-instance state in JavaScript.

</details>

## L3. Day 3 · #2704. To Be Or Not To Be · `easy` · 💻 Coding

**Group:** Closures · [LeetCode 2704](https://leetcode.com/problems/to-be-or-not-to-be/)

Build a tiny test helper. `expect(val)` returns an object with two methods:
- `toBe(other)` returns `true` if `val === other`. Otherwise it throws an error with the message `"Not Equal"`.
- `notToBe(other)` returns `true` if `val !== other`. Otherwise it throws an error with the message `"Equal"`.

**Example (own):** `expect(3).toBe(3)` returns `true`. `expect(3).notToBe(3)` throws `"Equal"`.

```js
/**
 * @param {string} val
 * @return {Object}
 */
var expect = function(val) {
  // return { toBe, notToBe }
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var expect = function(val) {
  return {
    toBe(other) {
      if (val !== other) throw new Error("Not Equal");
      return true;
    },
    notToBe(other) {
      if (val === other) throw new Error("Equal");
      return true;
    },
  };
};
```

**Test**

```js
function run(label, fn) {
  try {
    console.log(label + ' -> ' + JSON.stringify({ value: fn() }));
  } catch (err) {
    console.log(label + ' -> ' + JSON.stringify({ error: err.message }));
  }
}

run('expect(5).toBe(5)', () => expect(5).toBe(5));
run('expect(5).toBe(null)', () => expect(5).toBe(null));
run('expect(5).notToBe(null)', () => expect(5).notToBe(null));
run('expect(5).notToBe(5)', () => expect(5).notToBe(5));
run('expect("1").toBe(1)', () => expect("1").toBe(1));
run('expect(NaN).toBe(NaN)', () => expect(NaN).toBe(NaN));
const obj = {};
run('same object ref', () => expect(obj).toBe(obj));
run('equal-looking objects', () => expect({}).toBe({}));
```

**Output**

```text
expect(5).toBe(5) -> {"value":true}
expect(5).toBe(null) -> {"error":"Not Equal"}
expect(5).notToBe(null) -> {"value":true}
expect(5).notToBe(5) -> {"error":"Equal"}
expect("1").toBe(1) -> {"error":"Not Equal"}
expect(NaN).toBe(NaN) -> {"error":"Not Equal"}
same object ref -> {"value":true}
equal-looking objects -> {"error":"Not Equal"}
```

**Approach:** return an object whose methods close over `val`. Each method compares `val` with its argument using strict equality, and either returns `true` or throws an `Error` with the required message.

**Why it works:** both methods share the captured `val`. This is how Jest's `expect(x).toBe(y)` is built.

**Key concepts:** closures that return **an object of methods**, and **throwing errors**. LeetCode reads `err.message`, so use `throw new Error("Not Equal")`. Throwing a plain string would have no `.message`.

**Edge cases shown in the test:**
- `"1" === 1` is `false`, because strict equality does no type conversion.
- `NaN === NaN` is `false`. Jest's real `toBe` uses `Object.is`, which treats `NaN` as equal to itself. The LeetCode version uses `===`.
- Objects are compared **by reference**, so `{}` is not `{}`.

**Complexity:** O(1) time and space.

**Common mistakes:** using `==`, returning `false` instead of throwing, and throwing a string instead of an `Error`.

**Interview follow-up:** *How would you add `toEqual` for deep equality?* Write a recursive comparison: same type, same keys, and recursively equal values. Handle arrays, `null` and cycles. `JSON.stringify` is a weak shortcut, because key order matters and it loses `undefined` and functions.

**Takeaway:** a factory that returns an object of closures is the basis of fluent test APIs. Always throw `Error` objects, not strings.

</details>

## L4. Day 4 · #2665. Counter II · `easy` · 💻 Coding

**Group:** Closures · [LeetCode 2665](https://leetcode.com/problems/counter-ii/)

`createCounter(init)` returns an object with three methods:
- `increment()` adds 1 to the current value and returns it.
- `decrement()` subtracts 1 from the current value and returns it.
- `reset()` sets the value back to `init` and returns it.

**Example (own):** with `init = 3`, the calls `increment, increment, reset, decrement` return `4, 5, 3, 2`.

```js
/**
 * @param {integer} init
 * @return { increment: Function, decrement: Function, reset: Function }
 */
var createCounter = function(init) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var createCounter = function(init) {
  let current = init;
  return {
    increment: () => ++current,
    decrement: () => --current,
    reset: () => (current = init),
  };
};

// Alternative: class with a private field
class Counter {
  #init;
  #current;
  constructor(init) {
    this.#init = init;
    this.#current = init;
  }
  increment() { return ++this.#current; }
  decrement() { return --this.#current; }
  reset() { return (this.#current = this.#init); }
}
var createCounterClass = (init) => new Counter(init);
```

**Test**

```js
const c = createCounter(3);
console.log([c.increment(), c.increment(), c.reset(), c.decrement()].join(','));

const z = createCounter(0);
console.log([z.decrement(), z.decrement(), z.reset(), z.reset()].join(','));

// Methods still work when detached (arrow functions do not depend on "this")
const { increment } = createCounter(10);
console.log(increment());

const k = createCounterClass(5);
console.log([k.increment(), k.decrement(), k.decrement(), k.reset()].join(','));
console.log(JSON.stringify(Object.keys(c)));
```

**Output**

```text
4,5,3,2
-1,-2,0,0
11
6,5,4,5
["increment","decrement","reset"]
```

**Approach:** keep a private variable `current` in the closure and return three arrow functions that change it. `init` is also captured, so `reset` can go back to it.

**Why it works:** all three functions are created in the same call, so they share **the same** lexical environment. They all read and write one `current`.

**Key concepts:**
- **Pre-increment vs post-increment:** `++current` changes the value first and then returns it, which is what this problem needs.
- **The module pattern:** `current` can't be reached from outside. The class version gets the same privacy with `#private` fields.
- Detached methods (`const { increment } = ...`) still work, because the closure version doesn't use `this`. A class method that uses `this` would break if called detached.

**Edge cases:** negative values, and calling `reset` several times in a row.

**Complexity:** O(1) per operation and O(1) space.

**Common mistakes:**
- `current++` returns the old value.
- `reset` writing `init = 0` instead of restoring the original value.
- Changing `init` itself, which makes `reset` useless.

**Interview follow-up:** *Closure vs class: which should you use?* Closures give real privacy and methods that work without `this`, but each instance gets its own copies of the functions. Class methods live on the prototype and are shared, which is cheaper when you create many instances. `#fields` now give classes real privacy too.

**Takeaway:** several closures from one call share state. That is the module pattern, and it predates `#private` fields.

</details>

## L5. Day 5 · #2635. Apply Transform Over Each Element in Array · `easy` · 💻 Coding

**Group:** Basic Array Transformations · [LeetCode 2635](https://leetcode.com/problems/apply-transform-over-each-element-in-array/)

Write your own version of `Array.prototype.map` **without using it**. Return a new array where `result[i] = fn(arr[i], i)`.

**Example (own):** `map([10, 20, 30], (x, i) => x + i)` gives `[10, 21, 32]`.

```js
/**
 * @param {number[]} arr
 * @param {Function} fn
 * @return {number[]}
 */
var map = function(arr, fn) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var map = function(arr, fn) {
  const result = new Array(arr.length); // pre-size: no repeated growth
  for (let i = 0; i < arr.length; i++) {
    result[i] = fn(arr[i], i);
  }
  return result;
};

// Alternative: build with push
var mapPush = function(arr, fn) {
  const out = [];
  for (let i = 0; i < arr.length; i++) out.push(fn(arr[i], i));
  return out;
};
```

**Test**

```js
console.log(map([1, 2, 3], x => x * 2).join(','));
console.log(map([10, 20, 30], (x, i) => x + i).join(','));
console.log(JSON.stringify(map([], x => x + 1)));
console.log(map([5, 6], () => 42).join(','));

const input = [1, 2];
const out = map(input, x => x * 10);
console.log(input.join(',') + ' | ' + out.join(',') + ' | same ref: ' + (input === out));
console.log(mapPush([3, 4], (x, i) => x * i).join(','));
```

**Output**

```text
2,4,6
10,21,32
[]
42,42
1,2 | 10,20 | same ref: false
0,4
```

**Approach:** loop over the indices and save `fn(arr[i], i)` into a new array.

**Why it works:** `map` is a **pure** transformation. It builds a new array of the same length and doesn't change the input. The test shows the input is still `1,2` and the output is a different reference.

**Key concepts:** **higher-order functions** (the callback receives both the value *and the index*) and **immutability**.

**Edge cases:**
- An empty array gives `[]`.
- The callback can ignore its arguments (`() => 42`).
- The real `Array.prototype.map` skips holes in sparse arrays. A plain `for` loop visits them as `undefined`. That doesn't matter for LeetCode's dense inputs.

**Complexity:** O(n) time and O(n) space.

**Performance note:** pre-sizing with `new Array(n)` avoids repeated resizing. In V8, `push` onto a fresh `[]` is also well optimized, so both versions are fine.

**Common mistakes:**
- Forgetting to pass `i` to the callback.
- Writing into `arr` directly (changing the input).
- Using `for...in`, which gives string keys and also walks inherited enumerable properties.

**Interview follow-up:** *Implement `Array.prototype.myMap` as a polyfill.* Use `this` as the array, check that `fn` is a function, and call `fn.call(thisArg, this[i], i, this)` only when `i in this`, so holes are kept.

**Takeaway:** `map` is just a loop that builds a new array. Know the callback's arguments `(value, index, array)`.

</details>

## L6. Day 6 · #2634. Filter Elements from Array · `easy` · 💻 Coding

**Group:** Basic Array Transformations · [LeetCode 2634](https://leetcode.com/problems/filter-elements-from-array/)

Write your own version of `Array.prototype.filter` **without using it**. Keep `arr[i]` when `fn(arr[i], i)` returns a **truthy** value.

**Example (own):** `filter([4, 0, 7, 2], (x, i) => i % 2 === 0)` gives `[4, 7]`.

```js
/**
 * @param {number[]} arr
 * @param {Function} fn
 * @return {number[]}
 */
var filter = function(arr, fn) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var filter = function(arr, fn) {
  const result = [];
  for (let i = 0; i < arr.length; i++) {
    if (fn(arr[i], i)) result.push(arr[i]);
  }
  return result;
};

// Alternative: built on reduce
var filterReduce = function(arr, fn) {
  return arr.reduce((acc, x, i) => {
    if (fn(x, i)) acc.push(x);
    return acc;
  }, []);
};
```

**Test**

```js
console.log(filter([4, 0, 7, 2], (x, i) => i % 2 === 0).join(','));
console.log(filter([1, 2, 3, 4, 5], x => x > 2).join(','));
// Truthy, not strictly true: 0 is falsy, other numbers are truthy
console.log(filter([-1, 0, 1, 2], x => x + 1).join(','));
console.log(JSON.stringify(filter([], () => true)));
console.log(JSON.stringify(filter([1, 2], () => false)));
console.log(filterReduce([10, 15, 20], x => x % 10 === 0).join(','));
```

**Output**

```text
4,7
3,4,5
0,1,2
[]
[]
10,20
```

**Approach:** go through the array and `push` each element for which the callback returns a truthy value.

**Why it works:** filter keeps the order and only drops elements, so the output length is anything from 0 to n.

**Key concept:** **truthiness.** The callback doesn't have to return a boolean. In the third test, `x + 1` is `0` (falsy) only for `-1`, so that element is dropped and `0,1,2` stay. Falsy values are `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` and `NaN`.

**Edge cases:** an empty input, a callback that removes everything, and callbacks that use the index.

**Complexity:** O(n) time and O(k) extra space for the k kept elements.

**Common mistakes:**
- Checking `fn(...) === true`, which breaks for truthy non-boolean returns.
- Splicing the input array while looping over it. Indices shift, so elements get skipped.
- Forgetting the index argument.

**Interview follow-up:** *Remove items from an array **in place**.* Use two pointers. A write index `k` copies each kept element to `arr[k++]`, then set `arr.length = k`. That's O(n) time with O(1) extra space and no costly `splice` calls.

**Takeaway:** filter keeps elements whose callback result is **truthy**. Build a new array and never splice while you iterate.

</details>

## L7. Day 7 · #2626. Array Reduce Transformation · `easy` · 💻 Coding

**Group:** Basic Array Transformations · [LeetCode 2626](https://leetcode.com/problems/array-reduce-transformation/)

Write a reducer **without `Array.prototype.reduce`**. Start with `acc = init`. For each element, set `acc = fn(acc, nums[i])`, then return `acc`. For an empty array, return `init`.

**Example (own):** `reduce([2, 3, 4], (a, x) => a * x, 1)` gives `24`.

```js
/**
 * @param {number[]} nums
 * @param {Function} fn
 * @param {number} init
 * @return {number}
 */
var reduce = function(nums, fn, init) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var reduce = function(nums, fn, init) {
  let acc = init;
  for (const x of nums) {
    acc = fn(acc, x);
  }
  return acc;
};

// Alternative: recursive (fine for small arrays; deep recursion can overflow the stack)
var reduceRecursive = function(nums, fn, init, i = 0) {
  return i === nums.length ? init : reduceRecursive(nums, fn, fn(init, nums[i]), i + 1);
};
```

**Test**

```js
console.log(reduce([1, 2, 3, 4], (acc, x) => acc + x, 0));
console.log(reduce([2, 3, 4], (a, x) => a * x, 1));
console.log(reduce([1, 2, 3], (acc, x) => acc + x * x, 100));
console.log(reduce([], (acc, x) => acc + x, 25));
// Order matters: this reducer is not commutative
console.log(reduce([1, 2, 3], (acc, x) => acc * 10 + x, 0));
console.log(reduceRecursive([5, 5, 5], (a, x) => a - x, 20));
```

**Output**

```text
10
24
114
25
123
5
```

**Approach:** keep an accumulator that starts at `init`, and replace it with `fn(acc, x)` for each element from left to right.

**Why it works:** reduce folds a list into one value. Sum, product, max, grouping and `compose` (Day 8) are all folds.

**Key concepts:**
- **The accumulator pattern.** The callback returns the **next** accumulator, so you must `return` it.
- **Order.** Elements are processed left to right. `acc * 10 + x` builds `123`, which shows the order.

**Edge cases:**
- An empty array returns `init` (`25`).
- The real `Array.prototype.reduce` **throws a TypeError** for an empty array with no initial value. Here `init` is always given.

**Complexity:** O(n) time, O(1) extra space for the loop, O(n) stack for the recursive version.

**Common mistakes:**
- Starting from `nums[0]` and ignoring `init`.
- Forgetting `return` in a block-bodied callback, which gives `undefined`.
- Changing `acc` in place when it's shared state you meant to copy.

**Interview follow-up:** *What does `[].reduce((a, b) => a + b)` do?* It throws `TypeError: Reduce of empty array with no initial value`. Always pass an initial value in production code.

**Takeaway:** reduce = accumulator + left-to-right loop. Always return the new accumulator and always pass an initial value.

</details>

## L8. Day 8 · #2629. Function Composition · `easy` · 💻 Coding

**Group:** Function Transformations · [LeetCode 2629](https://leetcode.com/problems/function-composition/)

Given an array of one-argument functions `[f1, f2, ..., fk]`, return a function that computes `f1(f2(...fk(x)))`. The **rightmost function runs first**. If the array is empty, return the identity function (`x => x`).

**Example (own):** `compose([x => x * 2, x => x + 3])(4)` gives `(4 + 3) * 2 = 14`.

```js
/**
 * @param {Function[]} functions
 * @return {Function}
 */
var compose = function(functions) {
  return function(x) {
    // ...
  };
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var compose = function(functions) {
  return function(x) {
    let value = x;
    for (let i = functions.length - 1; i >= 0; i--) {
      value = functions[i](value);
    }
    return value;
  };
};

// Alternative: reduceRight
var composeReduce = function(functions) {
  return x => functions.reduceRight((acc, fn) => fn(acc), x);
};
```

**Test**

```js
const double = x => x * 2;
const add3 = x => x + 3;
const square = x => x * x;

console.log(compose([double, add3])(4));
console.log(compose([add3, double])(4));
console.log(compose([square, add3, double])(1));
console.log(compose([])(42));
console.log(composeReduce([double, add3])(4));
console.log(composeReduce([])(7));

// Call order is right to left
const order = [];
const tag = name => x => { order.push(name); return x; };
compose([tag('f1'), tag('f2'), tag('f3')])(0);
console.log(order.join('>'));
```

**Output**

```text
14
11
25
42
14
7
f3>f2>f1
```

**Approach:** loop over the functions **from right to left**, passing each result into the next function. With no functions, the loop never runs and `x` comes back unchanged, which is the identity.

**Why it works:** composition in maths, `(f ∘ g)(x) = f(g(x))`, applies the inner (rightmost) function first. `reduceRight` expresses this directly.

**Key concepts:** **higher-order functions** and **closures** (the returned function remembers `functions`). Also know `pipe`, which is the same idea but runs left to right.

**Walk-through:** `compose([square, add3, double])(1)` → `double(1) = 2` → `add3(2) = 5` → `square(5) = 25`.

**Edge cases:** an empty list returns the identity. A single function is just that function.

**Complexity:** O(k) per call for k functions, O(1) extra space.

**Common mistakes:**
- Looping left to right, which gives `pipe` instead of `compose`. In the test, `[double, add3]` gives `14` and `[add3, double]` gives `11`.
- Using `reduce` without a starting value, which breaks on an empty array.

**Interview follow-up:** *Write `pipe` for async functions.* `const pipeAsync = (...fns) => x => fns.reduce((p, f) => p.then(f), Promise.resolve(x));`. Each step waits for the previous one to finish.

**Takeaway:** compose runs right to left, pipe runs left to right. `reduceRight` with the input as the start value is a one-line compose.

</details>

## L9. Day 9 · #2703. Return Length of Arguments Passed · `easy` · 💻 Coding

**Group:** Function Transformations · [LeetCode 2703](https://leetcode.com/problems/return-length-of-arguments-passed/)

Write `argumentsLength`. It returns how many arguments it was called with.

**Example (own):** `argumentsLength("a", null, undefined)` gives `3`.

```js
/**
 * @param {...(null|boolean|number|string|Array|Object)} args
 * @return {number}
 */
var argumentsLength = function(...args) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var argumentsLength = function(...args) {
  return args.length;
};

// Alternative: the legacy "arguments" object (not available in arrow functions)
var argumentsLengthLegacy = function() {
  return arguments.length;
};
```

**Test**


## L11. Day 11 · #2623. Memoize · `medium` · 💻 Coding

**Group:** Function Transformations · [LeetCode 2623](https://leetcode.com/problems/memoize/)

Return a memoized version of `fn`. It must never call `fn` twice with the same inputs. Instead, it returns the cached result. LeetCode tests it with `sum(a, b)`, `fib(n)` and `factorial(n)` (integer arguments), and also checks how many times the real function was called. Note that `sum(2, 3)` and `sum(3, 2)` are **different** inputs.

**Example (own):** `const m = memoize((a, b) => a + b); m(2, 3); m(2, 3); m(3, 2);` calls the real function **twice**.

```js
/**
 * @param {Function} fn
 * @return {Function}
 */
function memoize(fn) {
  return function(...args) {
    // ...
  }
}
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
function memoize(fn) {
  const cache = new Map();
  return function(...args) {
    const key = args.join(','); // args are integers per constraints
    if (cache.has(key)) return cache.get(key);
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

// Alternative: nested Maps keyed by each argument (works for any value, compares by identity)
function memoizeTrie(fn) {
  const root = new Map();
  const RESULT = Symbol('result');
  return function(...args) {
    let node = root;
    for (const arg of args) {
      if (!node.has(arg)) node.set(arg, new Map());
      node = node.get(arg);
    }
    if (!node.has(RESULT)) node.set(RESULT, fn.apply(this, args));
    return node.get(RESULT);
  };
}
```

**Test**

```js

console.log([sum(2, 3), sum(2, 3), sum(3, 2), sum(0, 0)].join(','));
console.log('sum calls: ' + callCount);

// Cached result of 0 (falsy) must still be served from cache
let zeroCalls = 0;
const zero = memoize(() => { zeroCalls++; return 0; });
zero(); zero();
console.log('zero calls: ' + zeroCalls);

// Memoized recursive fib: recursion goes through the memoized wrapper
let fibCalls = 0;
const fib = memoize(n => { fibCalls++; return n <= 1 ? 1 : fib(n - 1) + fib(n - 2); });
console.log('fib(30) = ' + fib(30) + ', inner calls: ' + fibCalls);
fib(30);
console.log('after repeat: ' + fibCalls);

// Trie version distinguishes objects by reference and handles strings with commas
let trieCalls = 0;
const id = memoizeTrie((a, b) => { trieCalls++; return String(a) + '|' + String(b); });
const o = {};
id('1,2', 3); id('1', '2,3'); id(o, 1); id(o, 1); id({}, 1);
console.log('trie calls: ' + trieCalls);
```

**Output**

```text
5,5,5,0
sum calls: 3
zero calls: 1
fib(30) = 1346269, inner calls: 31
after repeat: 31
trie calls: 4
```

**Approach:** turn the arguments into a cache key and store results in a `Map`. On a cache hit, return the stored value **without** calling `fn`.

**Why it works:** LeetCode's functions are **pure** (the same inputs always give the same output), so a cached result can be reused. The key `args.join(',')` keeps the order, so `(2,3)` and `(3,2)` are separate entries (3 real calls in the test).

**Key concepts:** closures, the `Map` API, and **why you check `has` instead of the value**. A cached `0` is falsy, so `if (cache.get(key))` would call `fn` again. The `zero` test guards against this.

**Recursive memoization:** `fib` calls the *memoized* `fib`, so each `n` is computed once. `fib(30)` makes 31 inner calls (n = 0..30) instead of about 2.7 million.

**Key design choices:**
- `join(',')` is fine for integers, but it clashes for strings with commas (`'1,2',3` vs `'1','2,3'`) and turns every object into `[object Object]`. `JSON.stringify(args)` fixes the strings but still can't tell two objects with the same content apart. The **Map-trie** version compares each argument by identity and has no key clashes.
- The cache grows without limit. In production, use an **LRU** or a `WeakMap` for object keys.

**Complexity:** O(k) per call to build a key for k arguments. Space is O(number of distinct inputs).

**Common mistakes:** using a truthiness check, and a key that ignores argument order.

**Interview follow-up:** *How do you stop the cache from growing forever?* Use an LRU cache. A `Map` keeps insertion order, so on a hit, delete the key and set it again. When the size is over the limit, delete `map.keys().next().value`.

**Takeaway:** memoize = closure + Map + a good key. Check `has()`, not truthiness, and only memoize pure functions.

**Solution**

**Why it works:** `setInterval` doesn't fire at time 0, so the immediate call has to be made by hand. After that, the interval runs at t, 2t, 3t and so on, until it is cleared.

**Trace:** calls at 0, 60 and 120 ms, then the cancel at 150 ms. That's 3 calls, each pushing `2 * 5 = 10`. The cancel is placed halfway between ticks, so the count stays stable despite small timer delays.

**Key concept: `setInterval` vs recursive `setTimeout`.**

**Common mistakes:**
- Forgetting the immediate call.
- Clearing an interval id with `clearTimeout`. This happens to work in browsers and Node, but it's unclear, so match the pair.
- In the recursive version, saving only the first timer id. You must update `timerId` on every tick.

**Takeaway:** make the first call yourself, then `setInterval`. Prefer recursive `setTimeout` when each run is async or slow.

```js
    e => console.log(label + ' rejected: ' + (e instanceof Error ? e.message : e))
  );
}

(async () => {
  await report('fast', timeLimit(async (a, b) => { await slow(50); return a + b; }, 150)(2, 3));
  await report('slow', timeLimit(async () => slow(200, 'late'), 100)());
  await report('throws', timeLimit(async () => { throw new Error('boom'); }, 100)());
  await report('race fast', timeLimitRace(async x => x * 2, 50)(21));
  await report('race slow', timeLimitRace(() => slow(120, 'x'), 40)());
})();
```

**Output**

```text
fast resolved: 5
slow rejected: Time Limit Exceeded
throws rejected: boom
race fast resolved: 42
race slow rejected: Time Limit Exceeded
```

**Approach:** start a timer that rejects after `t` ms, and at the same time call `fn`. Whichever finishes first **settles** the outer promise. A promise can only settle once, so the later result is ignored. When `fn` settles, clear the timer.

**Why it works:** `resolve` and `reject` do nothing after the first settle. That makes a hand-written race safe. `Promise.race` does the same thing in one line.

**Key concepts:**
- Promise settling rules, `Promise.race`, and `finally` for cleanup.
- **Clear the timer.** Without `clearTimeout`, every fast call leaves a pending timer. In Node that keeps the process alive, and on a busy server it wastes memory.
- The **timeout does not cancel `fn`**. The slow work keeps running in the background. Real cancellation needs an `AbortController` passed into `fn`.

**Edge cases:**
- `fn` rejects before the limit: pass the original reason through (`boom`).
- `fn` resolves exactly at the limit: whichever timer callback runs first wins.
- LeetCode expects the rejection to be the **string** `"Time Limit Exceeded"`, not an `Error`.

**Complexity:** O(1) overhead.

**Common mistakes:**
- Wrapping `fn` in `try/catch` without `await`.
- Not clearing the timer.
- Using an `async` executor function inside `new Promise`.

**Interview follow-up:** *Build `fetchWithTimeout(url, ms)`.* Use `const ctrl = new AbortController(); const id = setTimeout(() => ctrl.abort(), ms); try { return await fetch(url, { signal: ctrl.signal }); } finally { clearTimeout(id); }`. Modern runtimes also have `AbortSignal.timeout(ms)`.

**Takeaway:** a timeout is a race between the work and a rejecting timer. Always clear the timer, and remember that a timeout doesn't stop the underlying work.

## L17. Day 17 · #2622. Cache With Time Limit · `medium` · 💻 Coding

**Group:** Promises and Time · [LeetCode 2622](https://leetcode.com/problems/cache-with-time-limit/)

Build a `TimeLimitedCache` class with integer keys and values, where every entry expires after its own duration:
- `set(key, value, duration)` stores the value for `duration` ms. It returns `true` if an **unexpired** entry with that key already existed (the value and duration are then overwritten), otherwise `false`.
- `get(key)` returns the value if the key exists and hasn't expired, otherwise `-1`.
- `count()` returns how many unexpired keys there are.

**Example (own):** `set(1, 42, 100)` returns `false`. `get(1)` gives `42` right away and `-1` at 150 ms.

```js
var TimeLimitedCache = function() {};
TimeLimitedCache.prototype.set = function(key, value, duration) {};
TimeLimitedCache.prototype.get = function(key) {};
TimeLimitedCache.prototype.count = function() {};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
// Approach 1: one timer per key; expired keys are deleted eagerly
var TimeLimitedCache = function() {
  this.cache = new Map(); // key -> { value, timerId }
};

TimeLimitedCache.prototype.set = function(key, value, duration) {
  const existing = this.cache.get(key);
  if (existing) clearTimeout(existing.timerId);
  const timerId = setTimeout(() => this.cache.delete(key), duration);
  this.cache.set(key, { value, timerId });
  return Boolean(existing);
};

TimeLimitedCache.prototype.get = function(key) {
  return this.cache.has(key) ? this.cache.get(key).value : -1;
};

TimeLimitedCache.prototype.count = function() {
  return this.cache.size;
};

// Approach 2: store expiry timestamps; expire lazily (no timers)
class LazyTTLCache {
  constructor() { this.store = new Map(); } // key -> { value, expiresAt }
  #alive(key) {
    const e = this.store.get(key);
    if (!e) return false;
    if (Date.now() >= e.expiresAt) { this.store.delete(key); return false; }
    return true;
  }
  set(key, value, duration) {
    const had = this.#alive(key);
    this.store.set(key, { value, expiresAt: Date.now() + duration });
    return had;
  }
  get(key) { return this.#alive(key) ? this.store.get(key).value : -1; }
  count() {
    let n = 0;
    for (const key of [...this.store.keys()]) if (this.#alive(key)) n++;
    return n;
  }
}
```

**Test**

```js
function scenario(label, cache, done) {
  const out = [];
  out.push(cache.set(1, 42, 100));     // false: new key
  out.push(cache.get(1));              // 42
  out.push(cache.count());             // 1
  setTimeout(() => {
    out.push(cache.set(1, 50, 100));   // true: still alive at ~50ms, duration resets
  }, 50);
  setTimeout(() => {
    out.push(cache.get(1));            // 50: alive until ~150ms
  }, 120);
  setTimeout(() => {
    out.push(cache.get(1));            // -1: expired
    out.push(cache.count());           // 0
    out.push(cache.set(1, 7, 50));     // false: old entry had expired
    console.log(label + ': ' + out.join(','));
    done();
  }, 220);
}

scenario('timers', new TimeLimitedCache(), () => {
  scenario('lazy', new LazyTTLCache(), () => {
    const c = new TimeLimitedCache();
    console.log('missing key: ' + c.get(99));
  });
});
```

**Output**

```text
timers: false,42,1,true,50,-1,0,false
lazy: false,42,1,true,50,-1,0,false
missing key: -1
```

**Approach 1 (timers):** store `{ value, timerId }` in a `Map`. Every `set` clears the old timer, if there is one, and starts a new timer that deletes the key. Then `get` is a plain lookup, and `count` is `map.size`, which is O(1).

**Approach 2 (lazy expiry):** store an `expiresAt` timestamp and treat an entry as dead when `Date.now() >= expiresAt`, removing it the next time it's read. There are no timers, which scales better for many keys. But `count` becomes O(n), and dead entries stay in memory until someone touches them. Redis uses a mix of both: lazy deletes plus a periodic sampling sweep.

**Trace:**
1. `set` at 0 ms returns `false`.
2. At 50 ms the key is still alive, so `set` returns `true` and the TTL restarts, now ending at about 150 ms.
3. At 120 ms, `get` returns `50`.
4. At 220 ms the key has expired: `get` returns `-1`, `count` returns `0`, and a new `set` returns `false`.

**Key concepts:** `Map`, `this` inside arrow callbacks (the `setTimeout` arrow function keeps the instance's `this`), and the prototype-method style used in LeetCode's template.

**Edge cases:**
- Overwriting must **clear the old timer**. Otherwise the old timer deletes the new value too early.
- Reading a missing key returns `-1`.

**Complexity:** approach 1 is O(1) for every operation. Approach 2 has O(1) `get`/`set` and O(n) `count`.

**Common mistakes:**
- Forgetting `clearTimeout` on overwrite.
- Using `function(){ this.cache.delete(key) }` inside `setTimeout`, where `this` is wrong.
- Returning `true` for an entry that has expired but hasn't been removed yet (in the lazy version).

**Interview follow-up:** *How would you cache API responses on the frontend?* Use a TTL cache keyed by the URL plus its parameters. Add stale-while-revalidate: serve the stale value and refresh it in the background. Libraries like React Query / SWR do exactly this.

**Takeaway:** TTL caches expire either eagerly (timers) or lazily (timestamps). Always cancel the old timer when you overwrite a key.

## L18. Day 18 · #2627. Debounce · `medium` · 💻 Coding

**Group:** Promises and Time · [LeetCode 2627](https://leetcode.com/problems/debounce/)

Return a debounced version of `fn` with delay `t` ms. Each call schedules `fn` to run `t` ms later with **that call's** arguments, and cancels any run that is still pending. So after a burst of calls, only the last one runs, `t` ms after it was made.

**Example (own):** with `t = 100`, calls at 0 ms (`"a"`) and 50 ms (`"b"`) give a single run at 150 ms with `"b"`.

```js
/**
 * @param {Function} fn
 * @param {number} t milliseconds
 * @return {Function}
 */
var debounce = function(fn, t) {
  return function(...args) {
    // ...
  }
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var debounce = function(fn, t) {
  let timerId;
  return function(...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn.apply(this, args), t);
  };
};

// Extended version: leading-edge option + cancel()
function debounceAdvanced(fn, t, { leading = false } = {}) {
  let timerId = null;
  function debounced(...args) {
    const callNow = leading && timerId === null;
    clearTimeout(timerId);
    timerId = setTimeout(() => {
      timerId = null;
      if (!leading) fn.apply(this, args);
    }, t);
    if (callNow) fn.apply(this, args);
  }
  debounced.cancel = () => { clearTimeout(timerId); timerId = null; };
  return debounced;
}
```

**Test**

```js
const fired = [];
const search = debounce(q => fired.push(q), 100);

setTimeout(() => search('a'), 0);    // cancelled by 'ab'
setTimeout(() => search('ab'), 50);  // fires at ~150
setTimeout(() => search('abc'), 220); // fires at ~320

// "this" is preserved
const box = { name: 'box', log: debounce(function () { fired.push('this=' + this.name); }, 30) };
box.log();

// Leading edge: first call fires immediately, burst is ignored
const lead = [];
const leadFn = debounceAdvanced(x => lead.push(x), 60, { leading: true });
leadFn(1); leadFn(2); leadFn(3);
setTimeout(() => leadFn(4), 150); // new burst after quiet period -> fires

// cancel()
const cancelled = [];
const c = debounceAdvanced(x => cancelled.push(x), 40);
c('x');
c.cancel();

setTimeout(() => {
  console.log('trailing: ' + fired.join(','));
  console.log('leading: ' + lead.join(','));
  console.log('after cancel: ' + cancelled.length);
}, 450);
```

**Output**

```text
trailing: this=box,ab,abc
leading: 1,4
after cancel: 0
```

**Approach:** keep one `timerId` in the closure. Every call clears the pending timer and starts a new one that runs `fn` with the latest arguments.

**Why it works:** a timer survives only if no other call comes in within `t` ms. So `fn` runs once per "quiet period", with the arguments of the **last** call.

**Trace:**
- `'a'` at 0 ms is replaced by `'ab'` at 50 ms, which fires at about 150 ms.
- `'abc'` at 220 ms comes after the first run, so it fires separately at about 320 ms.
- The `box` call fires first, at 30 ms. So the output is `this=box,ab,abc`.

**Key concepts:**
- Closures, timers, and **preserving `this`**. The wrapper is a normal `function`, and the arrow function inside `setTimeout` takes its `this`.
- **Debounce vs throttle.** Debounce waits for the calls to stop, which suits search-as-you-type (for example a stock search box) and resize handling. **Throttle** runs at most once every `t` ms, which suits scroll handlers and price-tick rendering.
- **Leading edge.** Run on the first call of a burst and ignore the rest until things have been quiet for `t` ms (`1`, then `4` after the pause).

**Edge cases:** `clearTimeout(undefined)` is safe. Calling `cancel()` drops the pending call.

**Complexity:** O(1) per call.

**Common mistakes:**
- Creating `timerId` **inside** the wrapper, which gives a new variable per call, so nothing is ever cancelled.
- Using the *first* call's arguments.
- Losing `this`.
- Creating a new debounced function on every React render (use `useMemo`/`useRef` to keep one).

**Interview follow-up:** *Write throttle.* `let last = 0; return (...a) => { const now = Date.now(); if (now - last >= t) { last = now; fn(...a); } };`. Add a trailing timer if the last call must not be lost.

**Takeaway:** debounce = one shared timer that every call resets. It runs after the calls stop, with the latest arguments.

## L19. Day 19 · #2721. Execute Asynchronous Functions in Parallel · `medium` · 💻 Coding

**Group:** Promises and Time · [LeetCode 2721](https://leetcode.com/problems/execute-asynchronous-functions-in-parallel/)

Write your own `Promise.all` **without using it**. You get an array of functions that take no arguments and each return a promise. Start them all at once and return a promise that:
- resolves with all the values **in input order**, once every promise has resolved, or
- rejects with the reason of the **first** promise to reject.

**Example (own):** functions that resolve to `'x'` after 60 ms and `'y'` after 10 ms give `['x', 'y']`, even though `'y'` finishes first.

```js
/**
 * @param {Array<Function>} functions
 * @return {Promise<any>}
 */
var promiseAll = function(functions) {
  // ...
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var promiseAll = function(functions) {
  return new Promise((resolve, reject) => {
    const results = new Array(functions.length);
    let remaining = functions.length;
    if (remaining === 0) return resolve(results);

    functions.forEach((fn, i) => {
      // Wrap in Promise.resolve().then so a synchronous throw becomes a rejection
      Promise.resolve()
        .then(fn)
        .then(value => {
          results[i] = value;          // store by index, not push
          remaining -= 1;
          if (remaining === 0) resolve(results);
        }, reject);                    // first rejection wins; later calls are ignored
    });
  });
};

// Alternative: async/await with a concurrency limit (a common follow-up)
var promisePool = async function(functions, limit) {
  const results = new Array(functions.length);
  let next = 0;
  async function worker() {
    while (next < functions.length) {
      const i = next++;
      results[i] = await functions[i]();
    }
  }
  const workers = [];
  for (let w = 0; w < Math.min(limit, functions.length); w++) workers.push(worker());
  for (const wk of workers) await wk;
  return results;
};
```

**Test**

```js
const after = (ms, value, fail) => () =>
  new Promise((res, rej) => setTimeout(() => (fail ? rej(value) : res(value)), ms));

(async () => {
  console.log(JSON.stringify(await promiseAll([after(60, 'x'), after(10, 'y'), after(30, 'z')])));
  console.log(JSON.stringify(await promiseAll([])));

  try {
    await promiseAll([after(80, 1), after(20, 'first error', true), after(40, 'second error', true)]);
  } catch (e) {
    console.log('rejected with: ' + e);
  }

  try {
    await promiseAll([() => { throw new Error('sync throw'); }]);
  } catch (e) {
    console.log('caught: ' + e.message);
  }

  // Parallel: 3 x 60ms tasks finish in well under 180ms
  const t0 = Date.now();
  await promiseAll([after(60, 1), after(60, 2), after(60, 3)]);
  console.log('ran in parallel: ' + (Date.now() - t0 < 150));

  // Pool with limit 2: order preserved, max 2 running at once
  let running = 0, peak = 0;
  const task = (ms, v) => async () => {
    running++; peak = Math.max(peak, running);
    await new Promise(r => setTimeout(r, ms));
    running--;
    return v;
  };
  const pooled = await promisePool([task(30, 'a'), task(10, 'b'), task(20, 'c'), task(5, 'd')], 2);
  console.log(pooled.join(',') + ' peak=' + peak);
})();
```

**Output**

```text
["x","y","z"]
[]
rejected with: first error
caught: sync throw
ran in parallel: true
a,b,c,d peak=2
```

**Approach:** start every function right away. Save each result **at its own index**, and count how many are still pending. Resolve when the count reaches 0. Pass `reject` straight through, so the first failure settles the outer promise and later ones are ignored, because a promise settles only once.

**Why it works:**
- Writing `results[i]` keeps the input order, whatever the finish order is (`x,y,z`).
- Counting with `remaining` is correct even when a result is `undefined`. Checking `results.length` would be wrong, because `new Array(n)` already has length n.

**Key concepts:** promise combinators, settle-once rules, and closures over `i` (`forEach`, or `let` in a loop, gives each callback its own index).

**Edge cases:**
- An empty input must resolve immediately with `[]`, or the promise would never settle.
- A function that **throws synchronously** has to become a rejection. `Promise.resolve().then(fn)` handles that.
- A task that fails early doesn't stop the others. They keep running.

**Complexity:** O(n) bookkeeping. Total time is roughly the slowest task, not the sum (checked by the parallel test).

**Common mistakes:**
- `results.push(value)`, which records finish order.
- Resolving when `i === n - 1`.
- Using `await` in a `for` loop, which runs the tasks one after another.
- Forgetting the empty case.

**Follow-up shown (promise pool):** run at most `limit` tasks at once. `limit` workers pull the next index from a shared counter. JS is single-threaded, so `next++` can't race. The test confirms `peak=2`. This is how you'd throttle, for example, 100 order-status requests to 5 at a time.

**Interview follow-up:** *`all` vs `allSettled` vs `race` vs `any`?* `all` fails fast. `allSettled` never rejects and reports every result. `race` settles with the first to settle. `any` resolves with the first success, or rejects with `AggregateError` if all fail.

**Takeaway:** a hand-written `Promise.all` = start everything, store by index, count what's done, and let the first `reject` win. Remember the empty case.

```js
  const groups = {};
  for (const item of this) {

    if (!Object.prototype.hasOwnProperty.call(groups, key)) groups[key] = [];

  }
  return groups;
```

Two arrays hold objects that each have an integer `id`. Within one array, ids are unique. Merge them into one array **sorted by `id` ascending**:

```js
 * @param {Array} arr1
 * @param {Array} arr2
 * @return {Array}

};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var join = function(arr1, arr2) {
  const byId = new Map();
  for (const obj of arr1) byId.set(obj.id, { ...obj });
  for (const obj of arr2) {
    byId.set(obj.id, byId.has(obj.id) ? { ...byId.get(obj.id), ...obj } : { ...obj });
  }
  return [...byId.values()].sort((a, b) => a.id - b.id);
};

// Alternative: sort both, then two-pointer merge (like merge sort's merge step)
var joinTwoPointer = function(arr1, arr2) {
  const a = [...arr1].sort((x, y) => x.id - y.id);
  const b = [...arr2].sort((x, y) => x.id - y.id);
  const out = [];
  let i = 0, j = 0;
  while (i < a.length || j < b.length) {
    if (j === b.length || (i < a.length && a[i].id < b[j].id)) out.push({ ...a[i++] });
    else if (i === a.length || b[j].id < a[i].id) out.push({ ...b[j++] });
    else out.push({ ...a[i++], ...b[j++] }); // same id
  }
  return out;
};
```

**Common mistakes:**

- Spreading in the wrong order, so `arr1` wins.
- Nested loops (O(n·m)).

**Interview follow-up:** *How would you deep-merge instead?* Recurse when both values are plain objects, and otherwise let the right-hand value win. Decide how to handle arrays (replace or concatenate). `structuredClone` can be used for copies.

**Group:** JSON · [LeetCode 2625](https://leetcode.com/problems/flatten-deeply-nested-array/)

Given a nested array `arr` and a depth `n`, return a flattened copy. A sub-array is spread into its parent only when its current nesting depth is **less than `n`**. The elements of the top-level array are at depth 0. Don't use `Array.prototype.flat`.

```js
/**
 * @param {Array} arr
 * @param {number} depth
 * @return {Array}
 */

};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var flat = function (arr, n) {
  const result = [];
  const walk = (items, depth) => {
    for (const item of items) {
      if (Array.isArray(item) && depth < n) walk(item, depth + 1);
      else result.push(item);
    }
  };
  walk(arr, 0);
  return result;
};

// Alternative: iterative with an explicit stack (no recursion depth limit)
var flatIterative = function (arr, n) {
  const stack = arr.map(item => [item, 0]);
  const result = [];
  while (stack.length) {
    const [item, depth] = stack.pop();
    if (Array.isArray(item) && depth < n) {
      for (const child of item) stack.push([child, depth + 1]);
    } else {
      result.push(item);
    }
  }
  return result.reverse(); // stack pops from the end, so reverse at the end
};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var compactObject = function(obj) {
  if (obj === null || typeof obj !== 'object') return obj;

  if (Array.isArray(obj)) {
    const out = [];
    for (const v of obj) {
      if (v) out.push(compactObject(v));
    }
    return out;
  }

  const out = {};
  for (const key of Object.keys(obj)) {
    const v = obj[key];
    if (v) out[key] = compactObject(v);
  }
  return out;

  const make = v => (Array.isArray(v) ? [] : {});
  const result = make(root);
  const queue = [[root, result]];
  while (queue.length) {
    const [src, dst] = queue.shift();
    for (const key of Object.keys(src)) {
      const v = src[key];
      if (!v) continue;
      let copy = v;
      if (typeof v === 'object') {
        copy = make(v);
        queue.push([v, copy]);

      if (Array.isArray(dst)) dst.push(copy);
      else dst[key] = copy;
    }
  }
  return result;
};
```

## L28. Day 28 · #2694. Event Emitter · `medium` · 💻 Coding

**Group:** Classes · [LeetCode 2694](https://leetcode.com/problems/event-emitter/)

Build an `EventEmitter` class:
- `subscribe(eventName, callback)` registers a listener and returns an object with an `unsubscribe()` method, which removes only **that** subscription. The same callback may be subscribed more than once.
- `emit(eventName, args = [])` calls every listener for that event **in the order they subscribed**, passing `...args`. It returns an array of their return values, or `[]` if there are no listeners.

**Example (own):** subscribe `(a, b) => a + b` and `(a) => a * 10` to `"calc"`. Then `emit("calc", [2, 3])` gives `[5, 20]`.

```js
class EventEmitter {
  subscribe(eventName, callback) {
    return { unsubscribe: () => {} };
  }
  emit(eventName, args = []) {}
}
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
class EventEmitter {
  constructor() {
    this.events = new Map(); // eventName -> Set of unique subscription tokens
  }

  subscribe(eventName, callback) {
    if (!this.events.has(eventName)) this.events.set(eventName, new Set());
    const listeners = this.events.get(eventName);
    // Wrap in a fresh object so the same callback can be subscribed twice
    const token = { callback };
    listeners.add(token);
    return {
      unsubscribe: () => {
        listeners.delete(token);
        if (listeners.size === 0 && this.events.get(eventName) === listeners) {
          this.events.delete(eventName);
        }
        return undefined;
      },
    };
  }

  emit(eventName, args = []) {
    const listeners = this.events.get(eventName);
    if (!listeners) return [];
    // Snapshot so listeners that (un)subscribe during emit do not affect this round
    return [...listeners].map(({ callback }) => callback(...args));
  }
}
```

**Test**

```js
const em = new EventEmitter();
console.log(JSON.stringify(em.emit('none')));

const s1 = em.subscribe('calc', (a, b) => a + b);
const s2 = em.subscribe('calc', a => a * 10);
console.log(JSON.stringify(em.emit('calc', [2, 3])));

s1.unsubscribe();
console.log(JSON.stringify(em.emit('calc', [2, 3])));
console.log(JSON.stringify(s1.unsubscribe())); // idempotent, returns undefined

// Same callback twice = two independent subscriptions
const hello = () => 'hi';
const h1 = em.subscribe('greet', hello);
em.subscribe('greet', hello);
console.log(JSON.stringify(em.emit('greet')));
h1.unsubscribe();
console.log(JSON.stringify(em.emit('greet')));

// Unsubscribing during emit does not skip listeners in the current round
const log = [];
let selfSub;
selfSub = em.subscribe('tick', () => { log.push('once'); selfSub.unsubscribe(); });
em.subscribe('tick', () => log.push('always'));
em.emit('tick');
em.emit('tick');
console.log(log.join(','));

s2.unsubscribe();
console.log(JSON.stringify(em.emit('calc', [1])) + ' events left: ' + [...em.events.keys()].join(','));
```

**Output**

```text
[]
[5,20]
[20]
undefined
["hi","hi"]
["hi"]
once,always,always
[] events left: greet,tick
```

**Approach:** keep a `Map` from event name to an **insertion-ordered `Set`** of subscription tokens. Each `subscribe` wraps the callback in a new `{ callback }` object, so subscribing the same function twice creates two separate entries, and `unsubscribe` removes exactly its own token.

**Why it works:**
- A `Set` keeps insertion order, so `emit` calls listeners in subscription order.
- Deleting a token is O(1). A plain array would need `indexOf` + `splice`, which is O(n).
- The `unsubscribe` closure remembers `token`, `listeners` and `eventName`. It's an arrow function, so it also keeps `this`.

**Key concepts:** classes, closures, `Map`/`Set`, and the **observer (pub/sub) pattern**, which is behind DOM events, Node's `EventEmitter`, Redux store subscriptions and WebSocket price feeds.

**Edge cases shown:**
- Emitting with no listeners gives `[]`.
- Calling `unsubscribe` twice is harmless.
- Duplicate callbacks count separately.
- **Changing listeners during `emit`.** Iterating over a snapshot (`[...listeners]`) means a listener that unsubscribes itself doesn't make the loop skip the next one (`once,always,always`).
- Empty events are removed from the map, so they don't pile up.

**Complexity:** subscribe and unsubscribe are O(1). `emit` is O(k) for k listeners.

**Common mistakes:**
- Storing raw callbacks in a `Set`, which merges duplicates.
- Using `indexOf(callback)` on unsubscribe, which removes the *first* matching callback, not this subscription.
- Returning `undefined` instead of `[]` for unknown events.
- Forgetting to clean up, which leaks memory in SPAs.

**Interview follow-up:** *Add `once`.* `once(name, cb) { const sub = this.subscribe(name, (...a) => { sub.unsubscribe(); return cb(...a); }); return sub; }`. In React, unsubscribe in the `useEffect` cleanup.

**Takeaway:** pub/sub = Map of ordered Sets + unsubscribe closures. Use unique tokens for duplicate listeners and iterate over a snapshot during emit.

## L29. Day 29 · #2695. Array Wrapper · `easy` · 💻 Coding

**Group:** Classes · [LeetCode 2695](https://leetcode.com/problems/array-wrapper/)

Build an `ArrayWrapper` class around an array of integers so that:
- adding two instances with `+` gives the **sum of all their numbers**;
- `String(instance)` gives the array in the form `"[1,2,3]"`.

**Example (own):** `new ArrayWrapper([4, 5]) + new ArrayWrapper([1])` gives `10`, and `String(new ArrayWrapper([7, 8]))` gives `"[7,8]"`.

```js
/**
 * @param {number[]} nums
 */
var ArrayWrapper = function(nums) {};
ArrayWrapper.prototype.valueOf = function() {};
ArrayWrapper.prototype.toString = function() {};
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
var ArrayWrapper = function(nums) {
  this.nums = nums;
};

ArrayWrapper.prototype.valueOf = function() {
  return this.nums.reduce((sum, n) => sum + n, 0);
};

ArrayWrapper.prototype.toString = function() {
  return '[' + this.nums.join(',') + ']';
};

// Alternative: class syntax with Symbol.toPrimitive (one hook for all conversions)
class ArrayWrapper2 {
  constructor(nums) { this.nums = nums; }
  [Symbol.toPrimitive](hint) {
    if (hint === 'string') return '[' + this.nums.join(',') + ']';
    return this.nums.reduce((s, n) => s + n, 0); // 'number' and 'default'
  }
}
```

**Test**

```js
const a = new ArrayWrapper([4, 5]);
const b = new ArrayWrapper([1]);
console.log(a + b);
console.log(String(new ArrayWrapper([7, 8])));
console.log(String(new ArrayWrapper([])));
console.log(new ArrayWrapper([]) + new ArrayWrapper([]));
console.log(a * 2);          // valueOf is used for arithmetic too
console.log(a + '');         // "default" hint -> valueOf first -> "9"
console.log(`${a}`);         // template literal -> "string" hint -> toString
console.log(a > b);

const c = new ArrayWrapper2([1, 2, 3]);
console.log((c + c) + ' ' + String(c) + ' ' + (c + '!'));
```

**Output**

```text
10
[7,8]
[]
0
18
9
[4,5]
true
12 [1,2,3] 6!
```

**Approach:** store the array. Override `valueOf` to return the sum and `toString` to return the bracketed list.

**Why it works:** when JavaScript needs a primitive from an object, it runs **ToPrimitive** with a *hint*:
- `"number"` (`*`, `>`, unary `+`) and `"default"` (binary `+`, `==`) call `valueOf` first, then `toString`.
- `"string"` (`String(x)`, template literals, property keys) calls `toString` first.

So `a + b` becomes `9 + 1 = 10`, while `String(a)` gives `"[4,5]"`.

**Surprise in the test:** `a + ''` is `"9"`, **not** `"[4,5]"`. Binary `+` uses the default hint, so `valueOf` runs first. A template literal uses the string hint and gives `[4,5]`.

**Key concepts:** type coercion, prototype methods, and `Symbol.toPrimitive`. `Symbol.toPrimitive` takes priority over both methods and receives the hint directly (`c + '!'` gives `"6!"`).

**Edge cases:**
- An empty array sums to `0` (reduce needs the `0` start value) and prints as `"[]"`.
- Comparisons like `a > b` also use `valueOf`.

**Complexity:** O(n) per conversion. You could cache the sum if the array never changes.

**Common mistakes:**
- `toString` returning `this.nums.toString()`, which has no brackets.
- `reduce` without a start value, which throws on an empty array.
- Using arrow functions on the prototype, so `this` is wrong.
- Using `JSON.stringify(this.nums)`. It works for integers but hides the intent.

**Interview follow-up:** *What is `[] + {}`?* `""` + `"[object Object]"` = `"[object Object]"`. Both sides fall back to `toString`, because their `valueOf` returns the object itself, which is not a primitive.

**Takeaway:** `valueOf` controls numeric and default coercion, `toString` controls string coercion, and `Symbol.toPrimitive` overrides both.

## L30. Day 30 · #2726. Calculator with Method Chaining · `easy` · 💻 Coding

**Group:** Classes · [LeetCode 2726](https://leetcode.com/problems/calculator-with-method-chaining/)

Build a `Calculator` class that starts from an initial value. `add`, `subtract`, `multiply`, `divide` and `power` each update the result and **return the calculator**, so the calls can be chained. `getResult()` returns the current number. Dividing by zero must throw an error with the message `"Division by zero is not allowed"`. LeetCode accepts results within 1e-5 of the expected answer.

**Example (own):** `new Calculator(2).add(8).divide(5).power(3).getResult()` gives `8`.

```js
class Calculator {
  /** @param {number} value */
  constructor(value) {}
  add(value) {}        // returns Calculator
  subtract(value) {}   // returns Calculator
  multiply(value) {}   // returns Calculator
  divide(value) {}     // returns Calculator
  power(value) {}      // returns Calculator
  getResult() {}       // returns number
}
```

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
class Calculator {
  constructor(value) {
    this.result = value;
  }
  add(value) {
    this.result += value;
    return this;
  }
  subtract(value) {
    this.result -= value;
    return this;
  }
  multiply(value) {
    this.result *= value;
    return this;
  }
  divide(value) {
    if (value === 0) throw new Error("Division by zero is not allowed");
    this.result /= value;
    return this;
  }
  power(value) {
    this.result **= value;
    return this;
  }
  getResult() {
    return this.result;
  }
}
```

**Test**

```js
console.log(new Calculator(2).add(8).divide(5).power(3).getResult());
console.log(new Calculator(10).subtract(4).multiply(3).getResult());
console.log(new Calculator(2).power(-1).getResult());
console.log(Math.abs(new Calculator(0.1).add(0.2).getResult() - 0.3) < 1e-5);

try {
  new Calculator(20).divide(0).getResult();
} catch (e) {
  console.log('Error: ' + e.message);
}

// Chaining returns the same instance
const calc = new Calculator(1);
console.log(calc.add(1) === calc);

// A detached method loses "this" (class bodies are strict mode)
const { add } = new Calculator(5);
try {
  add(1);
} catch (e) {
  console.log(e.name);
}
```

**Output**

```text
8
18
0.5
true
Error: Division by zero is not allowed
true
TypeError
```

**Approach:** keep the running value in `this.result`. Every operation updates it and returns `this`, and `getResult` returns the number.

**Why it works:** each call returns the same object, so the next `.method()` runs on it. This is **method chaining** (a *fluent interface*), as used by jQuery, Lodash's `_.chain`, query builders and `Promise.then`.

**Walk-through:** 2 → `add(8)` = 10 → `divide(5)` = 2 → `power(3)` = 8.

**Key concepts:**
- **`this` in class methods.** Class bodies always run in strict mode, so a detached method (`const { add } = calc`) gets `this === undefined` and throws a `TypeError`. Fix it with `calc.add.bind(calc)`, or define class-field arrow functions.
- **Throwing `Error` objects** so callers can read `e.message`.
- `**=` is the exponent assignment operator (ES2016).

**Edge cases:**
- Divide by zero throws (`-0` also matches `=== 0`).
- Negative powers give fractions.
- Floating-point error: `0.1 + 0.2` is `0.30000000000000004`, which is why LeetCode accepts a 1e-5 tolerance.

**Complexity:** O(1) per operation.

**Common mistakes:**
- Returning `this.result` from the operations, which breaks the chain.
- Returning `new Calculator(...)` (fine if you want immutability, but not what's asked).
- Throwing a string.
- Checking `if (!value)`, which would also reject `NaN`.

**Interview follow-up:** *How would you make this immutable?* Have each method return `new Calculator(newValue)`. Earlier values stay unchanged, which is safer for React state. For money (for example P&L in rupees), work in integer paise or use a decimal library instead of floats.

**Takeaway:** fluent APIs work by returning `this`. Class methods are strict mode, so a detached method loses `this`.

</details>
