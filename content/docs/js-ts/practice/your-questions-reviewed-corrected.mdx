## Y1. Your Question 1: `var` + function declaration with the same name (corrected) · `medium` · 🖨️ Output

```js
var a = 1;

function test() {
  console.log(a);

  var a = 2;

  console.log(a);

  function a() {
    return 3;
  }

  console.log(a);
}

test();

console.log(a);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
[Function: a]
2
2
1
```

**Correction:** the first log inside `test()` is **not `1`**. It prints the **function `a`**. (Node prints `[Function: a]`; the browser console prints `ƒ a() { return 3; }`.)

**Why: hoisting inside `test` happens in two passes:**
1. **Function declarations are hoisted with their body.** `a` is created and set to the function *before any code runs*.
2. **`var a` is hoisted too**, but a `var` declaration never overwrites an existing binding with `undefined`. So `a` is still the function.

As if the engine rewrote `test` like this:
```js
function test() {
  var a = function a() { return 3; }; // hoisted declaration wins
  console.log(a);   // function a
  a = 2;            // the assignment runs where it was written
  console.log(a);   // 2
  // "function a() {}" line does nothing at runtime — it was already hoisted
  console.log(a);   // 2
}
```
The local `a` **shadows** the global one. The global `a` never changes, so the final log is `1`.

**Rule of thumb:** inside a scope, the hoisting priority is **function declaration > var declaration**, but any **assignment** that runs later overwrites the value.

</details>

## Y2. Your Question 2: `setTimeout` vs Promise vs `queueMicrotask` (corrected) · `medium` · 🖨️ Output

```js
console.log("1");

setTimeout(() => {
  console.log("2");

  Promise.resolve().then(() => {
    console.log("3");
  });

  queueMicrotask(() => {
    console.log("4");
  });
}, 0);

new Promise((resolve) => {
  console.log("5");
  resolve();
}).then(() => {
  console.log("6");
});

queueMicrotask(() => {
  console.log("7");
});

console.log("8");
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1
5
8
6
7
2
3
4
```

**Correction:** the answer written in your notes was `1, 5, 6, 8, 7, 2, 3, 4`, but **`8` is printed before `6`**. `8` is synchronous, and **all synchronous code finishes before any microtask runs**.

**Step by step:**
| Step | What happens | Output |
|---|---|---|
| 1 | `console.log("1")` (sync) | `1` |
| 2 | `setTimeout` callback goes to the **macrotask (timer) queue** | |
| 3 | The Promise executor runs **synchronously** → logs `5`, then `resolve()` | `5` |
| 4 | `.then` is attached to an already-resolved promise → its callback is queued as **microtask #1** (logs 6) | |
| 5 | `queueMicrotask` → **microtask #2** (logs 7) | |
| 6 | `console.log("8")` (sync) | `8` |
| 7 | Call stack empty → drain microtasks in FIFO order | `6`, `7` |
| 8 | Next macrotask: the timer callback | `2` |
| 9 | Inside it, two microtasks are queued (3 then 4) and drained right after this macrotask | `3`, `4` |

**Final order:** `1 5 8 6 7 2 3 4`

**Rule:** sync code → **all** microtasks (Promise callbacks, `queueMicrotask`, `await` continuations) → **one** macrotask (timer) → all microtasks again → next macrotask …

</details>

## Y3. Your task: implement `memoizeAsync` (review of your draft + correct solution) · `medium` · 💻 Coding

Implement `memoizeAsync(fn)` so that:
```js
async function fetchUser(id) {
  const response = await fetch(`/api/users/${id}`);
  return response.json();
}

const getUser = memoizeAsync(fetchUser);
await getUser(1); // calls fetchUser
await getUser(1); // returns cached result
await getUser(2); // calls fetchUser again
```

**Review of your draft**

Your idea (keep a cache and return the stored value on a hit) is correct. These are the problems an interviewer would point out:

| # | Issue in the draft | Fix |
|---|---|---|
| 1 | `Function`, `Return`, `Const`, `Else` are capitalised, which is a syntax error in JavaScript | Use lowercase keywords |
| 2 | `Isdatapresent` is declared but `isdatapresent` is read. Identifiers are case-sensitive, so this throws a `ReferenceError` | Use one name |
| 3 | On a cache hit, nothing is returned (only a comment) | `return` the cached value |
| 4 | `arr.filter` scans the whole array on every call (O(n)) | Use a `Map` keyed by the argument (O(1)) |
| 5 | You push `{ Id, ...data }` (capital `I`) but look up `obj.id`, so it never matches (and `data.id` could overwrite it) | Store `key → value` in a `Map` |
| 6 | `if(dat)` is a typo | Remove it or check `data` |
| 7 | **Two concurrent calls `getUser(1)`** both miss the cache and both call the API | Cache the **promise**, not the resolved data |
| 8 | If the request fails, nothing sensible happens (or a bad value gets cached) | Remove the entry when the promise rejects, so the next call retries |
| 9 | Only works for a single `id` argument | Build the key from **all** arguments (`JSON.stringify(args)` or a custom resolver) |
| 10 | No expiry, so data can go stale forever | Optional `ttl` |

<details>
<summary><b>Solution & explanation</b></summary>

**Solution**

```js
// ✅ Production-quality version
function memoizeAsync(fn, { resolver = (...args) => JSON.stringify(args), ttl = Infinity } = {}) {
  const cache = new Map(); // key -> { promise, expiresAt }

  return function (...args) {
    const key = resolver(...args);
    const hit = cache.get(key);
    if (hit && hit.expiresAt > Date.now()) return hit.promise;   // cache hit (even while still pending)

    const promise = Promise.resolve()
      .then(() => fn.apply(this, args))
      .catch(err => {
        if (cache.get(key)?.promise === promise) cache.delete(key); // don't cache failures
        throw err;
      });

    cache.set(key, { promise, expiresAt: Date.now() + ttl });
    return promise;
  };
}

// ✅ Simple version, closest to your draft (fine to start with in an interview, then improve)
function memoizeAsyncSimple(cb) {
  const cache = new Map();
  return async function (id) {
    if (cache.has(id)) return cache.get(id);  // return cached data
    const data = await cb(id);
    cache.set(id, data);
    return data;
  };
}
```

**Test**

```js
let calls = 0;
async function fetchUser(id) {            // mock instead of real fetch
  calls++;
  await new Promise(r => setTimeout(r, 20));
  if (id === 99) throw new Error('User not found');
  return { id, name: 'User ' + id };
}

(async () => {
  const getUser = memoizeAsync(fetchUser);
  console.log((await getUser(1)).name, calls);          // first call → fetch
  console.log((await getUser(1)).name, calls);          // cached
  console.log((await getUser(2)).name, calls);          // different id → fetch

  const [a, b] = await Promise.all([getUser(3), getUser(3)]);
  console.log(a === b, calls);                          // concurrent calls share ONE request

  await getUser(99).catch(e => console.log(e.message, calls));
  await getUser(99).catch(e => console.log(e.message, calls)); // failure not cached → retried

  const getUserShort = memoizeAsync(fetchUser, { ttl: 200 });
  await getUserShort(7);
  await getUserShort(7);
  console.log(calls);                                   // only one extra call
  await new Promise(r => setTimeout(r, 250));
  await getUserShort(7);
  console.log(calls);                                   // expired → fetched again

  const simple = memoizeAsyncSimple(fetchUser);
  await Promise.all([simple(5), simple(5)]);
  console.log(calls);                                   // simple version fetched TWICE (no in-flight dedupe)
})();
```

**Output**

```text
User 1 1
User 1 1
User 2 2
true 3
User not found 4
User not found 5
6
7
9
```

**Key ideas an interviewer wants to hear:**
1. **Closure:** `cache` lives in the outer function's scope. Every call of the returned function shares it, but nothing outside can touch it.
2. **Cache the promise, not the value.** The second concurrent `getUser(3)` finds the *pending* promise and waits on the same request (**in-flight de-duplication**). The simple version misses this, as the last line shows: two calls for id 5.
3. **Evict on failure.** A rejected promise stays rejected forever, so it must be removed, or every later call would fail instantly. The `cache.get(key)?.promise === promise` check makes sure we only delete *our own* entry (not a newer one created after a TTL expiry).
4. **Key from all arguments** with a customisable `resolver`. `JSON.stringify` works for primitives and plain objects; for object identity, use a `WeakMap`.
5. **`fn.apply(this, args)`** preserves `this` when the memoized function is used as a method.
6. **`Promise.resolve().then(() => fn(...))`** also turns a *synchronous throw* inside `fn` into a rejection, so callers can always use `.catch`.
7. **Optional TTL** handles staleness. For unbounded key spaces, add an **LRU size limit** (see the `LRUCache` in the prep guide §4.14).

**Complexity:** O(1) per call (Map lookup), plus the cost of building the key.

</details>
