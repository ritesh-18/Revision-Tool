## O1. `typeof` quirks · `easy` · 🖨️ Output

```js
console.log(typeof null);
console.log(typeof NaN);
console.log(typeof typeof 42);
console.log(typeof function () {});
console.log(typeof class Account {});
console.log(typeof [1, 2]);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
object
number
string
function
function
object
```

1. `typeof null` is `"object"` — a bug from the first JS engine (null had the object type tag) that was never fixed for web compatibility.
2. `NaN` is a value of the **Number** type ("not a number" is still a number), so `"number"`.
3. `typeof 42` is the string `"number"`; `typeof` of any string is `"string"`. `typeof` always returns a string.
4. Callable objects report `"function"`.
5. A class is just a special constructor function, so it is also `"function"`.
6. Arrays are objects; use `Array.isArray` to detect them.

**Takeaway:** `typeof` gives `"object"` for null and arrays, and `"function"` for classes — check null with `=== null` and arrays with `Array.isArray`.

</details>

## O2. String and number with `+` vs `-` · `easy` · 🖨️ Output

```js
console.log('5' - 2);
console.log('5' + 2);
console.log(true + true);
console.log('4' * '3');
console.log(1 + 2 + '3');
console.log('1' + 2 + 3);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
3
52
2
12
33
123
```

1. `-` only works on numbers, so `'5'` becomes `5`: `5 - 2 = 3`.
2. `+` concatenates if **either** operand is a string: `'5' + '2' = '52'`.
3. No strings involved, so booleans become numbers: `1 + 1 = 2`.
4. `*` converts both strings to numbers: `12`.
5. `+` is evaluated left to right: `1 + 2 = 3`, then `3 + '3' = '33'`.
6. `'1' + 2 = '12'` (a string), then `'12' + 3 = '123'`.

**Takeaway:** `+` prefers string concatenation once a string appears; other arithmetic operators always convert to numbers, and evaluation is left to right.

</details>

## O3. `0.1 + 0.2` · `easy` · 🖨️ Output

```js
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);
console.log((0.1 * 10 + 0.2 * 10) / 10);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
0.30000000000000004
false
true
0.3
```

1. Numbers are IEEE-754 doubles. `0.1` and `0.2` cannot be stored exactly in binary, and their sum rounds to the double just above `0.3`, printed as `0.30000000000000004`.
2. So strict equality with `0.3` is `false`.
3. The difference is about `5.5e-17`, smaller than `Number.EPSILON` (about `2.2e-16`), so the tolerance check is `true`.
4. `0.1 * 10` and `0.2 * 10` happen to give exactly `1` and `2`; `3 / 10` prints as `0.3`.

For money (e.g. order values on a trading app), work in the smallest unit (paise) as integers, or use a decimal library.

**Takeaway:** Never compare floats with `===`; compare with a tolerance or use integers.

</details>

## O4. References vs copies · `easy` · 🖨️ Output

```js
let price = 100;
let copyPrice = price;
copyPrice = 200;
console.log(price);

const order = { qty: 1 };
const sameOrder = order;
sameOrder.qty = 5;
console.log(order.qty);
console.log(order === sameOrder);
console.log({ qty: 5 } === { qty: 5 });
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
100
5
true
false
```

1. Primitives are copied by value; changing `copyPrice` does not affect `price` → `100`.
2. `sameOrder` holds a reference to the **same** object, so mutating through it is visible via `order` → `5`.
3. Both variables point to one object, so `===` is `true`.
4. Two object literals create two different objects. `===` compares identity, not contents → `false`.

**Takeaway:** Assigning an object copies the reference, not the object; object equality is identity-based.

</details>

## O5. `||` vs `??` · `easy` · 🖨️ Output

```js
const qty = 0;
const note = '';
console.log(qty || 10);
console.log(qty ?? 10);
console.log(note || 'none');
console.log(note ?? 'none');
console.log(null ?? 'fallback');
console.log(undefined || null || 'last');
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
10
0
none

fallback
last
```

1. `||` returns the right side when the left is **falsy**; `0` is falsy → `10`.
2. `??` only falls back for `null`/`undefined`; `0` is kept → `0`.
3. `''` is falsy → `'none'`.
4. `''` is not nullish, so `??` returns `''` — an empty line is printed.
5. `null` is nullish → `'fallback'`.
6. `||` chains return the first truthy value, or the last operand if none is truthy → `'last'`.

**Takeaway:** Use `??` when `0`, `''` or `false` are valid values (quantities, prices); `||` treats them as missing.

</details>

## O6. Optional chaining · `easy` · 🖨️ Output

```js
const user = { name: 'Asha', address: null };
console.log(user.address?.city);
console.log(user.profile?.city);
console.log(user.getName?.());
console.log(user?.name.length);
console.log(user.address.city);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
undefined
undefined
undefined
4
Uncaught TypeError: Cannot read properties of null (reading 'city')
```

1. `user.address` is `null`, so `?.` short-circuits to `undefined`.
2. `user.profile` is `undefined` → same result.
3. `?.()` calls only if the method exists; `getName` is missing → `undefined` instead of a TypeError.

5. Plain `.` on `null` throws. The message shown is V8's (Chrome/Node); Firefox says something like "user.address is null", Safari words it differently too.

**Takeaway:** `?.` protects only the access directly after it; a plain `.` on `null`/`undefined` still throws.

</details>

## O7. `Array(3)` vs `Array.of(3)` · `easy` · 🖨️ Output

```js
const a = Array(3);
const b = Array.of(3);
const c = Array(3, 4);
console.log(a.length, b.length, c.length);
console.log(JSON.stringify(a));
console.log(JSON.stringify(b));
console.log(JSON.stringify(c));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
3 1 2
[null,null,null]
[3]
[3,4]
```

1. `Array(n)` with a **single number** creates an empty array of length `n` (3 holes). `Array.of(3)` always treats arguments as elements → length 1. With two arguments, `Array(3, 4)` also treats them as elements → length 2. `console.log` joins them with spaces.
2. `JSON.stringify` writes holes (and `undefined`) inside arrays as `null`.
3. `[3]`.
4. `[3,4]`.

**Takeaway:** `Array(n)` is ambiguous; use `Array.of` or `Array.from({ length: n })` to be explicit.

</details>

## O8. Default `sort()` on numbers · `easy` · 🖨️ Output

```js
const prices = [10, 1, 5, 100, 25];
console.log(prices.sort().join(','));
console.log([...prices].sort((a, b) => a - b).join(','));
console.log(prices.join(','));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1,10,100,25,5
1,5,10,25,100
1,10,100,25,5
```

1. Without a comparator, `sort` converts elements to **strings** and compares UTF-16 code units: `"1" < "10" < "100" < "25" < "5"`. `sort` also sorts **in place**.
2. A numeric comparator `a - b` gives ascending numeric order. Spreading into a new array first keeps `prices` untouched.
3. `prices` still holds the string-sorted order from line 1 because that sort mutated it.

**Takeaway:** Always pass `(a, b) => a - b` for numbers, and remember `sort` mutates (use `toSorted` or a copy).

</details>

## O9. Strings are immutable · `easy` · 🖨️ Output

```js
let symbol = 'infy';
symbol[0] = 'I';
console.log(symbol);
symbol.toUpperCase();
console.log(symbol);
symbol = symbol.toUpperCase();
console.log(symbol);

```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
infy
infy
INFY

```

1. Strings are immutable primitives. Assigning to an index is silently ignored in sloppy mode (it would throw a TypeError in strict mode) → `infy`.

3. After reassigning the variable to the returned value → `INFY`.
4. Length is 4; reading an index past the end gives `undefined`.

**Takeaway:** String methods never change the original string; always use the returned value.

</details>

## O10. `NaN` comparisons, `includes` vs `indexOf` · `easy` · 🖨️ Output

```js
const values = [1, NaN, 3];
console.log(NaN === NaN);
console.log(values.indexOf(NaN));
console.log(values.includes(NaN));
console.log(Number.isNaN('abc'), isNaN('abc'));
console.log(Object.is(NaN, NaN), Object.is(0, -0));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
false
-1
true
false true
true false
```

1. `NaN` is the only value not equal to itself.
2. `indexOf` uses strict equality (`===`), so it never finds `NaN` → `-1`.
3. `includes` uses **SameValueZero**, which treats `NaN` as equal to `NaN` → `true`.
4. `Number.isNaN` does not convert: `'abc'` is a string, not NaN → `false`. Global `isNaN` first converts `'abc'` to a number (NaN) → `true`.
5. `Object.is` uses **SameValue**: `NaN` equals `NaN`, but `0` and `-0` are different.

**Takeaway:** Use `Number.isNaN` or `includes` for NaN checks; `===` and `indexOf` can never find it.

</details>

## O11. Destructuring defaults: `undefined` vs `null` · `easy` · 🖨️ Output

```js
const { exchange = 'NSE', qty = 1, price = 0 } = { exchange: undefined, qty: null };
console.log(exchange, qty, price);

const [first = 'a', second = 'b'] = [null];
console.log(first, second);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
NSE null 0
null b
```

1. A destructuring default is used **only when the value is `undefined`**.
   - `exchange` is explicitly `undefined` → default `'NSE'`.
   - `qty` is `null` → `null` is kept (no default).
   - `price` is missing (undefined) → default `0`.
2. For arrays the same rule applies: index 0 is `null` → kept; index 1 does not exist → `'b'`.

This is the same rule as default function parameters.

**Takeaway:** Defaults replace only `undefined`, never `null`.

</details>

## O12. Spread makes a shallow copy · `easy` · 🖨️ Output

```js
const original = { symbol: 'TCS', meta: { lot: 1 } };
const copy = { ...original };
copy.symbol = 'WIPRO';
copy.meta.lot = 50;
console.log(original.symbol);
console.log(original.meta.lot);
console.log(copy.meta === original.meta);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
TCS
50
true
```

1. Spread copies own top-level properties into a new object. Changing `copy.symbol` replaces a property on the copy only → `original.symbol` stays `TCS`.
2. `meta` holds an object; spread copies the **reference**, so both objects share the same `meta`. Mutating it through `copy` shows up in `original` → `50`.
3. The nested references are identical → `true`.

For a deep copy use `structuredClone(original)` (handles most data types) or a hand-written clone.

**Takeaway:** `{...obj}` and `Object.assign` are shallow — nested objects remain shared.

</details>

## O13. IIFE with a private counter · `easy` · 🖨️ Output

```js
const counter = (function () {
  let count = 0;
  return {
    inc: function () { return ++count; },
    get: function () { return count; },
  };
})();
counter.inc();
counter.inc();
console.log(counter.get());
console.log(counter.count);
console.log(typeof count);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
2
undefined
undefined
```

1. The IIFE runs once and returns an object whose methods close over `count`. Two `inc()` calls make it `2`.
2. `count` is a local variable, not a property of the returned object → `undefined`.
3. `count` is not in the outer scope. `typeof` on an undeclared identifier does not throw; it returns `"undefined"`.

This is the classic "module pattern": closures give truly private state.

**Takeaway:** Closure variables are reachable only through the functions that captured them.

</details>

## O16. Method call vs detached function (`this`) · `easy` · 🖨️ Output

```js
'use strict';
const stock = {
  symbol: 'HDFC',
  describe() {
    return typeof this === 'object' ? this.symbol : String(this);
  },
};
console.log(stock.describe());
const detached = stock.describe;
console.log(detached());
const other = { symbol: 'SBIN', describe: stock.describe };
console.log(other.describe());
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
HDFC
undefined
SBIN
```

`this` is decided by **how** a function is called, not where it is defined.

1. `stock.describe()` — called as a method, so `this` is `stock` → `HDFC`.
2. `detached()` is a plain call. In strict mode `this` is `undefined`, so the function returns `String(undefined)`. (In sloppy mode it would be the global object.)
3. The same function called as `other.describe()` gets `this = other` → `SBIN`.

**Takeaway:** The object before the dot at call time is `this`; pulling a method off its object loses that binding.

</details>

## O17. `['1','2','3'].map(parseInt)` · `medium` · 🖨️ Output

```js
console.log(['1', '2', '3'].map(parseInt).join(','));
console.log(['10', '10', '10'].map(parseInt).join(','));
console.log(['1', '2', '3'].map(Number).join(','));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
1,NaN,NaN
10,NaN,2
1,2,3
```

`map` calls its callback with `(element, index, array)`, and `parseInt` takes `(string, radix)` — so the **index becomes the radix**.

1. `parseInt('1', 0)` → radix 0 means "auto" (base 10) → `1`. `parseInt('2', 1)` → radix 1 is invalid → `NaN`. `parseInt('3', 2)` → `3` is not a binary digit → `NaN`.
2. `parseInt('10', 0)` → `10`; `parseInt('10', 1)` → `NaN`; `parseInt('10', 2)` → binary 10 = `2`.
3. `Number` ignores extra arguments → `1,2,3`.

**Takeaway:** Don't pass functions with optional parameters directly to `map`; use `s => parseInt(s, 10)` or `Number`.

</details>

## O18. `[] + {}` and friends · `medium` · 🖨️ Output

```js
console.log([] + []);
console.log([] + {});
console.log([1, 2] + [3]);
console.log({} + 'x');
console.log(+[]);
console.log(+{});
console.log([] - 1, [5] * 2);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text

[object Object]
1,23
[object Object]x
0
NaN
-1 10
```

Objects used with `+` are converted to primitives (`valueOf`, then `toString`).

1. `[]` → `''`; `'' + ''` → an empty line.

3. `[1,2]` → `'1,2'`, `[3]` → `'3'` → `'1,23'`.

</details>

## O19. `[] == ![]` and `null` comparisons · `medium` · 🖨️ Output

```js
console.log([] == ![]);
console.log(null == 0);
console.log(null >= 0);
console.log(undefined == null);
console.log(undefined == 0);
console.log('' == 0, '0' == false);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
true
false
true
true
false
true true
```

1. `![]` is `false` (arrays are truthy). `[] == false` → the boolean becomes `0`, `[]` becomes `''` then `0` → `0 == 0` → `true`.

**Takeaway:** `==` and relational operators follow different conversion rules; use `===` to avoid surprises.

</details>

## O20. Object keys are coerced to strings · `medium` · 🖨️ Output

```js
const cache = {};
const keyA = { id: 1 };
const keyB = { id: 2 };
cache[keyA] = 'first';
cache[keyB] = 'second';
console.log(cache[keyA]);
console.log(Object.keys(cache).join('|'));
cache[1] = 'one';
console.log(cache['1']);
console.log(Object.keys(cache).join('|'));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
second
[object Object]
one
1|[object Object]
```

1. Plain-object keys must be strings (or Symbols). Both `keyA` and `keyB` convert to `"[object Object]"`, so the second assignment overwrites the first → reading with `keyA` gives `'second'`.
2. At that point the object has exactly one key, the string `"[object Object]"`.
3. Number `1` becomes the string `"1"`, so `cache['1']` reads the same property → `'one'`.
4. Now there are two keys. `"1"` is listed first because integer-like keys come before other string keys.

**Takeaway:** Use a `Map` when you need objects (or distinct number/string) as keys.

</details>

## O21. Property order: integer keys first · `medium` · 🖨️ Output

```js
const book = { b: 1, 10: 'x', a: 2, 2: 'y', '-1': 'z', '01': 'w' };
console.log(Object.keys(book).join(','));
console.log(JSON.stringify(book));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
2,10,b,a,-1,01
{"2":"y","10":"x","b":1,"a":2,"-1":"z","01":"w"}
```

Own string keys are ordered by the spec as:
1. **Array-index-like keys** (canonical non-negative integers) in ascending numeric order: `2`, `10`.
2. All other string keys in **insertion order**: `b`, `a`, `-1`, `01`. `'-1'` is negative and `'01'` is not canonical (it would print as `1`), so both count as ordinary strings.

(Symbol keys would come after all strings, but `Object.keys` skips them.)

`JSON.stringify` follows the same order.

**Takeaway:** Don't rely on insertion order for numeric-looking keys — integer keys are always sorted first; use a `Map` for guaranteed insertion order.

</details>

## O22. `Object.freeze` is shallow · `medium` · 🖨️ Output

```js
const config = Object.freeze({ env: 'prod', limits: { maxQty: 100 } });
config.env = 'dev';
config.newKey = true;
config.limits.maxQty = 500;
console.log(config.env);
console.log(config.newKey);
console.log(config.limits.maxQty);

```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
prod
undefined
500
true false
```

This script is in sloppy mode, so writes to a frozen object fail **silently** (strict mode would throw a TypeError).

1. `env` is non-writable → stays `'prod'`.
2. Frozen objects are non-extensible, so `newKey` was never added → `undefined`.
3. `freeze` only affects the object's own properties. `limits` still points to a normal, unfrozen object, so `maxQty` changes → `500`.

**Takeaway:** `Object.freeze` is shallow — recursively freeze nested objects if you need deep immutability.

</details>

## O23. `delete` on arrays leaves holes · `medium` · 🖨️ Output

```js
const ids = ['a', 'b', 'c'];
delete ids[1];
console.log(ids.length);
console.log(1 in ids);
let visits = 0;
ids.forEach(() => visits++);
console.log(visits);
console.log(ids.map(x => x.toUpperCase()).length);
console.log(JSON.stringify(ids));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text

false
2
3

```

1. `delete` removes the property but does **not** shift elements or change `length` → `3`.

</details>

## O24. `in` vs `hasOwnProperty` · `medium` · 🖨️ Output

```js
const base = { exchange: 'NSE' };
const order = Object.create(base);
order.qty = 10;
order.note = undefined;
console.log('exchange' in order);
console.log(order.hasOwnProperty('exchange'));
console.log(Object.hasOwn(order, 'note'));
console.log(order.note !== undefined);
console.log('toString' in order);
console.log(Object.keys(order).join(','));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
true
false
true
false
true
qty,note
```

<summary><b>Output & explanation</b></summary>

**Output**

```js
}
```

```js
  finally { return 'swallowed'; }

console.log(c());
console.log(d());
console.log(e());
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text

try
finally
1
d finally
catch:boom
swallowed
```

1–2. `a`: the return value `'try'` is computed, then `finally` runs (logging first), then the function returns `'try'`.

## O49. Recursion order of output · `hard` · 🖨️ Output

```js
function walk(n, depth) {
  if (n === 0) {
    console.log(depth + 'base');
    return 0;
  }
  console.log(depth + 'down ' + n);
  const r = n + walk(n - 1, depth + '-');
  console.log(depth + 'up ' + r);
  return r;
}
console.log(walk(3, ''));
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
down 3
-down 2
--down 1
---base
--up 1
-up 3
up 6
6
```

Each call logs before recursing ("down") and after the recursive call returns ("up").

1–3. Calls go deeper: `walk(3)`, `walk(2)`, `walk(1)` each log "down" with growing indentation.
4. `walk(0)` hits the base case and returns `0`.
5. The stack unwinds: `walk(1)` computes `1 + 0 = 1` → `--up 1`.
6. `walk(2)`: `2 + 1 = 3` → `-up 3`.
7. `walk(3)`: `3 + 3 = 6` → `up 6`.
8. The outer `console.log` prints the final result `6`.

**Takeaway:** Code before a recursive call runs top-down; code after it runs bottom-up as the call stack unwinds.

</details>

## O50. `arguments` aliasing: sloppy vs strict · `hard` · 🖨️ Output

```js
function sloppy(a) {
  a = 2;
  arguments[0] = 3;
  return a;
}
function strict(a) {
  'use strict';
  a = 2;
  arguments[0] = 3;
  return a + ':' + arguments[0];
}
function withDefault(a = 0) {
  a = 2;
  return arguments[0];
}
function outer() {
  const arrow = () => arguments[0];
  return arrow('arrow-arg');
}
console.log(sloppy(1));
console.log(strict(1));
console.log(withDefault(1));
console.log(outer('outer-arg'));
console.log(sloppy.length, withDefault.length, ((x, y = 1, z) => 0).length);
```

<details>
<summary><b>Output & explanation</b></summary>

**Output**

```text
3
2:3
1
outer-arg
1 0 1
```

1. In sloppy functions with **simple** parameters, `arguments[i]` and the named parameter are linked (a "mapped" arguments object). Writing `arguments[0] = 3` also changes `a` → `3`.
2. In strict mode the link is removed: `a` is `2`, `arguments[0]` is `3` → `2:3`.
3. Any default/rest/destructured parameter also makes `arguments` unmapped, so it keeps the original `1`.
4. Arrow functions have no own `arguments`; `arrow` sees `outer`'s `arguments`, so it returns `'outer-arg'`, not its own argument.
5. A function's `length` counts parameters **before the first default or rest parameter**: `sloppy` → 1, `withDefault` → 0, and `(x, y = 1, z)` → 1 (`z` comes after a default, so it is not counted).

**Takeaway:** Only sloppy functions with simple parameter lists alias `arguments`, arrows borrow the outer `arguments`, and `fn.length` stops at the first default — prefer rest parameters.

</details>
