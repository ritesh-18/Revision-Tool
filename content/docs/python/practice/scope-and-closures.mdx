---
title: "Scope and closures"
description: Predict the output of snippets about LEGB lookup, global and nonlocal, UnboundLocalError and late-binding closures.
---

Python resolves names with the LEGB rule (Local, Enclosing, Global, Builtins), and it decides whether a name is local **at compile time**, by looking for any assignment to it anywhere in the function body. Closures capture variables, not values. Keep those two facts in mind for every question below.

Read each snippet, write down the exact output, then open the answer.

### Q 1 · Easy

```python
x = "global"

def f():
    print(x)

def g():
    x = "local"
    print(x)

f()
g()
print(x)
```

<details>
<summary>Answer</summary>

```text title="Output"
global
local
global
```

Explanation: `f` never assigns `x`, so the lookup goes Local (miss), Enclosing (none), Global (hit). `g` assigns `x`, which makes `x` a **local** of `g` for the whole function body. That local shadows the global and disappears when `g` returns, so the module-level `x` is unchanged.

</details>

### Q 2 · Easy

```python
count = 0

def inc():
    global count
    count += 1

inc()
inc()
print(count)
```

<details>
<summary>Answer</summary>

```text title="Output"
2
```

Explanation: `global count` tells the compiler that every use of `count` inside `inc` refers to the module-level name, so `count += 1` rebinds the global. Without that declaration the same code raises `UnboundLocalError` (see the next question). In JavaScript, assigning to an outer `let` from inside a function just works. In Python, **reading** an outer name works, but **rebinding** it needs `global` or `nonlocal`.

</details>

### Q 3 · Medium

```python
x = 1

def f():
    print(x)
    x = 2

f()
```

<details>
<summary>Answer</summary>

```text title="Output"
Traceback (most recent call last):
  ...
UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
```

Explanation: Because `x = 2` appears somewhere in `f`, the compiler marks `x` as local for the **entire** function, including the line before the assignment. At run time `print(x)` reads a local slot that has not been filled yet, so Python raises `UnboundLocalError` (a subclass of `NameError`) instead of falling back to the global.

This is close to JavaScript's temporal dead zone: `let x` inside a block also shadows the outer `x` from the start of the block, and reading it early throws a `ReferenceError`.

</details>

### Q 4 · Medium

```python
def make_counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

a = make_counter()
b = make_counter()
print(a(), a(), b(), a())
```

<details>
<summary>Answer</summary>

```text title="Output"
1 2 1 3
```

Explanation: Each call to `make_counter` creates a new local `n` and a new `inc` closure over it. `nonlocal n` lets `inc` rebind the enclosing function's variable instead of creating its own local. `a` and `b` close over **different** `n` cells, so `b()` starts from 1 while `a` keeps counting. This is the classic JavaScript counter closure. The only extra step is the explicit `nonlocal`.

</details>

### Q 5 · Medium

```python
def make():
    items = []
    def add(x):
        items.append(x)
        return items
    return add

add = make()
add(1)
print(add(2))
```

<details>
<summary>Answer</summary>

```text title="Output"
[1, 2]
```

Explanation: No `nonlocal` is needed here because `add` never **rebinds** `items`. It only reads the name and calls a method that mutates the list. Reading an enclosing variable is always allowed, so the closure keeps appending to the same list across calls. `nonlocal` is only required for assignments such as `items = ...` or `items += ...`.

</details>

### Q 6 · Medium

```python
fns = []
for i in range(3):
    fns.append(lambda: i)

print([f() for f in fns])
```

<details>
<summary>Answer</summary>

```text title="Output"
[2, 2, 2]
```

Explanation: Closures capture the **variable**, not its value at creation time (late binding). All three lambdas refer to the same module-level `i`, and they are called after the loop has finished, when `i` is 2.

In JavaScript, `for (let i ...)` creates a fresh binding per iteration and would give `[0, 1, 2]`, while `var i` would give `[3, 3, 3]`. A Python `for` loop never creates a new scope, so it behaves like `var`, except the last value is 2 because `range` stops there.

</details>

### Q 7 · Medium

```python
fns = [lambda i=i: i * 10 for i in range(3)]

print([f() for f in fns])
print(fns[0](7))
```

<details>
<summary>Answer</summary>

```text title="Output"
[0, 10, 20]
70
```

Explanation: `i=i` is a default argument, and defaults are evaluated **when the lambda is created**. Each lambda therefore stores the current value of `i` as its own default, which fixes the late-binding problem. The trade-off is that the value is now an overridable parameter, so `fns[0](7)` returns 70. `functools.partial` is the other common fix.

</details>

### Q 8 · Medium

```python
def outer():
    x = 1
    def inner():
        return x
    x = 2
    return inner

print(outer()())
```

<details>
<summary>Answer</summary>

```text title="Output"
2
```

Explanation: `inner` does not copy `x` when it is defined. It holds a reference to the cell that stores `outer`'s `x`. By the time `inner` is called, that cell contains 2. This is the same late-binding mechanism as the lambda loop, without a loop.

</details>

### Q 9 · Medium

```python
for i in range(3):
    pass
print(i)

squares = [j * j for j in range(3)]
try:
    print(j)
except NameError as e:
    print("NameError:", e)
```

<details>
<summary>Answer</summary>

```text title="Output"
2
NameError: name 'j' is not defined
```

Explanation: A `for` statement has no scope of its own. The loop variable is an ordinary variable of the enclosing scope and keeps its last value after the loop. Comprehensions are different: their iteration variable is private to the comprehension, so `j` does not leak. (Since Python 3.12 comprehensions are inlined for speed, but this isolation is preserved.)

</details>

### Q 10 · Medium

```python
e = "before"
try:
    1 / 0
except ZeroDivisionError as e:
    pass
print(e)
```

<details>
<summary>Answer</summary>

```text title="Output"
Traceback (most recent call last):
  ...
NameError: name 'e' is not defined
```

Explanation: At the end of an `except ... as e` block, Python implicitly runs `del e`. This prevents a reference cycle (the exception's traceback references the frame, which references the exception). Because `e` is the same name as the earlier variable, the original `"before"` binding is gone too, and `print(e)` raises `NameError`. JavaScript's `catch (e)` creates a block-scoped binding that shadows the outer one and leaves it untouched.

</details>

### Q 11 · Hard

```python
class C:
    x = 10
    ys = [y for y in range(x)]
    print(len(ys))
    doubled = [x * 2 for _ in range(2)]
```

<details>
<summary>Answer</summary>

```text title="Output"
10
Traceback (most recent call last):
  ...
NameError: name 'x' is not defined
```

Explanation: A class body is a scope, but it is **not** an enclosing scope for functions or comprehensions defined inside it. The outermost iterable of a comprehension (`range(x)`) is evaluated in the class body, so the first comprehension works. The expression `x * 2` runs inside the comprehension's own scope, which skips the class namespace and looks in globals, where there is no `x`. This is also why methods must write `self.x` or `C.x` and cannot just say `x`.

</details>

### Q 12 · Hard

```python
x = "g"

def outer():
    x = "outer"
    def inner():
        global x
        x = "set by inner"
    inner()
    print("outer sees:", x)

outer()
print("module sees:", x)
```

<details>
<summary>Answer</summary>

```text title="Output"
outer sees: outer
module sees: set by inner
```

Explanation: `global x` inside `inner` jumps straight to the module scope and skips `outer`'s local `x`. So `inner` rebinds the module-level `x`, and `outer`'s own `x` is untouched. To rebind `outer`'s variable you would need `nonlocal x` instead. `global` and `nonlocal` are explicit about **which** scope you mean.

</details>

### Q 13 · Hard

```python
print("start")

def f():
    nonlocal y
    y = 1
```

<details>
<summary>Answer</summary>

```text title="Output"
  ...
SyntaxError: no binding for nonlocal 'y' found
```

Explanation: `nonlocal` must refer to a variable in an **enclosing function** scope, and the module scope does not count. This is checked when the file is compiled, before any code runs, so even `print("start")` never executes. Python reports a `SyntaxError` with no runtime traceback. Scope errors that JavaScript reports at run time are often compile-time errors in Python.

</details>

### Q 14 · Hard

```python
def outer():
    a = 1
    b = 2
    def inner():
        return a
    return inner

f = outer()
print(f.__code__.co_freevars)
print(f.__closure__[0].cell_contents)
```

<details>
<summary>Answer</summary>

```text title="Output"
('a',)
1
```

Explanation: The compiler works out which enclosing variables a nested function actually uses. `inner` references only `a`, so only `a` is stored in a **cell** and listed in `co_freevars`. `b` stays an ordinary local of `outer` and is freed when `outer` returns. `__closure__` is the tuple of cells attached to the function object, and `cell_contents` is the current value. That is the concrete mechanism behind late binding: the closure holds the cell, not a snapshot.

</details>

### Q 15 · Hard

```python
def f():
    data = [3, 8, 1]
    if any((big := x) > 5 for x in data):
        print("first big:", big)
    print([last := n for n in range(3)], last)

f()
```

<details>
<summary>Answer</summary>

```text title="Output"
first big: 8
[0, 1, 2] 2
```

Explanation: The walrus operator `:=` inside a comprehension or generator expression binds the name in the **enclosing function's** scope, not the comprehension's private scope (PEP 572 makes this exception on purpose). `any` stops at the first true value, so `big` holds 8, the value that satisfied the test. In the list comprehension `last` is rebound on every iteration and keeps the final value, 2, after the comprehension ends, while `n` itself does not leak.

</details>
