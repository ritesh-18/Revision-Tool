Each page in this section is a set of short, self-contained snippets. Your job is to predict **exactly** what each one prints, then check. The questions are chosen to expose a specific mechanism (aliasing, late binding, the MRO, generator laziness, event-loop scheduling), so a wrong guess points straight at the part of the mental model that needs fixing.

## How to practise

1. **Read the code carefully, top to bottom.** Note every name that is rebound, every object that is mutated, and every place where control can jump (`yield`, `await`, `return` inside `try`, `raise`).
2. **Write your prediction down** before opening the answer, character for character, including blank lines and error lines. A vague "it prints the list twice" does not count.
3. **Open the answer** and compare. If you were wrong, read the explanation and name the mechanism you missed. Then change the snippet slightly and predict again.
4. **Run it yourself** when in doubt. Paste the snippet into a file and run `python file.py`, or use the REPL.

Each question is tagged Easy, Medium or Hard, and each page goes from easy to hard. Many explanations end with what JavaScript would do differently, because those contrasts are where JS habits lead you astray.

## Conventions

<Callout type="info">
  - Every output was produced by running the snippet with **CPython 3.14.6**. Most outputs are the same on 3.11 and later. Where a newer version changes the output (for example error message wording, or the 3.14 `SyntaxWarning` for `return` in `finally`), the explanation says so.
  - Snippets are run as a script named `main.py`, so warnings mention that file name.
  - Tracebacks are trimmed: `...` replaces the file, line and source frames, keeping the header and the exception lines.
  - No output depends on hash randomisation, memory addresses, timing or the platform. The asyncio questions use `asyncio.sleep(0)` instead of timed sleeps, so their order is deterministic.
</Callout>
