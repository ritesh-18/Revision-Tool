Python has only two loops, `for` and `while`, and its `for` is not the C-style counter loop. It is a **for-each over any iterable**, driven by the iterator protocol. On top of that sit comprehensions, a compact expression syntax for building lists, dicts, sets and lazy generators. Idiomatic Python uses comprehensions and the iteration helpers (`enumerate`, `zip`) much more than index-based loops.

<Callout type="info">
Snippets were run on **CPython 3.14.6**. Timings and `sys.getsizeof` numbers are machine and version specific.
</Callout>

## `for` iterates over any iterable

```python
for ch in "hi":
    print(ch, end=" ")
for k in {"a": 1, "b": 2}:
    print(k, end=" ")
for k, v in {"a": 1, "b": 2}.items():
    print(f"{k}={v}", end=" ")
for x in {3, 1, 2}:
    print(x, end=" ")
print()
```

```text title="Output"
h i a b a=1 b=2 1 2 3
```

- Iterating a dict gives its **keys** (in insertion order). Use `.items()` for pairs and `.values()` for values.
- Iterating a set gives elements in an arbitrary (hash-based) order. Small ints happen to come out sorted; do not rely on it.
- `for k, v in ...` uses **tuple unpacking** on each element.

### What `for` does underneath

`for x in obj:` is roughly this:

```python
it = iter(obj)              # calls obj.__iter__()
while True:
    try:
        x = next(it)        # calls it.__next__()
    except StopIteration:
        break
    ...body...
```

```python
items = ["a", "b"]
it = iter(items)
print(next(it), next(it))
try:
    next(it)
except StopIteration:
    print("StopIteration")
```

```text title="Output"
a b
StopIteration
```

Anything that implements `__iter__` (returning an iterator) is an **iterable**: lists, strings, dicts, files (line by line), generators, database cursors, `range`. An **iterator** is the object that keeps the current position and implements `__next__`. The iterator protocol has its own page; for now, the key ideas are that `for` works on any iterable, and that the loop ends when the iterator raises `StopIteration`. In bytecode this is `GET_ITER` followed by a `FOR_ITER` instruction per step (specialized for lists, ranges and generators).

<Mermaid chart={`flowchart LR
  A["for x in obj"] --> B["it = iter(obj)"]
  B --> C{"next(it)"}
  C -->|"value"| D["bind x, run body"]
  D --> C
  C -->|"StopIteration"| E["loop ends<br/>run else block if no break"]`} />

<Callout title="Coming from JS">
Python's `for x in items` is JavaScript's `for (const x of items)` (the iterator protocol, `Symbol.iterator` vs `__iter__`). There is **no** equivalent of JS `for...in` over object keys with prototype surprises; iterating a dict just gives its keys. And there is no `for (let i = 0; i < n; i++)`; you use `range`. Unlike `const x` in JS, the Python loop variable is an ordinary variable in the enclosing function scope.
</Callout>

## `range`

`range(stop)`, `range(start, stop)`, `range(start, stop, step)` produce integers from `start` up to but **not including** `stop`.

```python
r = range(0, 10, 3)
print(r, list(r), len(r), r[1], 6 in r, list(range(5, 0, -2)), range(10**18)[-1])
import sys
print(sys.getsizeof(range(10**9)), sys.getsizeof(list(range(1000))))
```

```text title="Output"
range(0, 10, 3) [0, 3, 6, 9] 4 3 True [5, 3, 1] 999999999999999999
48 8056
```

`range` is not a list or a generator. It is a lazy, immutable **sequence** that stores only `start`, `stop` and `step` and computes elements on demand. So:

- `range(10**9)` takes 48 bytes.
- `len`, indexing, slicing and `in` are O(1) arithmetic (for int arguments), not scans.
- It can be iterated many times (unlike a generator).

Prefer iterating over items directly. `for i in range(len(items)):` followed by `items[i]` is a code smell in Python; use `enumerate` when you need the index.

## `enumerate`

```python
for i, name in enumerate(["ann", "bob"], start=1):
    print(i, name)
print(list(enumerate("ab")))
```

```text title="Output"
1 ann
2 bob
[(0, 'a'), (1, 'b')]
```

`enumerate` wraps any iterable and yields `(index, item)` pairs lazily. `start=` sets the first index (useful for human-facing numbering like line numbers).

Unpacking can be nested:

```python
for i, (name, score) in enumerate([("ann", 9), ("bob", 7)]):
    print(i, name, score)
for first, *rest in [(1, 2, 3), (4, 5)]:
    print(first, rest)
```

```text title="Output"
0 ann 9
1 bob 7
1 [2, 3]
4 [5]
```

## `zip` and `strict=True`

`zip` walks several iterables in parallel and yields tuples. By default it **stops at the shortest** input, silently dropping the rest:

```python
names = ["ann", "bob", "cy"]
ages = [31, 25]
print(list(zip(names, ages)))
try:
    list(zip(names, ages, strict=True))
except ValueError as e:
    print("ValueError:", e)
from itertools import zip_longest
print(list(zip_longest(names, ages, fillvalue=None)))
```

```text title="Output"
[('ann', 31), ('bob', 25)]
ValueError: zip() argument 2 is shorter than argument 1
[('ann', 31), ('bob', 25), ('cy', None)]
```

- Silent truncation hides bugs (for example, columns and values from two sources that got out of sync). Since 3.10, `strict=True` raises `ValueError` on a length mismatch. Use it whenever the inputs **should** be the same length. (Ruff rule `B905` flags `zip` calls without `strict=`.)
- `itertools.zip_longest` pads the shorter inputs instead.

Two classic idioms:

```python
pairs = [("a", 1), ("b", 2)]
letters, nums = zip(*pairs)              # "unzip": transpose
print(letters, nums, dict(zip(names, ages)))
```

```text title="Output"
('a', 'b') (1, 2) {'ann': 31, 'bob': 25}
```

`zip(*pairs)` passes each pair as a separate argument, so zipping them regroups first elements together and second elements together. `dict(zip(keys, values))` builds a dict from two parallel lists.

<Callout title="Coming from JS">
JavaScript has no built-in `zip` or `enumerate`; you write `arr.forEach((x, i) => ...)`, `arr.entries()`, or use lodash's `_.zip`. In Python these are lazy built-ins that work on any iterable, not just arrays.
</Callout>

## `while`

`while condition:` repeats as long as the condition is truthy. Use it when you do not know the number of iterations in advance (polling, retries, reading until a sentinel, algorithms).

```python
n = 10
steps = 0
while n != 1:
    n = n // 2 if n % 2 == 0 else 3 * n + 1
    steps += 1
print(steps)
```

```text title="Output"
6
```

There is no `do ... while`. The idiom is `while True:` with a `break`, or the walrus operator:

```python
while True:
    line = input("> ")
    if line == "quit":
        break
    handle(line)

while (chunk := f.read(65536)):
    process(chunk)
```

## `break` and `continue`

`break` exits the innermost loop immediately; `continue` skips to the next iteration.

```python
for i in range(10):
    if i % 2:
        continue
    if i > 6:
        break
    print(i, end=" ")
print()
```

```text title="Output"
0 2 4 6
```

Python has **no labelled break**. To exit nested loops, move the loops into a function and `return`, use a flag, or restructure with `itertools.product` so there is only one loop.

## `for ... else` and `while ... else`

A loop can have an `else` block. It runs when the loop finishes **without hitting `break`** (including when it runs zero times). Think of it as "no break".

```python
def find(users, target):
    for u in users:
        if u == target:
            print("found", u)
            break
    else:
        print("not found", target)

find(["a", "b"], "b"); find(["a", "b"], "z")

attempts = 0
while attempts < 3:
    attempts += 1
    if attempts == 5:
        break
else:
    print("gave up after", attempts)

for x in []:
    pass
else:
    print("else runs for empty loop too")
```

```text title="Output"
found b
not found z
gave up after 3
else runs for empty loop too
```

Its main use is the search pattern above: it removes the need for a `found = False` flag. That said, many developers misread `else` as "runs if the loop body never ran". If your team finds it confusing, a helper function that returns early, or `next((u for u in users if u == target), None)`, is clearer.

<Callout title="Coming from JS">
There is no JS equivalent of loop `else`. The closest is a labelled block or a flag variable. Also, `return` inside the loop skips the `else` (just like `break`), and an exception does too.
</Callout>

## The loop variable after the loop

```python
for i in range(3):
    pass
print("i after loop:", i)

for j in []:
    pass
try:
    print(j)
except NameError as e:
    print("NameError:", e)
```

```text title="Output"
i after loop: 2
NameError: name 'j' is not defined
```

The loop variable is a normal variable in the enclosing scope. It keeps its last value after the loop, and it is never assigned if the iterable was empty. Reassigning it inside the body does not affect the iteration, because the next value comes from the iterator:

```python
for i in range(3):
    print(i, end=" ")
    i = 100
print()
```

```text title="Output"
0 1 2
```

## Comprehensions

A comprehension builds a collection from an iterable in one expression:

```text
[expression for item in iterable if condition]
```

```python
nums = [1, 2, 3, 4, 5, 6]
print([n * n for n in nums if n % 2 == 0])
print(["even" if n % 2 == 0 else "odd" for n in nums[:3]])
print({n: n * n for n in nums[:3]})
print({len(w) for w in ["hi", "yo", "hey"]})

users = [{"id": 1, "name": "ann"}, {"id": 2, "name": "bob"}]
by_id = {u["id"]: u["name"] for u in users}
print(by_id, {v: k for k, v in by_id.items()})
```

```text title="Output"
[4, 16, 36]
['odd', 'even', 'odd']
{1: 1, 2: 4, 3: 9}
{2, 3}
{1: 'ann', 2: 'bob'} {'ann': 1, 'bob': 2}
```

- **List** comprehension: square brackets. **Set** comprehension: braces with a single expression. **Dict** comprehension: braces with `key: value`.
- The trailing `if` **filters**. A conditional expression in the expression position (`a if c else b`) **transforms** every item. They are different things and can be combined.
- There is no tuple comprehension: parentheses make a generator expression (below). Use `tuple(x for x in ...)`.

<Callout title="Coming from JS">
`nums.filter(n => n % 2 === 0).map(n => n * n)` becomes `[n * n for n in nums if n % 2 == 0]`. `Object.fromEntries(users.map(u => [u.id, u.name]))` becomes `{u["id"]: u["name"] for u in users}`. Python does have `map` and `filter` built-ins (returning lazy iterators), but comprehensions are considered more idiomatic and are usually faster than `map` with a `lambda`.
</Callout>

### Why comprehensions are fast

A comprehension avoids the attribute lookup and method call of `result.append(x)` on each iteration; the compiler emits a dedicated `LIST_APPEND` instruction. Since 3.12 (PEP 709), list, dict and set comprehensions are also **inlined** into the surrounding function instead of creating and calling a hidden function object each time. A rough measurement doubling 100,000 ints:

```python
import timeit
setup = "data = list(range(100000))"
cases = {
    "listcomp": "[x * 2 for x in data]",
    "loop    ": "r = []\nfor x in data: r.append(x * 2)",
    "map     ": "list(map(lambda x: x * 2, data))",
}
for label, stmt in cases.items():
    best = min(timeit.repeat(stmt, setup, number=50, repeat=3))
    print(label, round(best * 20, 2), "ms")   # per run: best / 50 * 1000
```

```text title="Output"
listcomp 4.62 ms
loop     6.2 ms
map      7.69 ms
```

The difference is real but modest. Choose comprehensions for readability first; they are fast as a bonus.

### Nested comprehensions

Multiple `for` clauses read **left to right in the same order as nested loops**:

```python
matrix = [[1, 2, 3], [4, 5, 6]]
print([x for row in matrix for x in row])             # flatten
print([[row[i] for row in matrix] for i in range(3)]) # transpose (a comprehension inside one)
print([(x, y) for x in range(3) for y in range(x)])   # later clauses can use earlier variables
```

```text title="Output"
[1, 2, 3, 4, 5, 6]
[[1, 4], [2, 5], [3, 6]]
[(1, 0), (2, 0), (2, 1)]
```

`[x for row in matrix for x in row]` is equivalent to:

```python
result = []
for row in matrix:
    for x in row:
        result.append(x)
```

A good rule: one `for` plus one `if` is fine, two `for` clauses is the limit, and anything more complex should become a regular loop or a generator function.

**New in Python 3.15** (PEP 798): `*` and `**` unpacking are allowed in comprehensions, so flattening can be written `[*row for row in matrix]` and merging dicts `{**d for d in dicts}`. Use it only if all your environments run 3.15+.

## Generator expressions vs list comprehensions

Replace the square brackets with parentheses and you get a **generator expression**: a lazy iterator that produces items one at a time, on demand, instead of building the whole list in memory.

```python
import sys
sq_list = [n * n for n in range(1_000_000)]
sq_gen = (n * n for n in range(1_000_000))
print(sys.getsizeof(sq_list), sys.getsizeof(sq_gen))
print(sum(n * n for n in range(1_000_000)))
print(type(sq_gen).__name__, next(sq_gen), next(sq_gen))
```

```text title="Output"
8448728 208
333332833333500000
generator 0 1
```

The list holds a million references (about 8 MB for the pointer array alone, plus the int objects themselves). The generator is 208 bytes no matter how many items it will produce. When a generator expression is the only argument to a function, the extra parentheses can be dropped: `sum(n * n for n in ...)`.

<Mermaid chart={`flowchart TB
  subgraph L["List comprehension"]
    L1["run the whole loop now"] --> L2["store all N results<br/>O(N) memory"] --> L3["iterate as often as you like"]
  end
  subgraph G["Generator expression"]
    G1["create generator, nothing runs yet"] --> G2["next() computes one item<br/>O(1) memory"] --> G3["single pass, then exhausted"]
  end`} />

Trade-offs:

| | List comprehension | Generator expression |
|---|---|---|
| Memory | all items at once | one item at a time |
| Evaluation | eager, now | lazy, on iteration |
| Reusable | yes, iterate many times | no, **single pass** |
| `len`, indexing | yes | no |
| Short-circuit with `any`/`all`/`next` | builds everything first | stops early |
| Speed per item | slightly faster | slightly slower (generator resume overhead) |

Use a generator expression when you consume the values **once**, immediately, especially feeding a reducer (`sum`, `max`, `any`, `all`, `"".join`, `dict(...)`), or when the data is large or infinite (streaming lines from a big file). Use a list when you need to iterate more than once, index, or know the length.

The single-pass trap:

```python
g = (n for n in range(3))
print(list(g), list(g))
print(any(n > 2 for n in [1, 5, 2]), max(len(w) for w in ["a", "abc"]))
```

```text title="Output"
[0, 1, 2] []
True 3
```

The second `list(g)` is empty, with no error. Passing a generator to a function that iterates it twice (for example to validate, then to process) is a classic silent bug.

### Lazy body, eager first iterable

A generator expression evaluates its **first** (outermost) iterable immediately, when the generator is created. Everything else runs lazily:

```python
lst = [1, 2, 3]
g = (x for x in lst)
lst = [100]              # rebinding the name does not affect g
print(list(g))

try:
    g2 = (x for x in 1/0)
except ZeroDivisionError:
    print("first iterable evaluated eagerly")

g3 = (1/0 for x in range(3))
print("body is lazy")
```

```text title="Output"
[1, 2, 3]
first iterable evaluated eagerly
body is lazy
```

This makes errors in the source show up where you create the generator, not later at a confusing location.

## Comprehension scope rules

A comprehension has **its own scope**. The loop variable does not leak into the surrounding code:

```python
x = "outer"
squares = [x for x in range(3)]
print(x)
```

```text title="Output"
outer
```

(In Python 2 list comprehensions did leak; generator expressions never did.) The PEP 709 inlining in 3.12 is an implementation optimization: it keeps this isolation behaviour.

Two exceptions to know:

**1. The walrus operator binds in the enclosing scope**, on purpose, so you can keep a value computed inside:

```python
total = 0
data = [5, 15, 25]
running = [total := total + d for d in data]
print(running, total)
```

```text title="Output"
[5, 20, 45] 45
```

**2. Class bodies are not visible from inside comprehensions** (except the first iterable). A class body is not an enclosing function scope, so names defined there cannot be seen from the comprehension's scope:

```python
class Config:
    factor = 10
    try:
        scaled = [n * factor for n in range(3)]
    except NameError as e:
        err = str(e)
print(Config.err)
```

```text title="Output"
name 'factor' is not defined
```

Workarounds: compute the value outside the class, use a regular loop, or put the class attribute in the **first** iterable (`[n * f for f in [factor] for n in range(3)]`), which is evaluated in the class scope.

### Late binding of closures in comprehensions

Lambdas created in a comprehension capture the **variable**, not its value at that moment:

```python
fns = [lambda: i for i in range(3)]
print([f() for f in fns])
fns = [lambda i=i: i for i in range(3)]
print([f() for f in fns])
```

```text title="Output"
[2, 2, 2]
[0, 1, 2]
```

All three lambdas look up `i` when called, after the loop has finished, so they all see 2. The `i=i` default argument captures the current value at definition time. Closures and late binding are covered in depth in the scope page.

<Callout title="Coming from JS">
This is the same bug as `var` in a JS `for` loop with callbacks. JS fixed it with `let`, which creates a new binding per iteration. Python has no per-iteration binding, so you use the default-argument trick or `functools.partial`.
</Callout>

## Modifying a collection while iterating

### Lists: silent wrong results

```python
nums = [1, 2, 2, 3, 4, 4, 5]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)
```

```text title="Output"
[1, 2, 3, 4, 5]
```

The even numbers were not all removed, and there is **no error**. Why: the list iterator just keeps an integer index. When you remove the element at index 1, everything shifts left, the second `2` moves into index 1, and the iterator moves on to index 2, skipping it.

<Mermaid chart={`flowchart TB
  A["index 1 points at 2<br/>list: 1 2 2 3 4 4 5"] -->|"remove(2)"| B["list: 1 2 3 4 4 5<br/>second 2 shifted into index 1"]
  B -->|"iterator moves to index 2"| C["now looking at 3<br/>the second 2 was skipped"]`} />

Correct approaches:

```python
nums = [1, 2, 2, 3, 4, 4, 5]
nums = [n for n in nums if n % 2 != 0]          # build a new list (preferred)
print(nums)

nums = [1, 2, 2, 3, 4, 4, 5]
alias = nums
nums[:] = [n for n in nums if n % 2 != 0]       # replace contents in place, aliases see it
print(alias)

nums = [1, 2, 2, 3, 4, 4, 5]
for i in range(len(nums) - 1, -1, -1):          # delete by index, iterating backwards
    if nums[i] % 2 == 0:
        del nums[i]
print(nums)

nums = [1, 2, 3]
for n in nums.copy():                           # iterate over a snapshot
    if n == 2: nums.remove(n)
print(nums)
```

```text title="Output"
[1, 3, 5]
[1, 3, 5]
[1, 3, 5]
[1, 3]
```

Appending while iterating is also allowed for lists and makes the loop also visit the new items (which can loop forever):

```python
items = [1, 2, 3]
for x in items:
    if len(items) < 6:
        items.append(x * 10)
print(items)
```

```text title="Output"
[1, 2, 3, 10, 20, 30]
```

### Dicts and sets: an error

Dicts and sets detect size changes during iteration and raise:

```python
d = {"a": 1, "b": 2, "c": 3}
try:
    for k in d:
        if d[k] == 2:
            del d[k]
except RuntimeError as e:
    print("RuntimeError:", e)

d = {"a": 1, "b": 2, "c": 3}
for k in list(d):              # iterate over a snapshot of the keys
    if d[k] == 2:
        del d[k]
print(d)

d = {"a": 1, "b": 2}
for k in d:                    # changing values (not keys) is fine
    d[k] = d[k] * 10
print(d)

s = {1, 2, 3}
try:
    for x in s:
        s.add(x + 10)
except RuntimeError as e:
    print("RuntimeError:", e)
```

```text title="Output"
RuntimeError: dictionary changed size during iteration
{'a': 1, 'c': 3}
{'a': 10, 'b': 20}
RuntimeError: Set changed size during iteration
```

Usually the cleanest fix is a comprehension: `d = {k: v for k, v in d.items() if v != 2}`.

<Callout title="Coming from JS">
Mutating an array during `for...of` in JS has the same index-shifting problem, and `Map` / `Set` iteration in JS tolerates changes (deleted entries are skipped, added entries are visited). Python dicts and sets are stricter and raise `RuntimeError`, while lists behave like JS arrays and silently misbehave.
</Callout>

## Interview questions

**How does a `for` loop work in Python?**
**It calls `iter()` on the iterable to get an iterator, then repeatedly calls `next()` and binds the result to the loop variable until `StopIteration` is raised. Any object implementing `__iter__` works.**

**When does the `else` block of a loop run?**
**When the loop finishes without `break` (normal exhaustion, including zero iterations). `break`, `return` or an exception skip it. It is useful for search loops.**

**What is the difference between a list comprehension and a generator expression?**
**A list comprehension eagerly builds the full list in memory. A generator expression is lazy, yields one item at a time with constant memory, and can only be iterated once.**

**Does a comprehension's loop variable leak into the enclosing scope?**
**No, comprehensions have their own scope in Python 3. The exception is the walrus operator, which deliberately binds in the enclosing scope.**

**Why is `zip(..., strict=True)` useful?**
**Plain `zip` silently stops at the shortest input; `strict=True` (3.10+) raises `ValueError` if lengths differ, catching data misalignment bugs.**

**What happens if you remove items from a list while iterating over it?**
**Items get skipped silently, because the iterator advances by index while the list shifts left. Build a new list with a comprehension, assign to `lst[:]`, or iterate over a copy. Dicts and sets raise `RuntimeError` instead.**

**Why is `range(10**9)` cheap?**
**`range` is a lazy sequence storing only start, stop and step. Length, indexing and membership are computed arithmetically.**

**Why does `[lambda: i for i in range(3)]` give functions that all return 2?**
**Closures capture the variable, not its value; by the time they are called, `i` is 2. Bind the value with a default argument `lambda i=i: i`.**

## Recap

- `for` is for-each over any iterable via `iter()` and `next()`; there is no C-style loop. Use `range`, `enumerate` and `zip(strict=True)` instead of manual indices.
- `while` handles unknown iteration counts; `while True` plus `break` replaces do-while. No labelled break exists.
- Loop `else` runs only if the loop was not broken out of.
- Comprehensions build lists, dicts and sets concisely and quickly; keep them to one or two clauses. 3.15 adds unpacking inside them.
- Generator expressions are lazy and memory-flat but single-pass; their first iterable is evaluated eagerly.
- Comprehensions have their own scope (walrus excepted) and cannot see class-body names.
- Never remove items from a list you are iterating; build a new one. Dicts and sets raise if their size changes mid-loop.
