These questions cover the ground every Python interview starts on. Most of them look simple and hide one mechanism you are expected to name: names point at objects, some objects can change and some cannot, and CPython caches a few of them. All outputs below come from CPython 3.14.

## Names, objects and identity

### 1. What actually happens when you write `b = a`? **Easy**

**Short answer:** No copy is made. Assignment binds the name `b` to the same object that `a` already points to, so both names now refer to one object.

In Python, variables are names in a namespace (a dict-like table) that hold references to objects. Every object has an identity (`id`), a type and a value. Assignment never copies the value; it only adds another reference and bumps the object's reference count. Whether this matters depends on whether the object can change.

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)
print(a is b, id(a) == id(b))

x = 10
y = x
y += 1          # ints are immutable: this rebinds y to a new object
print(x, y)
```

```text title="Output"
[1, 2, 3, 4]
True True
10 11
```

**Likely follow-up:** "So how do I get an independent copy?" Use `a.copy()`, `list(a)` or `a[:]` for a shallow copy and `copy.deepcopy(a)` when the list contains other mutable objects. See [copying, mutability and identity](/docs/python/copying-mutability-and-identity).

<Callout type="info" title="Coming from JS">
  This is exactly how JS treats objects and arrays. The difference is that in Python *everything* is an object, including ints and strings, but since those are immutable you never notice the sharing.
</Callout>

More in [names, objects and the object model](/docs/python/names-objects-and-the-object-model).

### 2. Is Python pass-by-value or pass-by-reference? **Medium**

**Short answer:** Neither. It is "pass by object reference" (also called call by sharing): the function gets a new local name bound to the same object. Mutating the object is visible to the caller; rebinding the parameter is not.

When you call `f(x)`, CPython pushes a reference to the object onto the stack and the callee binds it to its parameter name in its own local scope. There is no copy, which rules out pass-by-value. But assigning to the parameter only changes the callee's local name, which rules out true pass-by-reference (there is no way to make the caller's variable point somewhere else, unlike C++ `&` parameters).

```python
def mutate(items):
    items.append("added")

def rebind(items):
    items = ["new list"]

data = ["original"]
mutate(data)
print(data)
rebind(data)
print(data)
```

```text title="Output"
['original', 'added']
['original', 'added']
```

**Likely follow-up:** "How would you let a function 'replace' the caller's value?" Return the new value and let the caller reassign it: `data = rebuild(data)`. That is the idiomatic way, and it keeps functions free of hidden side effects.

<Callout type="info" title="Coming from JS">
  Identical semantics to JS: objects are passed as shared references, and reassigning a parameter inside the function never affects the caller.
</Callout>

See [functions and arguments](/docs/python/functions-and-arguments).

### 3. Which built-in types are mutable and which are immutable, and why does it matter? **Easy**

**Short answer:** Immutable: `int`, `float`, `complex`, `bool`, `str`, `bytes`, `tuple`, `frozenset`, `None`. Mutable: `list`, `dict`, `set`, `bytearray` and most user-defined objects. It matters for sharing, hashing (only immutable values are safe dict keys) and default arguments.

An immutable object cannot change after creation; any "modification" builds a new object and rebinds the name. You can see it with `id`: `+=` on a list keeps the same object (it calls `__iadd__` and extends in place), while `+=` on a tuple or string produces a new one.

```python
nums = [1, 2]
before = id(nums)
nums += [3]
print(id(nums) == before)

t = (1, 2)
before = id(t)
t += (3,)
print(id(t) == before)

s = "hi"
try:
    s[0] = "H"
except TypeError as e:
    print("TypeError:", e)
```

```text title="Output"
True
False
TypeError: 'str' object does not support item assignment
```

**Likely follow-up:** "Is a tuple always immutable?" The tuple itself is, but it can hold mutable objects. `(1, [2])` cannot be a dict key because hashing a tuple hashes its items and the list is unhashable. See question 9 of [data structures and functions](/docs/python/interview-questions/data-structures-and-functions) for the famous `t[1] += [3]` trap.

### 4. What is the difference between `is` and `==`? **Easy**

**Short answer:** `==` compares values by calling `__eq__`; `is` compares identity, meaning "are these the same object in memory". Use `is` only for singletons such as `None`, `True`, `False` and sentinel objects.

`a is b` is a pointer comparison in CPython and cannot be overridden. `a == b` calls `type(a).__eq__(a, b)`, which a class can define however it likes (and falls back to identity if it doesn't define it).

```python
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b, a is b)

class AlwaysEqual:
    def __eq__(self, other):
        return True

x = AlwaysEqual()
print(x == None, x is None)
```

```text title="Output"
True False
True False
```

**Likely follow-up:** "Why does PEP 8 say `if x is None` rather than `if x == None`?" Because `==` can be overridden (as above, or by NumPy arrays returning element-wise results), while `is None` is always correct and slightly faster.

<Callout type="info" title="Coming from JS">
  `is` is roughly `Object.is`/`===` on references, and `==` is closer to a deep-equality method you control. Python's `==` never does type coercion like JS's loose `==`: `1 == "1"` is simply `False`.
</Callout>

### 5. Why can `a is b` be `True` for `256` but `False` for `257`? **Medium**

**Short answer:** CPython pre-allocates the integers from -5 to 256 and reuses those objects, so any expression producing one of them returns the cached object. Larger ints are created fresh, so two equal values are usually different objects. This is a CPython implementation detail; never rely on it.

The small-int cache lives in the interpreter state. There is an extra twist: the compiler merges equal constants within one code object, so `a = 257; b = 257` written in the same script or function can still be the same object. To see the real runtime behaviour, build the ints at runtime.

```python
a = int("256")
b = int("256")
print(a is b)

c = int("257")
d = int("257")
print(c is d)

e = 257
f = 257
print(e is f)   # same code object: the compiler shares one constant
```

```text title="Output"
True
False
True
```

**Likely follow-up:** "So the REPL and a script can disagree?" Yes. In the interactive REPL each line is compiled separately, so `e = 257` and `f = 257` on separate lines give `False`, while the same lines in a file give `True`. The lesson is the same either way: compare numbers with `==`.

More in [CPython memory management](/docs/python/cpython-memory-management).

### 6. What is string interning, and when are two equal strings the same object? **Medium**

**Short answer:** Interning stores one shared copy of a string so equal strings can be compared by pointer. CPython automatically interns identifiers and short compile-time string constants that look like identifiers; strings built at runtime are not interned unless you call `sys.intern`.

CPython uses interning internally for attribute names, variable names and dict keys of modules and classes, which makes attribute lookup fast. Constants that consist only of letters, digits and underscores are interned when code is compiled; strings created by concatenation, `join`, input or decoding usually are not.

```python
import sys

a = "hello_world"
b = "hello_world"
print(a is b)

c = "".join(["hello", "_", "world"])
print(a == c, a is c)

d = sys.intern(c)
print(a is d)
```

```text title="Output"
True
True False
True
```

**Likely follow-up:** "When would you call `sys.intern` yourself?" When you hold millions of repeated strings (for example, keys parsed from a big log or CSV file) and want to save memory and speed up dict lookups. In everyday code you never need it, and you should still compare with `==`.

### 7. Why does `id([]) == id([])` print `True`? **Hard**

**Short answer:** The first empty list is created, its `id` is taken, and it is freed immediately because nothing references it. The second list is then allocated in the same freed memory slot, so it gets the same address. Two objects can share an `id` if their lifetimes do not overlap.

In CPython `id(obj)` is the object's memory address, and reference counting frees an object the moment its count drops to zero. The allocator (pymalloc) reuses the most recently freed block of the same size class, so the second temporary list lands exactly where the first one was.

```python
print(id([]) == id([]))

a = []
b = []
print(id(a) == id(b))   # both alive at once: must differ
```

```text title="Output"
True
False
```

**Likely follow-up:** "Is `id` guaranteed to be an address?" No. The language only promises that `id` is unique and constant for an object *during its lifetime*. It is an address in CPython, but PyPy, for example, computes it differently. Never store ids of objects you don't keep alive. See [CPython memory management](/docs/python/cpython-memory-management).

## Numbers

### 8. Why do Python integers never overflow, and what does `-7 // 2` return? **Easy**

**Short answer:** `int` is arbitrary precision: CPython stores it as an array of 30-bit "digits" that grows as needed, so it is limited only by memory. `-7 // 2` is `-4`, because `//` is floor division (it rounds toward negative infinity), and `%` takes the sign of the divisor.

The rule `a == (a // b) * b + a % b` always holds. Since floor division rounds down, the remainder has the same sign as `b`. This differs from C, Java and JS, which truncate toward zero.

```python
import sys

big = 2 ** 100
print(big)
print(sys.getsizeof(1), sys.getsizeof(big))
print(-7 // 2, -7 % 2)
print(7 // -2, 7 % -2)
print(int(-7 / 2))   # truncation, like JS Math.trunc
```

```text title="Output"
1267650600228229401496703205376
28 40
-4 1
-4 -1
-3
```

**Likely follow-up:** "Is there any limit at all?" Converting huge ints to and from decimal strings is capped at 4300 digits by default (since 3.11) to block a denial-of-service attack where quadratic `int(str)` parsing is triggered by untrusted input. You can raise it with `sys.set_int_max_str_digits`. Arithmetic itself has no limit.

<Callout type="info" title="Coming from JS">
  JS `number` is a 64-bit float, safe only up to `2 ** 53 - 1`; beyond that you need `BigInt`. Python's `int` behaves like `BigInt` all the time. Also, `-7 % 2` is `-1` in JS but `1` in Python.
</Callout>

See [numbers and operators](/docs/python/numbers-and-operators).

### 9. Why is `0.1 + 0.2 == 0.3` `False`, and what do you use for money? **Easy**

**Short answer:** `float` is an IEEE 754 double, so `0.1` and `0.2` are stored as the nearest binary fractions and their sum is slightly off. Compare floats with `math.isclose`, and use `decimal.Decimal` (built from strings) or integer cents for money.

`Decimal` does base-10 arithmetic with configurable precision and rounding modes, which is why it is the standard for financial code. `fractions.Fraction` gives exact rational arithmetic when you need it.

```python
import math
from decimal import Decimal
from fractions import Fraction

print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3, math.isclose(0.1 + 0.2, 0.3))
print(Decimal("0.1") + Decimal("0.2"))
print(Decimal(0.1))          # built from a float: inherits the error
print(Fraction(1, 10) + Fraction(2, 10))
```

```text title="Output"
0.30000000000000004
False True
0.3
0.1000000000000000055511151231257827021181583404541015625
3/10
```

**Likely follow-up:** "Why `Decimal("0.1")` and not `Decimal(0.1)`?" Because the float literal is already inexact before `Decimal` sees it. Always build decimals from strings or ints. Pydantic and most ORMs map a `Decimal` field to a SQL `NUMERIC` column for this reason.

<Callout type="info" title="Coming from JS">
  Same IEEE 754 doubles as JS, so the same `0.30000000000000004`. The difference is that Python ships `Decimal` and `Fraction` in the standard library, so you don't need a package like `decimal.js`.
</Callout>

### 10. Why does `{1: "a", True: "b"}` have only one key? **Medium**

**Short answer:** `bool` is a subclass of `int`, and `True == 1` with `hash(True) == hash(1)`. A dict sees them as the same key, so the second assignment overwrites the value but keeps the original key object `1`.

`True` and `False` are the two instances of `bool`, which inherits from `int` with values 1 and 0. That is why `True + True` is `2` and `sum(flags)` counts the true values. When a dict gets an equal key, it updates the value and leaves the existing key in place.

```python
print(isinstance(True, int), True + True)
print(sum([True, False, True, True]))

d = {1: "a", True: "b", 1.0: "c"}
print(d)
print(len({0, False, 0.0}))
```

```text title="Output"
True 2
3
{1: 'c'}
1
```

**Likely follow-up:** "Where does this bite in real code?" JSON-like data where both `1` and `True` appear as keys or set members, and validation libraries: a Pydantic `int` field accepts `True` in lax mode unless you use `StrictInt`.

### 11. What does `round(2.5)` return? **Easy**

**Short answer:** `2`. Python's `round` uses "round half to even" (banker's rounding), so `.5` cases go to the nearest even number: `round(2.5)` is `2` and `round(3.5)` is `4`. On top of that, many decimal values are not exactly representable, so `round(2.675, 2)` gives `2.67`.

Round-half-even avoids the upward bias you get when you always round `.5` up, which matters when summing many rounded values. If you need "round half up" (for invoices, say), use `Decimal.quantize` with `ROUND_HALF_UP`.

```python
from decimal import Decimal, ROUND_HALF_UP

print(round(0.5), round(1.5), round(2.5), round(3.5))
print(round(2.675, 2))
print(Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
```

```text title="Output"
0 2 2 4
2.67
2.68
```

**Likely follow-up:** "Why `2.67` and not `2.68`?" The float `2.675` is actually stored as `2.67499999...`, so it is below the halfway point before rounding even starts.

<Callout type="info" title="Coming from JS">
  `Math.round(2.5)` is `3` in JS (half rounds toward positive infinity). Porting price logic from Node to Python without noticing this is a classic off-by-one-cent bug.
</Callout>

## Strings

### 12. What is the difference between `str` and `bytes`, and what is `len("😀")`? **Medium**

**Short answer:** `str` is a sequence of Unicode code points; `bytes` is a sequence of raw 8-bit values. You convert with `.encode()` and `.decode()`, and the encoding (almost always UTF-8) is explicit. `len("😀")` is `1` because `len` counts code points, not bytes or UTF-16 units.

Internally CPython (PEP 393) stores each string in the narrowest fixed width that fits its largest character: 1, 2 or 4 bytes per code point. That keeps indexing O(1). Text from the network or files arrives as bytes and must be decoded at the boundary.

```python
s = "café 😀"
print(len(s))
b = s.encode("utf-8")
print(b)
print(len(b))
print(b.decode("utf-8") == s)
try:
    "abc" + b"def"
except TypeError as e:
    print("TypeError:", e)
```

```text title="Output"
6
b'caf\xc3\xa9 \xf0\x9f\x98\x80'
10
True
TypeError: can only concatenate str (not "bytes") to str
```

**Likely follow-up:** "Can two strings that look identical compare unequal?" Yes: `"é"` can be one code point (U+00E9) or `e` plus a combining accent (U+0301). Normalise with `unicodedata.normalize("NFC", s)` before comparing user input.

<Callout type="info" title="Coming from JS">
  JS strings are UTF-16, so `"😀".length` is `2` and indexing can split a surrogate pair. Python has no such problem. Python also refuses to mix text and bytes implicitly, where Node's `Buffer` often converts silently.
</Callout>

See [strings and bytes](/docs/python/strings-and-bytes).

### 13. Why is building a string with `+=` in a loop considered bad, and what do you use instead? **Easy**

**Short answer:** Strings are immutable, so each `+=` can create a new string and copy everything so far, which is O(n²) in the worst case. Collect pieces in a list and call `"".join(pieces)` once, or use an f-string for small fixed formats.

CPython has an optimisation that resizes the string in place when the left-hand string has only one reference, so a simple loop is often fast in practice. But it is fragile (any second reference disables it) and other implementations don't have it, so `join` is the reliable idiom.

```python
parts = []
for i in range(5):
    parts.append(f"item{i}")
print(", ".join(parts))

user, n = "ada", 3
print(f"{user!r} has {n} item{'s' if n != 1 else ''}")
print(f"{n * 2 = }")
```

```text title="Output"
item0, item1, item2, item3, item4
'ada' has 3 items
n * 2 = 6
```

**Likely follow-up:** "What's new with string formatting?" Python 3.14 added template strings (`t"..."`, PEP 750), which evaluate to a `Template` object instead of a `str`, so a library can escape the interpolated values (for SQL or HTML) before combining them.

<Callout type="info" title="Coming from JS">
  f-strings are template literals. The `t"..."` strings are closer to JS tagged templates: the parts and values are kept separate for a processing function.
</Callout>

## Truthiness and operators

### 14. Which values are falsy in Python, and how does Python decide truthiness for your own classes? **Easy**

**Short answer:** Falsy: `None`, `False`, zero of any numeric type, and empty containers (`""`, `b""`, `[]`, `()`, `{}`, `set()`, `range(0)`). Everything else is truthy. For a custom object, `bool()` calls `__bool__`, falls back to `__len__`, and is `True` if neither exists.

```python
values = [None, 0, 0.0, "", [], {}, set(), range(0), "0", [0], " "]
print([bool(v) for v in values])

class Basket:
    def __init__(self, items):
        self.items = items
    def __len__(self):
        return len(self.items)

print(bool(Basket([])), bool(Basket(["apple"])))
```

```text title="Output"
[False, False, False, False, False, False, False, False, True, True, True]
False True
```

**Likely follow-up:** "When should you *not* write `if not x:`?" When `0`, `""` or an empty list are valid values distinct from "missing". Write `if x is None:` for optional parameters, otherwise a caller passing `0` takes the "missing" branch.

<Callout type="info" title="Coming from JS">
  The big difference: empty arrays and objects are *truthy* in JS but empty lists and dicts are *falsy* in Python. And `"0"` is truthy in both.
</Callout>

See [control flow and match](/docs/python/control-flow-and-match).

### 15. What do `and` and `or` return? **Medium**

**Short answer:** They return one of their operands, not necessarily a `bool`. `a or b` returns `a` if it is truthy, else `b`; `a and b` returns `a` if it is falsy, else `b`. Both short-circuit.

```python
print(0 or "default")
print("value" or "default")
print([] and "never evaluated")
print(3 and 4)

def get_port(port=None):
    return port or 8000     # bug: port=0 is replaced

def get_port_fixed(port=None):
    return port if port is not None else 8000

print(get_port(0))
print(get_port_fixed(0))
```

```text title="Output"
default
value
[]
4
8000
0
```

**Likely follow-up:** "Does Python have `??`?" No null-coalescing operator exists (PEP 505 was deferred). Write `x if x is not None else default`. Use `or` only when every falsy value really should be replaced.

<Callout type="info" title="Coming from JS">
  `or` is JS `||` and `and` is `&&`, with the same "returns an operand" behaviour. Python has no `??` and no `?.`.
</Callout>

### 16. What does `False == False in [False]` evaluate to? **Medium**

**Short answer:** `True`. Comparison operators chain, so it means `(False == False) and (False in [False])`, and both parts are true. `in`, `not in`, `is` and `is not` count as comparison operators for chaining.

Chaining is why `0 < x < 10` works as in maths, with `x` evaluated only once. The same rule produces surprising results when you mix `==` with `in` or `is`.

```python
x = 5
print(0 < x < 10)
print(False == False in [False])
print((False == False) in [False])
print(1 < 3 > 2)
```

```text title="Output"
True
True
False
True
```

**Likely follow-up:** "How would JS evaluate `1 < 2 < 3` and `3 > 2 > 1`?" Left to right with coercion: `3 > 2 > 1` becomes `true > 1`, then `1 > 1`, which is `false`. In Python it is `True`.

## Control flow and comprehensions

### 17. How does `match` work, and why does `case NOT_FOUND:` match everything? **Medium**

**Short answer:** `match` is structural pattern matching: it checks the subject against patterns that can destructure sequences, mappings and class instances and bind names. A bare name in a pattern is a *capture* pattern that always matches and binds, so to compare against a constant you need a dotted name (like `Status.NOT_FOUND`) or a literal.

Patterns are tried top to bottom. Sequence patterns check length and items, mapping patterns check that keys exist (extra keys are allowed), class patterns call `isinstance` and then match attributes (positional ones use `__match_args__`). Guards with `if` add arbitrary conditions.

```python
from enum import IntEnum

class Status(IntEnum):
    OK = 200
    NOT_FOUND = 404

def describe(event):
    match event:
        case {"type": "click", "pos": (x, y)}:
            return f"click at {x},{y}"
        case {"type": "key", "key": str(k)} if len(k) == 1:
            return f"key {k}"
        case [first, *rest]:
            return f"batch of {1 + len(rest)} starting with {first}"
        case Status.NOT_FOUND:
            return "not found"
        case _:
            return "unknown"

print(describe({"type": "click", "pos": (3, 4), "extra": 1}))
print(describe({"type": "key", "key": "q"}))
print(describe([10, 20, 30]))
print(describe(404))
print(describe("hello"))
```

```text title="Output"
click at 3,4
key q
batch of 3 starting with 10
not found
unknown
```

Note the last line: a `str` does not match the sequence pattern `[first, *rest]`. `str`, `bytes` and `bytearray` are deliberately excluded from sequence patterns.

**Likely follow-up:** "What happens with `NOT_FOUND = 404` and `case NOT_FOUND:`?" The compiler rejects it if more cases follow (`SyntaxError: name capture 'NOT_FOUND' makes remaining patterns unreachable`), and if it is the last case it silently matches anything and rebinds `NOT_FOUND`.

<Callout type="info" title="Coming from JS">
  `match` is not `switch`: there is no fall-through and no `break`, and it destructures like JS destructuring with type checks built in. A closer analogy is the TC39 pattern matching proposal.
</Callout>

See [control flow and match](/docs/python/control-flow-and-match).

### 18. What is the difference between a list comprehension and a generator expression, and does the loop variable leak? **Medium**

**Short answer:** `[x for x in it]` builds the whole list eagerly; `(x for x in it)` returns a lazy generator that produces items on demand and can be consumed only once. Comprehension variables do not leak into the enclosing scope in Python 3, but a plain `for` loop variable does.

Since Python 3.12 (PEP 709), list, dict and set comprehensions are inlined into the enclosing function instead of creating a hidden function, which makes them faster, but their variables are still isolated. Generator expressions still use a separate frame because they run lazily.

```python
import sys

squares_list = [n * n for n in range(100_000)]
squares_gen = (n * n for n in range(100_000))
print(sys.getsizeof(squares_list) > 100_000, sys.getsizeof(squares_gen) < 500)
print(sum(squares_gen), sum(squares_gen))   # second pass: already exhausted

for i in range(3):
    pass
print("loop var:", i)

[j for j in range(3)]
print("j" in globals())
```

```text title="Output"
True True
333328333350000 0
loop var: 2
False
```

**Likely follow-up:** "When do you pick which?" Use a list when you need to index, iterate several times or know the size; use a generator expression for single-pass pipelines like `sum(x.price for x in orders)` or streaming large files, where memory stays constant.

See [loops and comprehensions](/docs/python/loops-and-comprehensions).

### 19. What is `range`, and why is `10**9 in range(10**12)` instant? **Easy**

**Short answer:** `range` is a lazy, immutable sequence that stores only start, stop and step. It supports `len`, indexing, slicing and an O(1) `in` check for ints, computed arithmetically instead of by iterating.

```python
r = range(0, 20, 3)
print(r, list(r))
print(len(r), r[2], r[-1], r[1:3])
print(10**9 in range(10**12))
print(range(0, 10, 2) == range(0, 9, 2))
```

```text title="Output"
range(0, 20, 3) [0, 3, 6, 9, 12, 15, 18]
7 6 18 range(3, 9, 3)
True
True
```

**Likely follow-up:** "Why do the two different ranges compare equal?" Ranges compare as sequences: both produce `0, 2, 4, 6, 8`. Also note `in` is only O(1) for real `int` values; testing a float like `5.0` falls back to a linear scan.

<Callout type="info" title="Coming from JS">
  JS has no built-in range; people write `Array.from({ length: n }, (_, i) => i)`, which allocates the whole array. Python's `range` allocates nothing.
</Callout>

### 20. What does `else` on a `for` or `while` loop do? **Medium**

**Short answer:** The `else` block runs when the loop finishes normally, that is, without hitting `break`. It replaces the "found" flag you'd otherwise set when searching.

Think of it as "no break". It also runs when the loop body never executes (empty iterable). Combined with the walrus operator `:=` (assignment expression), search loops get compact.

```python
def find_admin(users):
    for user in users:
        if user["role"] == "admin":
            print("found", user["name"])
            break
    else:
        print("no admin")

find_admin([{"name": "ana", "role": "dev"}, {"name": "bo", "role": "admin"}])
find_admin([{"name": "ana", "role": "dev"}])
find_admin([])

lines = iter(["a", "b", ""])
while (line := next(lines)):
    print("read", line)
```

```text title="Output"
found bo
no admin
no admin
read a
read b
```

**Likely follow-up:** "Would you use it in production code?" It is idiomatic, but many teams prefer a helper like `next((u for u in users if u["role"] == "admin"), None)` because readers coming from other languages often misread `for`/`else`. Know both.
