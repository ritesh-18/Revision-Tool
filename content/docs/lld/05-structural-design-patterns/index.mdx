---
title: "5. Structural Design Patterns"
---

Creational patterns decide how objects are born. Structural patterns decide how objects are **wired together**: how you plug a vendor SDK into your interfaces, how you wrap a service with logging and retries without touching it, how you treat a folder and a file the same way, and how you hide ten services behind one method call. Most of them work by **wrapping** one object in another, which is why they are so easy to confuse. This chapter pays special attention to telling the wrappers apart.

**What you'll learn**

- Adapter: making a third-party API (payment gateway, market-data vendor) fit your interface
- Bridge: splitting two independent dimensions of variation so classes don't multiply
- Composite: treating a single item and a group of items uniformly (portfolios, file systems, org charts)
- Decorator: adding behaviour (logging, caching, retry) by wrapping, and how it relates to TypeScript's `@decorators`
- Facade: one simple entry point over a complex subsystem (order placement)
- Flyweight: sharing immutable data among thousands of objects (instrument metadata)
- Proxy: controlling access (caching, protection, lazy loading), including JavaScript's built-in `Proxy`
- A clear way to explain **Adapter vs Decorator vs Proxy vs Facade** in an interview

One rule of thumb before we start: **all four wrappers hold a reference to another object, and the difference is intent.** Adapter changes the interface. Decorator keeps the interface and adds behaviour. Proxy keeps the interface and controls access. Facade offers a new, simpler interface over many objects.
