## Intent

Share the common, immutable part of many similar objects so you store it once, and keep only the varying part in each object.

## Problem

A market-data screen processes 100,000 ticks a second across 5,000 instruments. Each tick object needs the instrument's static details (symbol, ISIN, exchange, lot size, tick size, company name, sector). Copying those 7 fields into every tick wastes memory and GC time. The details are the same for every INFY tick. Flyweight splits the state:

- **Intrinsic** (shared, immutable): instrument metadata.
- **Extrinsic** (per object, passed in or stored beside): price, quantity, timestamp.

Chess is the classic teaching version: 32 pieces on the board, but only 12 distinct (colour, type) combinations; the square is extrinsic.

## TypeScript implementation

```ts
// ----- Flyweight: intrinsic, immutable, shared -----
class InstrumentMeta {
  constructor(
    readonly symbol: string,
    readonly isin: string,
    readonly exchange: string,
    readonly lotSize: number,
    readonly tickSize: number,
    readonly sector: string,
  ) {
    Object.freeze(this); // sharing is only safe if nobody can mutate it
  }

  // Behaviour that needs extrinsic state takes it as a parameter.
  roundToTick(price: number): number {
    const ticks = Math.round(price / this.tickSize);
    return +(ticks * this.tickSize).toFixed(2);
  }
}

// ----- Flyweight factory -----
class InstrumentRegistry {
  private readonly cache = new Map<string, InstrumentMeta>();
  private readonly master: Record<string, ConstructorParameters<typeof InstrumentMeta>> = {
    INFY: ['INFY', 'INE009A01021', 'NSE', 1, 0.05, 'IT'],
    TCS: ['TCS', 'INE467B01029', 'NSE', 1, 0.05, 'IT'],
    NIFTY24SEPFUT: ['NIFTY24SEPFUT', '-', 'NFO', 25, 0.05, 'INDEX'],
  };
  lookups = 0;

  get(symbol: string): InstrumentMeta {
    let meta = this.cache.get(symbol);
    if (!meta) {
      const row = this.master[symbol];
      if (!row) throw new Error(`unknown instrument ${symbol}`);
      this.lookups++; // imagine a DB / file lookup here
      meta = new InstrumentMeta(...row);
      this.cache.set(symbol, meta);
    }
    return meta;
  }

  size(): number {
    return this.cache.size;
  }
}

// ----- Context objects: extrinsic state + reference to the flyweight -----
interface Tick {
  readonly meta: InstrumentMeta;
  readonly price: number;
  readonly qty: number;
  readonly seq: number;
}

const registry = new InstrumentRegistry();
const symbols = ['INFY', 'TCS', 'NIFTY24SEPFUT'];
const ticks: Tick[] = [];

for (let seq = 0; seq < 30_000; seq++) {
  const symbol = symbols[seq % symbols.length];
  // deterministic fake prices
  const base = symbol === 'INFY' ? 1500 : symbol === 'TCS' ? 4100 : 25000;
  ticks.push({ meta: registry.get(symbol), price: base + (seq % 7) * 0.03, qty: (seq % 5) + 1, seq });
}

console.log(`ticks=${ticks.length} flyweights=${registry.size()} masterLookups=${registry.lookups}`);
console.log(`shared object: ${ticks[0].meta === ticks[3].meta}`);

const t = ticks[5]; // NIFTY future, seq 5
console.log(
  `${t.meta.symbol} raw=${t.price.toFixed(2)} tick-rounded=${t.meta.roundToTick(t.price)} ` +
    `lots=${t.qty} units=${t.qty * t.meta.lotSize}`,
);

try {
  (t.meta as { lotSize: number }).lotSize = 50;
} catch (err) {
  console.log(`mutation blocked: ${(err as Error).constructor.name}`);
}
```

30,000 ticks share three metadata objects. Without the flyweight, each tick would carry its own copy of six fields: roughly 30,000 extra objects.

**Chess sketch.** The same idea in the classic example, type-checked:

```ts
type Color = 'white' | 'black';
type Kind = 'K' | 'Q' | 'R' | 'B' | 'N' | 'P';

class PieceType {
  constructor(
    readonly color: Color,
    readonly kind: Kind,
  ) {}
  glyph(): string {
    return this.color === 'white' ? this.kind : this.kind.toLowerCase();
  }
}

class PieceFactory {
  private static readonly pool = new Map<string, PieceType>();
  static get(color: Color, kind: Kind): PieceType {
    const key = `${color}-${kind}`;
    let p = PieceFactory.pool.get(key);
    if (!p) PieceFactory.pool.set(key, (p = new PieceType(color, kind)));
    return p; // at most 12 instances, ever
  }
}

// Extrinsic state (square) lives in the board, not in the piece.
export const board = new Map<string, PieceType>([
  ['e1', PieceFactory.get('white', 'K')],
  ['a2', PieceFactory.get('white', 'P')],
  ['b2', PieceFactory.get('white', 'P')],
]);
```

## When to use / when NOT to use

- **Use** when you have a *very large* number of objects, a large share of their state is identical and immutable, and memory or GC pressure is a measured problem: ticks, map tiles, text glyphs in an editor, game sprites, particles.
- **Don't use** for a few hundred objects. JS engines already share string contents and hidden classes; the added complexity isn't worth it without measurement.

## Pitfalls

- **Mutable flyweights**: one mutation changes every tick of that instrument. Freeze them.
- **Putting extrinsic state into the flyweight** (e.g. `lastPrice` on `InstrumentMeta`) silently breaks sharing and correctness.
- **Unbounded factory cache**: for a changing universe (options contracts expire every week), the registry grows forever. Evict, or use a `WeakRef`-based cache.
- **Identity assumptions**: code comparing by `===` works only if everyone goes through the factory.

## Related patterns

- **Singleton** shares exactly one instance; a flyweight factory shares *one instance per key*.
- **Object Pool** (Chapter 4) lends mutable objects exclusively; flyweights are immutable and used by many at once.
- **Composite** leaves are often flyweights (e.g. characters in a document tree).
- **Prototype** copies state; Flyweight deliberately avoids copying.

## Where it shows up in LLD interview problems

- Chess / board games (piece types).
- Text editor (character glyph/format objects).
- Trading: instrument master shared by ticks, orders and positions.
- Map / ride-sharing: shared icons and tile data; game design with thousands of trees or bullets.

Interview line: *"Symbol, lot size and tick size are identical for every tick of an instrument, so I keep one frozen `InstrumentMeta` per symbol in a registry and ticks store only price, qty and a reference."*

## Quick check

1. Classify for a movie-booking seat map: seat category + price tier, seat number, booked-by user. Which are intrinsic?
2. Why must a flyweight be immutable?

<details>
<summary>Answers</summary>

1. Category and price tier are intrinsic (shared by many seats). Seat number and booked-by are extrinsic (unique per seat or changing).
2. Because many contexts reference the same object; a change made for one of them would silently change all the others.
