## Chapter recap

- Structural patterns describe how objects are **composed**. Most of them wrap another object; tell them apart by **intent** and **interface**.
- **Adapter** translates a foreign interface (units, statuses, errors, push vs pull) into your domain's port. Never leak vendor types.
- **Bridge** turns an M × N class explosion into M + N by composing an abstraction with an implementor.
- **Composite** gives leaves and groups one interface, so aggregate operations are simple recursion. Watch for cycles and hot-path recomputation.
- **Decorator** stacks behaviours (logging, caching, retry) around an object with the same interface. Order matters; don't retry non-idempotent calls. TS `@decorators` are a related language feature, not the same thing.
- **Facade** offers one high-level call over a subsystem and owns the orchestration and compensation. Avoid god facades.
- **Flyweight** shares frozen intrinsic state across huge numbers of objects; extrinsic state is stored or passed separately.
- **Proxy** keeps the subject's interface and controls access: caching, protection, lazy loading, remote access. JS `Proxy` does this generically but magically.

## Interview questions on this chapter

**Q1. Explain the difference between Adapter, Decorator, Proxy and Facade.**

<details>
<summary>Answer</summary>

All wrap other objects. Adapter changes the interface of one object to the one clients expect. Decorator keeps the interface and adds behaviour, and decorators can be stacked in any order. Proxy keeps the interface and controls access to the subject (lazy creation, caching, permissions, remote calls), often owning the subject's lifecycle. Facade wraps many objects and exposes a new, simpler interface.

</details>

**Q2. You integrate Razorpay today and may add Stripe and PayU later. How would you design it?**

<details>
<summary>Answer</summary>

Define a domain `PaymentGateway` port (`createOrder`, `charge`, `refund`, `verifyWebhook`) with our own types (amounts in paise, our status enum, our error types). Implement one adapter per vendor that translates requests, responses, units and errors. Pick the adapter via a factory or config and inject it. Add cross-cutting behaviour (retry for idempotent calls, logging, metrics) as decorators around the port, not inside adapters. Webhook payloads get adapted into domain events too.

</details>

**Q3. How would you design a file system using Composite?**

<details>
<summary>Answer</summary>

A `FileSystemNode` interface with `name`, `size()`, `path()` and maybe `find(predicate)`. `File` is a leaf with its own size. `Directory` holds a `Map<string, FileSystemNode>` of children, implements `size()` by summing children, and has `add/remove/get` (safe design, only on directories). Operations like `ls`, `mkdir -p` and search are recursive or use an explicit stack. Guard against moving a directory into its own subtree, and cache sizes if they are read often.

</details>

**Q4. Why prefer Decorator over inheritance for adding logging and caching?**

<details>
<summary>Answer</summary>

Inheritance fixes the combination at compile time and multiplies classes (logging+caching, caching+retry, ...). Decorators are composed at runtime, each handles one concern (SRP), the core class stays untouched (OCP), and different instances can have different stacks. Inheritance also couples to the parent's internals.

</details>

**Q5. In a Decorator stack of cache, retry and logging, how does ordering change behaviour?**

<details>
<summary>Answer</summary>

Cache outermost: hits skip both logging and retries. Logging outside retry: one log line per logical call; inside retry: one per attempt (useful for debugging flaky upstreams). Retry outside cache: pointless for hits, and a cached failure would be retried against the cache. Choose the order deliberately and document it at the wiring site.

</details>

**Q6. What is the difference between Bridge and Strategy?**

<details>
<summary>Answer</summary>

Both use composition with an interface. Strategy lets a context swap one algorithm (pricing rule, sorting). Bridge separates two hierarchies that both evolve: the abstraction (alert kinds) has its own subclasses and delegates low-level work to the implementor hierarchy (channels). Bridge is a structural decision to avoid an M × N class explosion.

</details>

**Q7. What are intrinsic and extrinsic state in Flyweight? Give a trading example.**

<details>
<summary>Answer</summary>

Intrinsic state is shared, context-independent and immutable, stored in the flyweight: instrument symbol, ISIN, lot size, tick size, sector. Extrinsic state depends on context and is stored in the context object or passed to methods: last price, quantity, timestamp, order ID. Ticks hold a reference to the shared `InstrumentMeta` plus their own price and qty.

</details>

**Q8. Name three kinds of proxy and a use case for each.**

<details>
<summary>Answer</summary>

Virtual proxy: lazily creates an expensive object (report, image) on first real use. Protection proxy: checks permissions before delegating (account withdrawals). Caching/smart proxy: caches results of slow or remote calls (reference data). Also: remote proxy (a gRPC client stub that looks like a local service) and logging/metrics proxies.

</details>

**Q9. What is JavaScript's `Proxy` object and where is it used in real frameworks?**

<details>
<summary>Answer</summary>

A built-in that wraps any object and intercepts operations via traps (`get`, `set`, `has`, `deleteProperty`, `apply`, ...), usually forwarding to `Reflect`. Vue 3 and MobX use it for reactivity (tracking reads, triggering updates on writes), Immer uses it to record changes to drafts, and it is used for validation, read-only views and API client stubs. Downsides: hidden behaviour, weaker type safety, performance overhead, and problems with `#private` fields and identity.

</details>

**Q10. How is a Facade different from a "god class", and how do you keep it healthy?**

<details>
<summary>Answer</summary>

A facade orchestrates; the real work stays in focused subsystem classes. It becomes a god class when it absorbs business rules and grows methods for every use case. Keep it healthy by splitting per use case, injecting subsystems, keeping only workflow and compensation logic in it, and letting advanced clients still use subsystems directly.

</details>

**Q11. How would you add retries to an exchange order placement call safely?**

<details>
<summary>Answer</summary>

Only retry when the operation is idempotent. Generate a client order ID (idempotency key) before the first attempt and send it every time, so the exchange or OMS can deduplicate. Retry only on clearly transient errors (connection refused before send), and on timeouts query order status by client order ID before retrying. Implement this as a decorator or in the gateway adapter, with bounded attempts and backoff.

</details>

## Practice exercises

1. **File system Composite.** Implement `File`, `Directory` and a `FileSystem` facade with `mkdirP(path)`, `writeFile(path, size)`, `du(path)` and `find(pathPrefix, predicate)`. Prevent moving a directory into its own descendant.
2. **Market-data adapters.** Add a second vendor that delivers JSON batches (`{"s":"INFY","p":150025,"v":10}[]`) every 100 ms. Write an adapter for the same `MarketDataFeed` interface, and a test that both adapters deliver identical `Tick` objects for the same data.
3. **Decorator stack.** Add a `RateLimitDecorator` (max N calls per window, injected clock) and a `MetricsDecorator` (counts success/failure/latency buckets). Show two stacks with different orders and explain the difference in output.
4. **Bridge for reports.** Report kinds (`ContractNote`, `PnlStatement`, `LedgerStatement`) × formats (`CsvRenderer`, `HtmlRenderer`, `PlainTextRenderer`). Keep the renderer interface primitive (`heading`, `row`, `footer`).
5. **Facade with saga steps.** Extend `OrderPlacementFacade` with a basket order that places 3 orders; if any fails, cancel the already-placed ones and release all margin. Print the compensation steps.
6. **Pizza Decorator.** `Margherita` base (Rs.199) with `ExtraCheese` (+50), `Olives` (+30) and `Jalapeno` (+25) decorators that each append to `description()` and add to `cost()`. Then implement the same with a builder, and write two sentences on when you'd pick each.
7. **Generic caching `Proxy`.** Using the JS `Proxy` object, write `memoize<T extends object>(target: T): T` that caches results of any async method by method name + JSON of arguments, and never caches rejections.
