## Chapter recap

### Pattern crosswalk

| Problem | Primary pattern | Secondary patterns |
|---|---|---|
| 15.1 Typed Event Emitter | Observer (generics) | Copy-on-write for stable iteration |
| 15.2 Analytics SDK | Chain of Responsibility (pipeline) | Strategy (processors), Adapter (transport) |
| 15.3 Feature Flag Service | Strategy (rules) | Observer (subscriptions) |
| 15.4 File Explorer / Tree | Normalized state, Iterator | Command-style operations |
| 15.5 Redux-like Store | Observer + Reducer | Decorator (middleware), Memento (time travel) |
| 15.6 HTTP Client | Chain of Responsibility (interceptors) | Decorator, Strategy (transport/scheduler) |
| 15.7 Toast Queue | Priority Queue | Observer, State |
| 15.8 Autocomplete | Trie + LRU Cache | Observer, Decorator (debounce) |
| 15.9 Infinite Feed | State machine | Observer, Iterator (window) |

### Three rules that cover most of the scoring

**1. Start from the API.** Write `interface X { ... }` and a three-line usage example before you write any implementation. A wrong API is hard to fix later; a wrong implementation can be swapped.

**2. Keep time and I/O out of the core.** Anything that calls `Date.now()`, `setTimeout`, `fetch`, `localStorage`, or `Math.random` needs to be behind a tiny interface. One `Scheduler` interface is enough for all time concerns. One `Transport` type is enough for all network concerns. These seams are also what the interviewer tests when they say "how would you test this?"

**3. Every subscription returns an unsubscribe.** React's `useEffect` cleanup and `useSyncExternalStore` both depend on this contract. Forgetting it means re-render loops, stale-closure bugs, and memory leaks that only appear after ten route changes.

### Connecting to React

Every engine in this chapter exposes the same three-method shape:
```ts
interface ExternalStore<T> {
  getSnapshot(): T;
  subscribe(fn: () => void): () => void;
}
```

React 18's `useSyncExternalStore` consumes it directly:
```ts
// Illustrative — not a run block
import { useSyncExternalStore } from 'react';
function useStore<T>(store: ExternalStore<T>): T {
  return useSyncExternalStore(store.subscribe, store.getSnapshot);
}
```

The engine is unaware of React; the hook is unaware of the engine's internals. That separation is the design.

### API design checklist

Before finishing your interview answer, check:

- [ ] Is the public API minimal? (caller can do everything they need; can't reach internal state)
- [ ] Does every `subscribe` return an `unsubscribe`?
- [ ] Are time and I/O behind interfaces?
- [ ] Are all observable state changes synchronous and deterministic (no `Math.random`, no `Date.now` in output)?
- [ ] Does the class handle the "nothing here yet" case? (empty collection, `null` cursor, `idle` status)
- [ ] Are error cases typed? (`HttpError`, `TimeoutError`, `AbortError` by name — not just `throw new Error(msg)`)
- [ ] Is the interviewer's "how would you test this?" answerable in two sentences?

### Practice exercises

1. **Extend the Event Emitter** (15.1) with a `waitFor(event, signal?)` method that returns a Promise resolving to the next payload of that event, cancelled by the signal.

2. **Add offline batching to the Analytics SDK** (15.2): buffer events when `navigator.onLine` is false; flush on reconnect. The `PageLifecycle` dependency is already injected.

3. **Extend the Feature Flag Service** (15.3) with a `flagVariant(key, userId)` method that applies a percentage rollout rule: user is in the experiment if `hash(userId + key) % 100 < rolloutPct`. Use a deterministic hash (no `Math.random`).

4. **Add an undo/redo stack** to the File Explorer (15.4): each mutating operation (add, remove, move) should be reversible. Hint: the normalized state already supports snapshots.

5. **Add optimistic updates** to the Redux Store (15.5): `dispatchOptimistic(action, rollbackAction)` applies `action` immediately, then calls an async thunk; if the thunk rejects, applies `rollbackAction` to restore the previous state.

6. **Add request cancellation UI** to the HTTP Client (15.6): return a `{ promise, cancel }` object from `get`/`post`. `cancel()` calls `controller.abort()`.

7. **Add a "do not disturb" mode** to the Toast Manager (15.7): when `dnd = true`, new `info` and `warning` toasts go silently to the queue; only `error` toasts are shown.

8. **Extend the Autocomplete Engine** (15.8) with fuzzy matching as a fallback when the trie returns no results: edit distance ≤ 1 (one character inserted/deleted/substituted). Show exact prefix matches first.

9. **Add a sliding-window rate limiter** to the Infinite Feed (15.9): allow at most N `loadMore` calls in a rolling T-second window. Block and queue subsequent calls.
