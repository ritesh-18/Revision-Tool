## Chapter recap

| Problem | Core pattern | SDE-2 signal |
|---|---|---|
| BookMyShow | Seat holds (TTL + Clock), optimistic booking | Per-show lock, idempotent confirm |
| Pub-Sub | Partitions + offset commit | At-least-once, DLT, consumer group rebalance |

**Canonical questions for this chapter:**
- How do you prevent two users from booking the same seat?
- What is "at-least-once delivery" and how does your consumer handle duplicates?
- How would you add persistent storage without changing the core domain logic?
- What changes if you need exactly-once delivery?

## Practice exercises

1. Add a **payment timeout**: if a user holds seats but does not confirm within 10 minutes (injected clock), the hold expires and seats are released.
2. Add a **waitlist**: when a show is sold out, register interest and notify the first waiter when a seat is released.
3. Extend the Pub-Sub to support **message filters** on a subscription (e.g., a consumer only receives messages where `event.type === 'ORDER_PLACED'`).
4. Add **consumer group rebalancing** when a consumer joins or leaves a group — redistribute partitions evenly.
5. Implement the **Job Scheduler** from §16's practice list. Use the `AsyncMutex` and `Semaphore` from §7.
6. Implement the **DAG Execution Engine** from §16's practice list. Start with topological sort, then add parallel execution with a concurrency limit.
