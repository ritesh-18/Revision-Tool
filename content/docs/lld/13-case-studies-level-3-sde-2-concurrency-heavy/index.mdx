---
title: "13. Case Studies — Level 3 (SDE-2): Concurrency-Heavy Systems"
---

What separates an SDE-2 design from an SDE-1 design is not the number of classes but **the questions it answers**: what happens when two users book the last seat at the same millisecond? What does a consumer replay when it crashes mid-batch? How do you cancel a job that is already running? How does the system behave when a downstream service is down?

This chapter covers four systems where these questions are central:

| # | Problem | Key SDE-2 concerns | Reported at |
|---|---|---|---|
| 13.1 | BookMyShow / Movie Ticket Booking | Temporary seat holds with TTL, concurrent booking, payment timeout | Flipkart, Meesho, PhonePe |
| 13.2 | Pub-Sub / Kafka-lite Message Broker | Partitions, consumer groups, offsets, at-least-once, dead-letter | Razorpay, Flipkart, Groww |
| 13.3 | Job / Task Scheduler | Min-heap priorities, worker pool, retries, backoff, cancellation | Uber, Amazon, Atlassian |
| 13.4 | Workflow / DAG Execution Engine | Topological sort, parallel ready-tasks, failure policies, output passing | Flipkart, Amazon |

> **Note:** Sections 13.3 and 13.4 (Job Scheduler and DAG Engine) are covered as practice problems in §16 with full requirements, suggested entities, and implementation hints. The concurrency patterns they rely on (semaphore, async Mutex, injected Clock) are implemented and tested in §7.
