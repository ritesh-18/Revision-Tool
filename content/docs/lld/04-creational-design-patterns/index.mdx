---
title: "4. Creational Design Patterns"
---

Every object in your system is born somewhere. Creational patterns are about *where* and *how* that happens, so the code that uses an object doesn't have to know the messy details of building it. In a NestJS codebase you already use several of these without naming them: the DI container is a factory plus a singleton registry, `ConfigModule.forRoot({...})` is a builder in disguise, and `pg.Pool` is an object pool.

**What you'll learn**

- Why `new` spread across the codebase becomes a problem, and the five-plus ways to take control of object creation
- Singleton: the classic version, the TypeScript module-level version, the async-safe version, and why DI is usually the better answer
- The difference between Simple Factory, Factory Method and Abstract Factory (a favourite interview trap)
- Builder in two flavours: fluent builder and type-safe step builder
- Prototype and the real-world caveats of `structuredClone`
- Object Pool with async `acquire`/`release`, the pattern behind every DB connection pool
- Which pattern to reach for in common LLD problems (Parking Lot, Pizza/Order, Notification System, Trading Platform)

A single thread runs through the chapter: **separate "deciding what to create" from "using what was created".** Each pattern draws that line in a different place.
