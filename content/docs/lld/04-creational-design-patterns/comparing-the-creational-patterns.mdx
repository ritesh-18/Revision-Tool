---
title: "4.8 Comparing the creational patterns"
---

| Pattern | Core question it answers | Creates | Decided by | Typical TS form | LLD example |
| --- | --- | --- | --- | --- | --- |
| Singleton | "How do I have exactly one?" | 1 instance per process | The class itself (or the DI container) | module-level `const`, or private ctor + `getInstance()` | Logger, ParkingLot, metrics |
| Simple Factory | "Which class for this input?" | 1 product | A switch or registry in one place | `static create(kind)` with `never` check | Vehicle types, notifier by channel |
| Factory Method | "Let subclasses choose the product" | 1 product | Subclass override | `protected abstract createX()` | Payment processor → gateway |
| Abstract Factory | "Create a consistent family" | Several related products | The concrete factory object you inject | interface with several `createX()` | NSE/BSE components, UI themes |
| Builder | "How do I assemble a complex object safely?" | 1 complex product, step by step | The caller's sequence of calls | fluent `this`-returning setters, or type-state step interfaces | Pizza, Order, HTTP request |
| Prototype | "Can I copy a configured object instead?" | Copies of an existing object | The prototype's `clone()` | `clone(): T`, `structuredClone` for plain data | Strategy templates, duplicate shape |
| Object Pool | "How do I reuse a bounded set of expensive objects?" | Reused instances, lent exclusively | The pool (acquire/release) | async `acquire()` + `use(fn)` | DB connection pool, parking spots |
