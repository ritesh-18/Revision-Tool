---
title: "3.5 Law of Demeter (principle of least knowledge)"
---

**Rule.** A method should only talk to its "immediate friends": its own fields, its parameters, objects it creates, and itself. Avoid reaching through chains like `a.getB().getC().doThing()`.

**Why.** Every dot in a chain is a dependency on someone else's internal structure. If `Account` stops holding a `Wallet` directly, every caller that dug through it breaks.

```ts
// ❌ The checkout knows the internal layout of Client -> Account -> Wallet
if (client.getAccount().getWallet().getBalance() >= orderValue) {
  client.getAccount().getWallet().setBalance(
    client.getAccount().getWallet().getBalance() - orderValue,
  );
}
```

"Tell, don't ask" is the fix: tell the object what you want and let it handle its own internals.

```ts
class Wallet {
  #available: number;
  constructor(available: number) {
    this.#available = available;
  }
  tryBlock(amount: number): boolean {
    if (amount > this.#available) return false;
    this.#available -= amount;
    return true;
  }
  get available(): number {
    return this.#available;
  }
}

class Account {
  constructor(private readonly wallet: Wallet) {}
  reserveMargin(amount: number): boolean {
    return this.wallet.tryBlock(amount);
  }
  get freeMargin(): number {
    return this.wallet.available;
  }
}

class Client {
  constructor(readonly id: string, private readonly account: Account) {}
  reserveMargin(amount: number): boolean {
    return this.account.reserveMargin(amount);
  }
  get freeMargin(): number {
    return this.account.freeMargin;
  }
}

function checkout(client: Client, orderValue: number): string {
  return client.reserveMargin(orderValue)
    ? `${client.id}: margin blocked ${orderValue}, free ${client.freeMargin}`
    : `${client.id}: rejected, free ${client.freeMargin} < ${orderValue}`;
}

const c = new Client('C-5', new Account(new Wallet(10_000)));
console.log(checkout(c, 7_500));
console.log(checkout(c, 7_500));
```

```text
C-5: margin blocked 7500, free 2500
C-5: rejected, free 2500 < 7500
```

**Caveats**

- Fluent builders (`qb.where(...).orderBy(...).limit(10)`) and array pipelines (`list.filter().map()`) are fine: each call returns the *same kind* of thing you already own.
- Plain data (`order.address.pincode` on a DTO) isn't a real violation. The rule matters for objects with behaviour.
- Don't create 20 pass-through methods blindly. If `Client` needs lots of forwarding, maybe the caller should receive the `Account` directly.
