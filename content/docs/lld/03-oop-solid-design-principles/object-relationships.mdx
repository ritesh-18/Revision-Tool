title: "3.8 Object relationships"
---

Interviewers love asking "is this aggregation or composition?" Here are the six relationships, from weakest to strongest, each with a diagram and code.

| Relationship | Meaning | Lifetime | Mermaid |
|---|---|---|---|
| Dependency | "uses temporarily" (param/local) | not stored | `A ..> B` |
| Association | "knows about" (stored reference) | independent | `A --> B` |
| Aggregation | "has, but shares" (whole–part, parts outlive whole) | independent | `A o-- B` |
| Composition | "owns" (parts die with whole) | bound to owner | `A *-- B` |
| Realization | "implements" an interface | n/a | `A ..\|> I` |
| Inheritance | "is a" | n/a | `Parent <\|-- Child` |

## 3.8.1 Dependency

`OrderValidator` *uses* a `MarketCalendar` passed into one method. It doesn't keep it.

<Mermaid chart={`classDiagram
  class OrderValidator {
    +validate(order, calendar) boolean
  }
  class MarketCalendar {
    +isOpen(minuteOfDay) boolean
  }
  OrderValidator ..> MarketCalendar : uses`} />

```ts
class MarketCalendar {
  isOpen(minuteOfDay: number): boolean {
    return minuteOfDay >= 555 && minuteOfDay <= 930; // 09:15–15:30
  }
}

class OrderValidator {
  // Dependency: appears only as a parameter, not stored
  validate(order: { qty: number; minuteOfDay: number }, calendar: MarketCalendar): boolean {
    return order.qty > 0 && calendar.isOpen(order.minuteOfDay);
  }
}
```

## 3.8.2 Association

A `Trader` knows their `RelationshipManager`. Both exist independently; the reference is kept as a field.

<Mermaid chart={`classDiagram
  class Trader {
    +id: string
    -rm: RelationshipManager
    +escalate(issue) string
  }
  class RelationshipManager {
    +name: string
  }
  Trader "0..*" --> "1" RelationshipManager : assigned to`} />

```ts
class RelationshipManager {
  constructor(readonly name: string) {}
}

class Trader {
  constructor(readonly id: string, private rm: RelationshipManager) {}
  reassign(rm: RelationshipManager): void {
    this.rm = rm;
  }
  escalate(issue: string): string {
    return `${this.id} -> ${this.rm.name}: ${issue}`;
  }
}
```

## 3.8.3 Aggregation

A `Watchlist` *groups* `Instrument`s, but instruments are shared across many watchlists and outlive them. Deleting a watchlist doesn't delete INFY.

<Mermaid chart={`classDiagram
  class Watchlist {
    +name: string
    +add(instrument) void
  }
  class Instrument {
    +symbol: string
    +exchange: string
  }
  Watchlist "0..*" o-- "0..50" Instrument : contains`} />

```ts
class Instrument {
  constructor(readonly symbol: string, readonly exchange: 'NSE' | 'BSE') {}
}

class Watchlist {
  readonly #items: Instrument[] = [];
  constructor(readonly name: string) {}
  add(instrument: Instrument): void {
    // Receives an existing object; doesn't create or own its lifecycle
    if (!this.#items.includes(instrument)) this.#items.push(instrument);
  }
}

const infy = new Instrument('INFY', 'NSE');
new Watchlist('IT').add(infy);
new Watchlist('Long term').add(infy); // same instance shared
```

## 3.8.4 Composition

An `Order` *owns* its `OrderLeg`s (for a bracket order: entry, target, stop-loss). Legs are created by the order, never shared, and meaningless without it.

<Mermaid chart={`classDiagram
  class BracketOrder {
    +id: string
    +legs() OrderLeg[]
  }
  class OrderLeg {
    +type: string
    +price: number
  }
  BracketOrder "1" *-- "3" OrderLeg : owns`} />

```ts
class OrderLeg {
  constructor(readonly type: 'ENTRY' | 'TARGET' | 'STOPLOSS', readonly price: number) {}
}

class BracketOrder {
  readonly #legs: readonly OrderLeg[];
  constructor(readonly id: string, entry: number, target: number, stopLoss: number) {
    // The whole creates its parts; nobody else holds them
    this.#legs = [new OrderLeg('ENTRY', entry), new OrderLeg('TARGET', target), new OrderLeg('STOPLOSS', stopLoss)];
  }
  legs(): readonly OrderLeg[] {
    return this.#legs;
  }
}
```

**Aggregation vs composition, the one question to ask:** *if the whole is deleted, do the parts still make sense on their own?* Yes → aggregation. No → composition.

## 3.8.5 Realization

A class *implements* an interface.

<Mermaid chart={`classDiagram
  class PaymentGateway {
    <<interface>>
    +charge(amount) string
  }
  class RazorpayGateway {
    +charge(amount) string
  }
  class NetBankingGateway {
    +charge(amount) string
  }
  RazorpayGateway ..|> PaymentGateway
  NetBankingGateway ..|> PaymentGateway`} />

```ts
interface PaymentGateway {
  charge(amount: number): string;
}

class RazorpayGateway implements PaymentGateway {
  charge(amount: number): string {
    return `rzp_${amount}`;
  }
}

class NetBankingGateway implements PaymentGateway {
  charge(amount: number): string {
    return `nb_${amount}`;
  }
}
```

## 3.8.6 Inheritance (generalization)

<Mermaid chart={`classDiagram
  class Instrument {
    <<abstract>>
    +symbol: string
    +lotSize() number
  }
  class Equity {
    +lotSize() number
  }
  class FuturesContract {
    +expiry: string
    +lotSize() number
  }
  Instrument <|-- Equity
  Instrument <|-- FuturesContract`} />

```ts
abstract class Instrument {
  constructor(readonly symbol: string) {}
  abstract lotSize(): number;
}

class Equity extends Instrument {
  override lotSize(): number {
    return 1;
  }
}

class FuturesContract extends Instrument {
  constructor(symbol: string, readonly expiry: string, private readonly lot: number) {
    super(symbol);
  }
  override lotSize(): number {
    return this.lot;
  }
}
```
