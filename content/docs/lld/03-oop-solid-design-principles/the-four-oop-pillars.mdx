title: "3.1 The four OOP pillars"
---

Think of the pillars as four tools, not four commandments. Each one fixes a specific problem, and each one causes new problems when you use it where it doesn't fit.

## 3.1.1 Encapsulation: protect the rules

**Intuition.** An object owns some data *and* the rules that keep that data valid. Outsiders shouldn't be able to put the object into a state that breaks those rules.

**Rule.** Keep state private. Change it only through methods that check the rules (the *invariants*).

A trading wallet is a good example. The balance must never go negative, and every change must leave an audit entry.

```ts
class InsufficientFundsError extends Error {
  override name = 'InsufficientFundsError';
}

class TradingWallet {
  #balancePaise = 0;
  readonly #ledger: string[] = [];

  constructor(readonly clientId: string) {}

  get balance(): number {
    return this.#balancePaise / 100;
  }

  deposit(amountRupees: number, ref: string): void {
    if (amountRupees <= 0) throw new RangeError('Deposit must be positive');
    this.#balancePaise += Math.round(amountRupees * 100);
    this.#ledger.push(`CR ${amountRupees} (${ref})`);
  }

  block(amountRupees: number, orderId: string): void {
    const paise = Math.round(amountRupees * 100);
    if (paise > this.#balancePaise) {
      throw new InsufficientFundsError(`Need ${amountRupees}, have ${this.balance}`);
    }
    this.#balancePaise -= paise;
    this.#ledger.push(`DR ${amountRupees} (${orderId})`);
  }

  statement(): readonly string[] {
    return [...this.#ledger];
  }
}

const wallet = new TradingWallet('C-101');
wallet.deposit(5000, 'UPI-1');
wallet.block(1200.5, 'ORD-1');
try {
  wallet.block(10_000, 'ORD-2');
} catch (err) {
  if (err instanceof Error) console.log(`${err.name}: ${err.message}`);
}
console.log(`balance=${wallet.balance}`);
console.log(wallet.statement().join(' | '));
```

```text
InsufficientFundsError: Need 10000, have 3799.5
balance=3799.5
CR 5000 (UPI-1) | DR 1200.5 (ORD-1)
```

Things to notice:

- `#balancePaise` is a real runtime-private field. TypeScript's `private` is only checked at compile time; `#` is enforced by JavaScript itself.
- Money is stored in paise (integers) to avoid floating-point drift. That's an implementation detail nobody outside needs to know, which is the whole point.
- `statement()` returns a copy, so callers can't push fake entries into the ledger.

**When it helps:** any object with invariants (orders, wallets, carts, rate limiters).
**When it hurts:** wrapping plain data (DTOs, API responses) in getters and setters that check nothing. A `type OrderDto = { ... }` is fine. Getters and setters that do no checking add ceremony and protect nothing.

## 3.1.2 Abstraction: hide the how, expose the what

**Intuition.** You call `notifier.send(user, msg)` without caring whether it's SMS, email or push. Abstraction is choosing *what a caller needs to know* and hiding the rest.

**Rule.** Callers depend on a small, meaningful contract, not on implementation steps.

```ts
interface QuoteSource {
  lastPrice(symbol: string): Promise<number>;
}

class CachedQuoteSource implements QuoteSource {
  readonly #cache = new Map<string, number>();
  #upstreamCalls = 0;

  async lastPrice(symbol: string): Promise<number> {
    const hit = this.#cache.get(symbol);
    if (hit !== undefined) return hit;
    const price = await this.#fetchFromExchange(symbol);
    this.#cache.set(symbol, price);
    return price;
  }

  get upstreamCalls(): number {
    return this.#upstreamCalls;
  }

  async #fetchFromExchange(symbol: string): Promise<number> {
    this.#upstreamCalls++;
    await new Promise((r) => setTimeout(r, 5));
    const fake: Record<string, number> = { INFY: 1510.25, TCS: 3890 };
    return fake[symbol] ?? 0;
  }
}

async function portfolioValue(src: QuoteSource, holdings: Record<string, number>): Promise<number> {
  let total = 0;
  for (const [sym, qty] of Object.entries(holdings)) total += (await src.lastPrice(sym)) * qty;
  return total;
}

const src = new CachedQuoteSource();
console.log(await portfolioValue(src, { INFY: 10, TCS: 2 }));
console.log(await portfolioValue(src, { INFY: 4 }));
console.log(`upstream calls: ${src.upstreamCalls}`);
```

```text
22882.5
6041
upstream calls: 2
```

`portfolioValue` has no idea caching exists. Tomorrow you can swap in a WebSocket-backed source and it won't change.

**When it helps:** at boundaries (I/O, third-party APIs, anything you want to fake in tests).
**When it hurts:** "abstraction for one implementation that will never change". An `IStringUtils` interface with one `StringUtils` class is noise. Also watch for *leaky* abstractions: if callers must know "call `connect()` before `lastPrice()`", the abstraction is lying.

## 3.1.3 Inheritance: "is-a" with shared behaviour

**Intuition.** A subclass is a more specific version of its parent. It reuses the parent's code and can override parts of it.

**Rule.** Use inheritance only when the child really *is* the parent in every context, and the parent was designed to be extended.

```ts
abstract class Order {
  constructor(readonly symbol: string, readonly qty: number) {}

  describe(): string {
    return `${this.kind()} ${this.qty} ${this.symbol}${this.priceText()}`;
  }

  protected abstract kind(): string;

  protected priceText(): string {
    return '';
  }
}

class MarketOrder extends Order {
  protected override kind(): string {
    return 'MARKET';
  }
}

class LimitOrder extends Order {
  constructor(symbol: string, qty: number, readonly limitPrice: number) {
    super(symbol, qty);
  }
  protected override kind(): string {
    return 'LIMIT';
  }
  protected override priceText(): string {
    return ` @ ${this.limitPrice}`;
  }
}

const orders: Order[] = [new MarketOrder('SBIN', 50), new LimitOrder('INFY', 10, 1500)];
for (const o of orders) console.log(o.describe());
```

```text
MARKET 50 SBIN
LIMIT 10 INFY @ 1500
```

This is the *template method* shape: the parent fixes the algorithm (`describe`) and children fill in the steps.

**When it hurts** (and it often does):

- **Fragile base class.** A change in `Order` ripples into every subclass, sometimes silently.
- **Deep hierarchies.** `Order → EquityOrder → IntradayEquityOrder → BracketIntradayEquityOrder` explodes as soon as a second dimension (product type × order type) appears.
- **Inheriting to reuse code**, not because of an "is-a" relationship. `class ReportService extends HttpClient` is a classic mistake.

Rule of thumb: one level of inheritance from an abstract base is usually fine. Beyond two levels, reach for composition (section 3.4).

## 3.1.4 Polymorphism: one call, many behaviours

**Intuition.** The caller writes `charge.compute(trade)` once; the right logic runs depending on the object. It replaces `if/else` or `switch` on a type tag.

TypeScript gives you three flavours:

1. **Subtype polymorphism**: different classes implementing the same interface (the most common in LLD).
2. **Parametric polymorphism**: generics, such as `Repository<T>`.
3. **Structural typing**: any object with the right shape fits, with no `implements` needed.

```ts
type Trade = { side: 'BUY' | 'SELL'; turnover: number };

interface Charge {
  readonly name: string;
  compute(t: Trade): number;
}

class Brokerage implements Charge {
  readonly name = 'brokerage';
  compute(t: Trade): number {
    return Math.min(20, t.turnover * 0.0003);
  }
}

class Stt implements Charge {
  readonly name = 'stt';
  compute(t: Trade): number {
    return t.side === 'SELL' ? t.turnover * 0.001 : 0;
  }
}

// Structural typing: a plain object literal also satisfies Charge
const exchangeFee: Charge = {
  name: 'exchange',
  compute: (t) => t.turnover * 0.0000345,
};

function totalCharges(charges: readonly Charge[], t: Trade): string {
  return charges
    .map((c) => `${c.name}=${c.compute(t).toFixed(2)}`)
    .join(', ');
}

const charges = [new Brokerage(), new Stt(), exchangeFee];
console.log(totalCharges(charges, { side: 'BUY', turnover: 50_000 }));
console.log(totalCharges(charges, { side: 'SELL', turnover: 100_000 }));
```

```text
brokerage=15.00, stt=0.00, exchange=1.72
brokerage=20.00, stt=100.00, exchange=3.45
```

**When it hurts:** when there are only two cases that will never grow, a `switch` on a discriminated union is simpler and the compiler checks exhaustiveness for you. Polymorphism pays off when the set of behaviours is *open* (new fee types, new payment methods).

> **Interview line:** "Encapsulation protects invariants, abstraction hides the how behind a contract, inheritance shares behaviour for true is-a relationships, and polymorphism lets me add a new variant without touching the caller. In practice I lean on encapsulation and polymorphism through interfaces, and use inheritance sparingly."
