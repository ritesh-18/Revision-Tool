---
title: "3.9 UML class-diagram cheat sheet"
---

You'll often sketch a diagram in the first 10 minutes of an LLD round. Keep it light: classes, key fields/methods, relationships and multiplicity.

## 3.9.1 Visibility and member notation

| Marker | Meaning | TypeScript |
|---|---|---|
| `+` | public | `public` (default) |
| `-` | private | `private` / `#field` |
| `#` | protected | `protected` |
| `~` | package/internal | no direct equivalent (module-private, not exported) |
| `$` suffix | static | `static` |
| `*` suffix | abstract | `abstract` |

Member syntax in Mermaid: `+name: type` for fields, `+method(args) ReturnType` for methods. Generics use tildes: `List~Order~`.

<Mermaid chart={`classDiagram
  class OrderBook {
    <<service>>
    -bids: List~Order~
    -asks: List~Order~
    #lastTradePrice: number
    +instanceCount$: number
    +place(order) Trade[]
    +cancel(orderId) boolean
    +match()* void
  }`} />

## 3.9.2 Arrow types

| Relationship | Mermaid | Picture |
|---|---|---|
| Inheritance | `Parent <\|-- Child` | solid line, hollow triangle |
| Realization | `Class ..\|> Interface` | dashed line, hollow triangle |
| Composition | `Whole *-- Part` | solid line, filled diamond at whole |
| Aggregation | `Whole o-- Part` | solid line, hollow diamond at whole |
| Association | `A --> B` | solid line, open arrow |
| Dependency | `A ..> B` | dashed line, open arrow |
| Link (undirected) | `A -- B` | solid line |

## 3.9.3 Multiplicity and labels

| Notation | Meaning |
|---|---|
| `1` | exactly one |
| `0..1` | optional |
| `*` or `0..*` | zero or more |
| `1..*` | at least one |
| `n..m` | range |

Multiplicities go in quotes on each side; a label goes after a colon.

<Mermaid chart={`classDiagram
  class Client
  class DematAccount
  class Order
  class Holding
  class Notifier {
    <<interface>>
    +notify(clientId, msg) void
  }
  class SmsNotifier
  Client "1" --> "1..*" DematAccount : owns accounts
  Client "1" --> "0..*" Order : places
  DematAccount "1" *-- "0..*" Holding : holds
  SmsNotifier ..|> Notifier
  Order ..> Notifier : notifies via`} />

## 3.9.4 Annotations

`<<interface>>`, `<<abstract>>`, `<<enumeration>>` and `<<service>>` go on the first line inside a class block.

<Mermaid chart={`classDiagram
  class OrderSide {
    <<enumeration>>
    BUY
    SELL
  }
  class OrderType {
    <<enumeration>>
    MARKET
    LIMIT
    SL
  }`} />

**Interview tip.** Don't try to draw everything. Show the core 5–8 classes, the relationship type between them and multiplicity where it matters ("a client has many orders"). Then move to code.
