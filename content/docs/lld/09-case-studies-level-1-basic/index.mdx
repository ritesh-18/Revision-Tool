---
title: "9. Case Studies — Level 1 (Basic)"
---

This is where the book turns from patterns into problems. Every case study in this chapter is a problem Indian product companies really use in machine-coding and LLD rounds. They're "basic" only because the domain fits in your head in two minutes. The grading is not basic. A Flipkart or PhonePe reviewer opens your code and checks whether the entities are right, whether a new vehicle type or win rule can be added without editing five files, whether an invalid move throws a meaningful error, and whether the program actually runs.

Every problem follows the same 15-step template, so after the first one you'll know where to look for things. It's also the order to *think* in during an interview: clarify, list requirements, find the entities, draw them, choose patterns, code in layers, run it, then harden it (concurrency, extensions, edge cases).

**What you'll learn**

- How to turn a one-line prompt ("design a parking lot") into a scoped, runnable design in 90 minutes
- Where Strategy, State, Command, Chain of Responsibility, Observer and Specification actually earn their place (and where they would be over-engineering)
- How to keep games and machines deterministic with injected `Clock`, `IdGenerator` and `Dice`
- The concurrency questions that follow even "basic" problems at SDE-2 level: the last parking spot, a late UPI callback, overlapping log flushes, lost updates on a task
- How to implement the follow-up interviewers ask *after* your first version works
