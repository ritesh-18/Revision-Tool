---
title: "2.19 satisfies"
---

`satisfies` checks a value against a type **without widening** the value's inferred type. You get validation plus precise types.

```ts
type Segment = "EQUITY" | "FNO" | "COMMODITY";
interface FeeRule { brokeragePaise: number; exchange: "NSE" | "BSE" | "MCX" }

// With a type annotation, the literal info is lost: FEES.EQUITY.exchange is "NSE" | "BSE" | "MCX"
const FEES_ANNOTATED: Record<Segment, FeeRule> = {
  EQUITY: { brokeragePaise: 0, exchange: "NSE" },
  FNO: { brokeragePaise: 2000, exchange: "NSE" },
  COMMODITY: { brokeragePaise: 2000, exchange: "MCX" },
};

// With satisfies: every Segment key is still required, typos are caught,
// but the exact literal types are kept.
const FEES = {
  EQUITY: { brokeragePaise: 0, exchange: "NSE" },
  FNO: { brokeragePaise: 2000, exchange: "NSE" },
  COMMODITY: { brokeragePaise: 2000, exchange: "MCX" },
} as const satisfies Record<Segment, FeeRule>;

const mcx: "MCX" = FEES.COMMODITY.exchange;            // ✅ literal type preserved
// const mcx2: "MCX" = FEES_ANNOTATED.COMMODITY.exchange; // ❌ error: union not assignable to "MCX"

// Missing key or wrong value would fail:
// const BAD = { EQUITY: { brokeragePaise: 0, exchange: "NYSE" } } satisfies Record<Segment, FeeRule>;

const routes = {
  placeOrder: "/orders",
  cancelOrder: "/orders/:id/cancel",
} satisfies Record<string, `/${string}`>;
type RouteName = keyof typeof routes; // "placeOrder" | "cancelOrder" (not string!)
const r: RouteName = "cancelOrder";

console.log(`${mcx} ${FEES_ANNOTATED.FNO.brokeragePaise} ${routes[r]}`);
```

```text
MCX 2000 /orders/:id/cancel
```

Use `satisfies` for config tables, route maps, strategy registries and handler maps: anything where you want "must match this shape" without losing the specific keys.
