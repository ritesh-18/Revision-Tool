---
title: "2.7 Abstract classes vs interfaces"
---

## Intuition

- An **interface** says *what* something can do. No code, no state. A class may implement many.
- An **abstract class** says *what* plus *some of how*. It can hold shared state and shared logic (template method). A class can extend only one.

## Rule

- Start with an **interface** for every collaborator you inject (`PaymentMethod`, `Notifier`, `PriceFeed`). It keeps you flexible and easy to mock.
- Add an **abstract base class** only when several implementations share real logic or state: the classic Template Method pattern.
- It is common to use both: `interface PaymentMethod` + `abstract class BasePaymentMethod implements PaymentMethod`.

## Example: payment methods

```ts
interface PaymentMethod {
  readonly name: string;
  pay(amountPaise: number): string;
}

abstract class BasePaymentMethod implements PaymentMethod {
  abstract readonly name: string;
  protected abstract readonly maxPaise: number;

  // Template method: fixed algorithm, variable steps
  pay(amountPaise: number): string {
    if (amountPaise <= 0) throw new Error("amount must be positive");
    if (amountPaise > this.maxPaise) {
      throw new Error(`${this.name}: limit ₹${this.maxPaise / 100} exceeded`);
    }
    const ref = this.charge(amountPaise);
    return `${this.name} ok ref=${ref} fee=${this.fee(amountPaise)}`;
  }

  protected abstract charge(amountPaise: number): string;

  // Hook with a default that subclasses may override
  protected fee(_amountPaise: number): number {
    return 0;
  }
}

class UpiPayment extends BasePaymentMethod {
  readonly name = "UPI";
  protected readonly maxPaise = 1_00_000_00; // ₹1,00,000
  constructor(private readonly vpa: string) { super(); }
  protected charge(amountPaise: number): string {
    return `upi:${this.vpa}:${amountPaise}`;
  }
}

class CardPayment extends BasePaymentMethod {
  readonly name = "CARD";
  protected readonly maxPaise = 5_00_000_00;
  constructor(private readonly last4: string) { super(); }
  protected charge(amountPaise: number): string {
    return `card:${this.last4}:${amountPaise}`;
  }
  protected override fee(amountPaise: number): number {
    return Math.round(amountPaise * 0.018); // 1.8% card fee
  }
}

// A totally unrelated implementation that doesn't use the base class
class WalletPayment implements PaymentMethod {
  readonly name = "WALLET";
  pay(amountPaise: number): string {
    return `WALLET debited ${amountPaise}`;
  }
}

const methods: PaymentMethod[] = [
  new UpiPayment("ritesh@okbank"),
  new CardPayment("4242"),
  new WalletPayment(),
];

for (const m of methods) {
  try {
    console.log(m.pay(200_000));
    console.log(m.pay(2_00_00_000));
  } catch (err) {
    if (err instanceof Error) console.log(`failed: ${err.message}`);
  }
}
// new BasePaymentMethod(); // ❌ error: cannot create an instance of an abstract class
```

```text
UPI ok ref=upi:ritesh@okbank:200000 fee=0
failed: UPI: limit ₹100000 exceeded
CARD ok ref=card:4242:200000 fee=3600
CARD ok ref=card:4242:20000000 fee=360000
WALLET debited 200000
WALLET debited 20000000
```

## A second classic: `Vehicle` in a parking lot

```ts
type VehicleSize = "SMALL" | "MEDIUM" | "LARGE";

abstract class Vehicle {
  constructor(public readonly plate: string) {}
  abstract get size(): VehicleSize;
  abstract hourlyRatePaise(): number;

  parkingFee(hours: number): number {
    const billable = Math.max(1, Math.ceil(hours));
    return billable * this.hourlyRatePaise();
  }
  describe(): string {
    return `${this.constructor.name}(${this.plate}, ${this.size})`;
  }
}

class Bike extends Vehicle {
  get size(): VehicleSize { return "SMALL"; }
  hourlyRatePaise(): number { return 1000; }
}

class Car extends Vehicle {
  get size(): VehicleSize { return "MEDIUM"; }
  hourlyRatePaise(): number { return 4000; }
}

class Truck extends Vehicle {
  get size(): VehicleSize { return "LARGE"; }
  hourlyRatePaise(): number { return 10000; }
  override parkingFee(hours: number): number {
    return super.parkingFee(hours) + 5000; // flat loading-bay surcharge
  }
}

const vehicles: Vehicle[] = [new Bike("KA01"), new Car("MH02"), new Truck("DL03")];
for (const v of vehicles) {
  console.log(`${v.describe()} 2.5h → ₹${v.parkingFee(2.5) / 100}`);
}
```

```text
Bike(KA01, SMALL) 2.5h → ₹30
Car(MH02, MEDIUM) 2.5h → ₹120
Truck(DL03, LARGE) 2.5h → ₹350
```

| Question | Interface | Abstract class |
|---|---|---|
| Holds state / constructor? | No | Yes |
| Shared implementation? | No | Yes |
| How many per class? | Many (`implements A, B`) | One (`extends`) |
| Exists at runtime? | No (erased) | Yes (a real JS class, `instanceof` works) |
| Best for | DI contracts, mocks, capabilities | Template Method, shared validation |

> **How to say it in an interview:** "I code to interfaces for anything injected. If implementations share an algorithm, I add an abstract base that implements the interface and exposes abstract steps. That gives me the Template Method without forcing every implementation into one hierarchy."
