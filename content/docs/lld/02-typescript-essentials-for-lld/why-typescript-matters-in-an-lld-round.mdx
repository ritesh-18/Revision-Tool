---
title: "2.1 Why TypeScript matters in an LLD round"
---

In an LLD round the interviewer is not only checking whether your code runs. They are checking whether your **types describe the domain**. Compare these two signatures:

```ts
// ❌ vague: what is `status`? what is `amount` — rupees? paise? a float?
function placeOrder(user: string, symbol: string, qty: number, amount: number, status: string): any {}
```

```ts
type OrderSide = "BUY" | "SELL";
type OrderStatus = "OPEN" | "FILLED" | "CANCELLED";

interface PlaceOrderRequest {
  readonly userId: string;
  readonly symbol: string;
  readonly side: OrderSide;
  readonly quantity: number;
  readonly limitPricePaise: number; // integer paise, never a float
}

interface Order extends PlaceOrderRequest {
  readonly id: string;
  status: OrderStatus;
}

declare function placeOrder(req: PlaceOrderRequest): Order;
```

The second version tells the reader what is legal before they read a single line of the body. That is the mindset for the rest of this chapter: **make illegal states hard to write down**.

> **How to say it in an interview:** "I'll start with the types first. They act like a contract. Once the entities and their states are typed, the service code mostly writes itself and the compiler catches misuse for me."
