---
title: "2.10 Enums vs string-literal unions"
---

## Options

```ts
// 1. Numeric enum (avoid in domain code)
enum Priority { LOW, MEDIUM, HIGH }

// 2. String enum
enum OrderTypeEnum {
  MARKET = "MARKET",
  LIMIT = "LIMIT",
}

// 3. String-literal union (+ optional runtime list via as const)
const ORDER_TYPES = ["MARKET", "LIMIT", "STOP_LOSS"] as const;
type OrderType = (typeof ORDER_TYPES)[number];

function isOrderType(x: string): x is OrderType {
  return (ORDER_TYPES as readonly string[]).includes(x);
}

// 4. "Enum-like object" — named constants AND a union type
const Side = { BUY: "BUY", SELL: "SELL" } as const;
type Side = (typeof Side)[keyof typeof Side];

// Numeric enum pitfalls
const someNumber: number = 42;
const p: Priority = someNumber; // ⚠️ compiles! any `number` is accepted (only bare literals are checked)
console.log(`Priority[2]=${Priority[2]} p=${p}`); // reverse mapping exists for numeric enums

// String enum: callers must use the enum, not the raw string
function placeEnum(t: OrderTypeEnum): string { return `enum:${t}`; }
console.log(placeEnum(OrderTypeEnum.LIMIT));
// placeEnum("LIMIT"); // ❌ error: '"LIMIT"' is not assignable to 'OrderTypeEnum'

// Union: raw strings work, autocomplete works, nothing is emitted
function placeUnion(t: OrderType, s: Side): string { return `union:${s}:${t}`; }
console.log(placeUnion("STOP_LOSS", Side.BUY));

// Validating untrusted input (e.g. a request body)
for (const raw of ["LIMIT", "ICEBERG"]) {
  console.log(`${raw} valid=${isOrderType(raw)}`);
}
console.log(`all: ${ORDER_TYPES.join("|")} sides: ${Object.values(Side).join("|")}`);
```

```text
Priority[2]=HIGH p=42
enum:LIMIT
union:BUY:STOP_LOSS
LIMIT valid=true
ICEBERG valid=false
all: MARKET|LIMIT|STOP_LOSS sides: BUY|SELL
```

## Pros and cons

| | Numeric `enum` | String `enum` | Literal union (+ `as const` list) |
|---|---|---|---|
| Generates runtime code | Yes | Yes | Only if you write the array/object |
| Readable in logs/JSON | No (`2`) | Yes | Yes |
| Accepts raw strings from JSON | — | No (needs cast) | Yes |
| Type safety | Weak (any number fits) | Strong | Strong |
| Works with Node type-stripping / `erasableSyntaxOnly` | No | No | Yes |
| Iterate values | Awkward (reverse mapping) | `Object.values` | The `as const` array |
| Rename refactor | Easy | Easy | Editor-supported |

## Recommendation

Use **string-literal unions**, with an `as const` array or object when you also need the values at runtime. Use a string `enum` only if the codebase already does (many NestJS projects do, for Swagger and class-validator). Avoid numeric enums for domain states.

> **How to say it in an interview:** "I prefer string-literal unions: no runtime code, readable JSON, and they narrow nicely in switches. If I need to iterate values I derive the union from an `as const` array, so there's one source of truth."
