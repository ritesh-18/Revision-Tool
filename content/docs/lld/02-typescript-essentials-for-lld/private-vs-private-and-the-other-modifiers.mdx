## The three TypeScript modifiers

| Modifier | Visible in the class | Visible in subclasses | Visible outside |
|---|---|---|---|
| `public` (default) | Yes | Yes | Yes |
| `protected` | Yes | Yes | No |
| `private` | Yes | No | No |

These are **compile-time only**. After compilation, a `private` field is an ordinary JS property and anyone can read it with `obj["field"]` or `JSON.stringify`.

## ECMAScript `#private`

`#field` is real JavaScript privacy enforced by the runtime. It does not show up in `JSON.stringify`, `Object.keys`, or bracket access.

```ts
class TsPrivateWallet {
  constructor(private pin: string) {}
  check(p: string): boolean { return p === this.pin; }
}

class HashPrivateWallet {
  #pin: string;
  constructor(pin: string) { this.#pin = pin; }
  check(p: string): boolean { return p === this.#pin; }

  static hasPin(obj: object): boolean {
    return #pin in obj; // ergonomic brand check
  }
}

const w1 = new TsPrivateWallet("1234");
const w2 = new HashPrivateWallet("5678");

console.log(JSON.stringify(w1)); // leaks!
console.log(JSON.stringify(w2)); // nothing to see
console.log(`bracket access: ${(w1 as unknown as Record<string, string>)["pin"]}`);
console.log(`keys of w2: [${Object.keys(w2).join(",")}]`);
console.log(`hasPin: ${HashPrivateWallet.hasPin(w2)} ${HashPrivateWallet.hasPin(w1)}`);
console.log(`checks: ${w1.check("1234")} ${w2.check("5678")}`);
```

```text
{"pin":"1234"}
{}
bracket access: 1234
keys of w2: []
hasPin: true false
checks: true true
```

## Which one should you use?

- **`private`**: the common choice in NestJS code bases; works with parameter properties and dependency injection; fine for interviews.
- **`#private`**: use when the secret must not leak at runtime (tokens, PINs, internal state that gets serialized or logged).
- `protected`: use sparingly. It couples subclasses to parent internals. Prefer a protected **method** over a protected mutable **field**.

> **How to say it in an interview:** "`private` is a compile-time check; `#private` is enforced by the JS runtime and doesn't leak through `JSON.stringify`. I default to `private` for readability with DI, and use `#` for sensitive data."
