---
title: "2.17 unknown vs any"
---

- `any` switches the type checker **off**. Anything goes in, anything comes out, and the "any-ness" spreads.
- `unknown` means "I don't know yet". You can store it and pass it around, but you must **narrow** it before using it.

```ts
function riskyAny(payload: any): number {
  return payload.amount.toFixed(2).length; // compiles, but can crash
}

function safeUnknown(payload: unknown): number {
  if (
    typeof payload === "object" && payload !== null &&
    "amount" in payload && typeof payload.amount === "number"
  ) {
    return payload.amount;
  }
  throw new TypeError("payload.amount must be a number");
}

const good: unknown = JSON.parse('{"amount": 499}');
const bad: unknown = JSON.parse('{"amt": 499}');

console.log(`safe good: ${safeUnknown(good)}`);
try {
  safeUnknown(bad);
} catch (err) {
  if (err instanceof Error) console.log(`safe bad: ${err.message}`);
}
try {
  riskyAny(bad);
} catch (err) {
  if (err instanceof Error) console.log(`any crashed at runtime: ${err.name}`);
}
```

```text
safe good: 499
safe bad: payload.amount must be a number
any crashed at runtime: TypeError
```

Rule: type external input (HTTP bodies, `JSON.parse`, message queue payloads, `catch` variables) as `unknown`, then validate with a type guard or a schema library (zod, class-validator). Never write `any` in an interview unless you say why.
