## Fields, constructors and parameter properties

A **parameter property** declares and assigns a field in one go by putting a modifier (`private`, `public`, `readonly`, `protected`) in front of a constructor parameter. It is the idiomatic way to take dependencies in NestJS-style code.

```ts
class Account {
  // 1. explicit field with initializer
  private balancePaise = 0;
  // 2. static member: shared by all instances
  private static nextId = 1;
  static readonly MIN_BALANCE_PAISE = 0;

  readonly id: string;

  // 3. parameter properties: `ownerName` and `kycVerified` become fields automatically
  constructor(
    public readonly ownerName: string,
    private kycVerified: boolean,
  ) {
    this.id = `ACC-${Account.nextId++}`;
  }

  // 4. getter: read like a field, computed like a method
  get balance(): number {
    return this.balancePaise;
  }

  // 5. getter + setter pair with validation
  get isKycVerified(): boolean {
    return this.kycVerified;
  }
  set isKycVerified(value: boolean) {
    if (!value && this.balancePaise > 0) {
      throw new Error("cannot revoke KYC while funds are held");
    }
    this.kycVerified = value;
  }

  deposit(paise: number): void {
    if (!this.kycVerified) throw new Error(`${this.id}: KYC pending`);
    if (!Number.isSafeInteger(paise) || paise <= 0) throw new Error("deposit must be a positive integer");
    this.balancePaise += paise;
  }

  // 6. static factory method
  static openVerified(ownerName: string): Account {
    return new Account(ownerName, true);
  }
}

const a = Account.openVerified("Ritesh");
a.deposit(50_000);
console.log(`${a.id} ${a.ownerName} balance=${a.balance}`);

const b = new Account("Asha", false);
try {
  b.deposit(100);
} catch (err) {
  if (err instanceof Error) console.log(err.message);
}
b.isKycVerified = true;
b.deposit(100);
console.log(`${b.id} balance=${b.balance} kyc=${b.isKycVerified}`);

try {
  a.isKycVerified = false;
} catch (err) {
  if (err instanceof Error) console.log(err.message);
}
// a.balance = 10;       // ❌ error: cannot assign to 'balance' because it is a read-only property
// a.balancePaise = 10;  // ❌ error: property 'balancePaise' is private
```

```text
ACC-1 Ritesh balance=50000
ACC-2: KYC pending
ACC-2 balance=100 kyc=true
cannot revoke KYC while funds are held
```

Things worth pointing out in an interview:

- `balance` has **only a getter**, so outside code can read it but never write it. Changes go through `deposit`, which enforces rules. This is encapsulation in practice.
- The static `nextId` counter is fine for a machine-coding round. Mention that in production IDs come from a DB sequence or UUID.
- Static factory methods (`openVerified`) give constructors meaningful names.

## Parameter properties and the Node "strip types" caveat

Node's type stripping (`--experimental-strip-types`) cannot handle parameter properties or enums because they generate JavaScript. This book runs code with `--experimental-transform-types`, which supports them. In a real NestJS project compiled by `tsc` or SWC they work normally. If an interviewer's online editor complains, fall back to explicit fields.
