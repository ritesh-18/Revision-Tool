---

## Index signatures

```ts
const balances: { [userId: string]: number } = {};   // or Record<string, number>
balances["U1"] = 100;
const x = balances["U2"]; // type is number, but the value is undefined at runtime!
```

With `noUncheckedIndexedAccess` the type becomes `number | undefined`, which is safer. Plain objects also carry prototype baggage: a key like `"constructor"` or `"__proto__"` can behave strangely.

## Why `Map` is usually better for in-memory stores

| | Plain object / `Record` | `Map` |
|---|---|---|
| Key types | strings/symbols only | anything (objects, numbers, branded ids) |
| Missing key type | `V` (unless the flag is on) | `.get()` always returns `V \| undefined` |
| Size | `Object.keys(o).length` (O(n)) | `.size` (O(1)) |
| Insertion order | mostly, with quirks for integer-like keys | guaranteed |
| Frequent add/delete | slower | designed for it |
| JSON serializable | yes | no (convert with `Object.fromEntries`) |

Use `Record` for **fixed lookup tables** (keys known up front, e.g. `Record<OrderStatus, string>`). Use `Map` for **dynamic stores** (orders by id, positions by user).

```ts
type Side = "BUY" | "SELL";
interface Position { symbol: string; qty: number }

class PortfolioStore {
  // userId → (symbol → position)
  private readonly positions = new Map<string, Map<string, Position>>();
  // userId → watchlist symbols (Set: no duplicates, O(1) has)
  private readonly watchlists = new Map<string, Set<string>>();

  apply(userId: string, symbol: string, side: Side, qty: number): void {
    let byUser = this.positions.get(userId);
    if (!byUser) {
      byUser = new Map();
      this.positions.set(userId, byUser);
    }
    const current = byUser.get(symbol)?.qty ?? 0;
    const next = side === "BUY" ? current + qty : current - qty;
    if (next < 0) throw new Error(`cannot sell ${qty} ${symbol}, holding ${current}`);
    if (next === 0) byUser.delete(symbol);
    else byUser.set(symbol, { symbol, qty: next });
  }

  watch(userId: string, symbol: string): void {
    const set = this.watchlists.get(userId) ?? new Set<string>();
    set.add(symbol);
    this.watchlists.set(userId, set);
  }

  summary(userId: string): string {
    const pos = [...(this.positions.get(userId)?.values() ?? [])]
      .map((p) => `${p.symbol}:${p.qty}`)
      .join(",");
    const watch = [...(this.watchlists.get(userId) ?? [])].join(",");
    return `${userId} positions=[${pos}] watch=[${watch}]`;
  }

  toJSON(): Record<string, Position[]> {
    return Object.fromEntries(
      [...this.positions].map(([u, m]) => [u, [...m.values()]]),
    );
  }
}

const store = new PortfolioStore();
store.apply("U1", "INFY", "BUY", 10);
store.apply("U1", "TCS", "BUY", 5);
store.apply("U1", "INFY", "SELL", 10);
store.watch("U1", "HDFCBANK");
store.watch("U1", "HDFCBANK"); // duplicate ignored
store.watch("U1", "SBIN");

try {
  store.apply("U1", "TCS", "SELL", 6);
} catch (err) {
  if (err instanceof Error) console.log(err.message);
}
console.log(store.summary("U1"));
console.log(JSON.stringify(store));

// Set operations (ES2024 lib has no Set.union typings, so do it by hand)
const a = new Set(["INFY", "TCS", "SBIN"]);
const b = new Set(["TCS", "WIPRO"]);
console.log(`common: ${[...a].filter((s) => b.has(s)).join(",")}`);
```

```text
cannot sell 6 TCS, holding 5
U1 positions=[TCS:5] watch=[HDFCBANK,SBIN]
{"U1":[{"symbol":"TCS","qty":5}]}
common: TCS
```

Tips:

- `JSON.stringify(map)` gives `{}`. That is why the store defines `toJSON()`.
- Object keys in a `Map` are compared by **reference**, not by value. `map.get({ id: 1 })` never finds an entry stored with a different object. Use a string/number key.
- Never hand out the inner `Map` from a class; return copies or read-only views.
