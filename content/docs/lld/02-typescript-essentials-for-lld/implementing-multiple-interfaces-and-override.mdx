## Capability interfaces

Small, focused interfaces (Interface Segregation from SOLID) can be combined freely.

```ts
interface Identifiable { readonly id: string }
interface Cancellable { cancel(reason: string): void }
interface Auditable { history(): readonly string[] }

class LimitOrder implements Identifiable, Cancellable, Auditable {
  private readonly log: string[] = [];
  private cancelled = false;

  constructor(public readonly id: string, public readonly pricePaise: number) {
    this.log.push(`created @${pricePaise}`);
  }

  cancel(reason: string): void {
    if (this.cancelled) throw new Error(`${this.id} already cancelled`);
    this.cancelled = true;
    this.log.push(`cancelled: ${reason}`);
  }

  history(): readonly string[] {
    return [...this.log];
  }
}

// Functions depend only on the capability they need
function cancelAll(items: Cancellable[], reason: string): void {
  for (const i of items) i.cancel(reason);
}
function printAudit(x: Identifiable & Auditable): void {
  console.log(`${x.id}: ${x.history().join(" | ")}`);
}

const o = new LimitOrder("O-1", 152_000);
cancelAll([o], "user request");
printAudit(o);
try {
  o.cancel("again");
} catch (err) {
  if (err instanceof Error) console.log(err.message);
}
```

```text
O-1: created @152000 | cancelled: user request
O-1 already cancelled
```

Note that `implements` **does not add anything** to the class. It only asks the compiler to check the class against the interface. The parameter types of methods are not inferred from the interface either; you still write them.

## The `override` keyword

With `noImplicitOverride` on (strongly recommended, and on in this book), every method that replaces a parent method must say `override`. This protects you from two silent bugs:

```ts
class Notifier {
  send(msg: string): string { return `base: ${msg}`; }
}

class SmsNotifier extends Notifier {
  send(msg: string): string { return `sms: ${msg}`; }
  // ❌ error: This member must have an 'override' modifier because it overrides a member in base class 'Notifier'.
}

class EmailNotifier extends Notifier {
  override sendd(msg: string): string { return `email: ${msg}`; }
  // ❌ error: This member cannot have an 'override' modifier because it is not declared in the base class 'Notifier'.
}
```

The second error is the valuable one: a typo or a renamed base method would otherwise leave you with a new, never-called method.

```ts
class Notifier {
  send(msg: string): string { return `base: ${msg}`; }
  protected prefix(): string { return "[N]"; }
}

class SmsNotifier extends Notifier {
  override send(msg: string): string {
    return `${this.prefix()} sms: ${super.send(msg)}`;
  }
  protected override prefix(): string { return "[SMS]"; }
}

const n: Notifier = new SmsNotifier();
console.log(n.send("order filled"));
```

```text
[SMS] sms: base: order filled
```
