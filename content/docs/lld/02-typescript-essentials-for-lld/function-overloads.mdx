---
title: "2.14 Function overloads"
---

Overloads give one function several typed call signatures when the **return type depends on the arguments** in a way a union can't express.

```ts
interface Order { id: string; symbol: string }

class OrderQuery {
  private readonly orders: Order[] = [
    { id: "O-1", symbol: "INFY" },
    { id: "O-2", symbol: "TCS" },
  ];

  // Overload signatures (what callers see)
  find(id: string): Order | undefined;
  find(ids: readonly string[]): Order[];
  // Implementation signature (not visible to callers)
  find(idOrIds: string | readonly string[]): Order | undefined | Order[] {
    if (typeof idOrIds === "string") return this.orders.find((o) => o.id === idOrIds);
    return this.orders.filter((o) => idOrIds.includes(o.id));
  }
}

const q = new OrderQuery();
const one = q.find("O-2");          // type: Order | undefined
const many = q.find(["O-1", "O-2"]); // type: Order[]
console.log(`${one?.symbol} | ${many.map((o) => o.symbol).join(",")}`);
```

```text
TCS | INFY,TCS
```

Rules:

- The implementation signature must be compatible with all overloads, and it is **not callable** directly.
- Order overloads from most specific to least specific.
- If the return type is the same for all inputs, **use a union parameter instead**; overloads are overkill. In an interview, separate methods with clear names (`findById`, `findByIds`) are often even better.
