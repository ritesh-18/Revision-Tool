## What LLD interviews actually test

A Low-Level Design round checks whether you can turn a loosely worded problem ("design a parking lot", "design a stock exchange") into **clean, extensible, working object-oriented code**. It comes in two formats:

| Format | Typical duration | What you produce | Where it's common |
|---|---|---|---|
| **Discussion / whiteboard LLD** | 45–60 min | Requirements, entities, class diagram, key interfaces, a few core methods, extension discussion | Amazon, Microsoft, Angel One (reported), many SDE-2 loops |
| **Machine coding** | 90–120 min (+ code review) | A **working, in-memory application** with a demo driver, handling edge cases, then a walkthrough | Flipkart, PhonePe, Razorpay, Swiggy, Uber, Groww, CRED, Meesho, Atlassian (code design) |

Interviewers grade roughly the same things in both formats:
- **Clarity:** did you clarify requirements and scope?
- **Modelling:** are the entities right, with sensible responsibilities?
- **Design principles:** SOLID, low coupling, high cohesion, patterns used only where they help.
- **Extensibility:** can a new vehicle type, pricing rule or channel be added without rewriting code?
- **Correctness:** validation, errors, edge cases.
- **Concurrency awareness:** what happens when two users book the last seat? (This is what separates SDE-2 from SDE-1.)
- **Code quality:** naming, small classes, readability, and a runnable demo or tests.
- **Communication:** trade-offs explained, follow-ups handled.

## How each case study is structured

Every problem in §9–§14 follows the same flow, which is also a good order to follow in the interview itself:

1. **Clarify:** questions and assumptions.
2. **Requirements:** functional, non-functional, and what's out of scope.
3. **Model:** entities, relationships, class diagram.
4. **Design:** the patterns chosen and why, plus the alternatives that were rejected.
5. **Implement:** complete, runnable TypeScript, built up in explained parts.
6. **Demo:** the real output.
7. **Harden:** concurrency, failure handling, edge cases.
8. **Extend:** the follow-ups interviewers ask, and how the design absorbs them.
9. **Reflect:** complexity, what graders look for, a 90-minute plan, and interview Q&A.

**How to study a case study:**
1. Read only the problem and requirements.
2. **Close the book and design it yourself.** Draw the class diagram and write the code with a 90-minute timer.
3. Compare your version with the book's: entities, patterns, edge cases, concurrency.
4. Re-implement one extension without looking.

## Running the code yourself

You already have Node 24 and TypeScript installed globally. Save any runnable block as `demo.ts`, then:

```bash
node --experimental-transform-types demo.ts
```

To type-check with the same strictness this book used:

```bash
tsc --strict --noEmit --target es2024 --lib es2024,dom demo.ts
```

Notes:
- `--experimental-transform-types` lets Node run TypeScript-only syntax such as `enum` and constructor parameter properties. Plain type annotations work even without the flag.
- Some programs are split across several code blocks with explanations in between. Paste all of a problem's implementation blocks, in order, into one file.
- **Mermaid diagrams:**
  - GitHub renders them automatically.
  - In VS Code, install the *Markdown Preview Mermaid Support* extension, then open the preview (`Ctrl+Shift+V`).
  - Anywhere else, paste a diagram into mermaid.live.
- The examples avoid `Date.now()` and `Math.random()`: time, IDs and randomness are **injected**, so every output is repeatable and testable. That's a habit worth showing in interviews too.

## Conventions used in this book

- **Money is stored as integer paise** (₹1 = 100 paise), never as floating-point rupees.
- **`// ❌`** marks an intentionally bad example (not meant to compile or run). **`// ✅`** marks the recommended version.
- Interview answers are hidden inside expandable blocks. Try answering before you open them.
- "Reported at X" means a public interview write-up mentions it. "(uncertain)" means there was only a single or indirect source.
