title: "14. Case Studies — Level 3 (SDE-2): Trading & Social Systems"
---

The Level 1 and Level 2 case studies taught you to model entities, pick patterns, and keep code clean. Level 3 raises the stakes. At a stockbroker, a bug does not just show the wrong page. It can fill an order twice, let someone spend the same ₹50,000 twice, or put a trade ahead of an order that arrived first. An interviewer at Angel One, Groww, Zerodha or Upstox is really asking one thing: **can I trust this engineer with code that touches money?**

Three things set these rounds apart:

1. **Correctness with money.** You use integer paise, never floats. Money is blocked before an order goes out and released only after it resolves. Every state change is explicit and checked.
2. **Ordering.** Price-time priority is how an exchange stays fair. A feed that shows tweets in the wrong order is a bug users notice. You need to know which data structure keeps order cheaply: a heap, sorted levels, or FIFO queues.
3. **Concurrency.** Two orders from the same user can arrive in the same millisecond, and a double tap can send the same order twice. An SDE-2 candidate should be able to name the race, show it happening, and fix it with a single-writer queue, a per-key lock or an idempotency key.
