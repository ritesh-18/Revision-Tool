---
title: "16.6 Practice problems (no solutions)"
---

These 30 problems are **not solved in this book**. Each has a spec you can build in 90 minutes, follow-ups to prepare for, suggested entities, and hints. Treat them as mock rounds: set a timer, write the code in TypeScript, run your own demo scenarios, then review yourself against the checklist in §16.7.

Difficulty: **★** basic · **★★** intermediate · **★★★** SDE-2.

## P1. Flight booking (Flipkart SDE-2, Apr '25 [snippet]) — ★★

- **Functional:** airlines register flights (from, to, departure, price, seats, meal available); search flights between two cities; return the route with the **fewest hops** or the **lowest total cost**; optional filter "meal on every leg"; book seats on a route.
- **Follow-ups:** a maximum number of layovers; minimum connection time between legs; cancellation that frees seats on all legs atomically.
- **Entities:** `Airline`, `Flight`, `Route` (list of flights), `Booking`, `Passenger`, `FlightRepository`, `SearchService`.
- **Hints:** a `RouteSearchStrategy` interface with BFS (fewest hops) and Dijkstra (cheapest) implementations; filters as Specifications applied while traversing; reserve seats on all legs or none (check first, then commit).

## P2. Music streaming (Groww SDE-2 [snippet], Salesforce '26) — ★★

- **Functional:** add, update and search songs (by title prefix, artist, album); users create playlists; each user has an **independent playback session** (play, pause, next, previous, queue).
- **Follow-ups:** shuffle and repeat modes; "recently played" (last 10); top songs by play count.
- **Entities:** `Song`, `Artist`, `Album`, `Playlist`, `User`, `PlaybackSession`, `CatalogService`.
- **Hints:** a Strategy for next-song selection (sequential, shuffle, repeat-one); State for the player (playing/paused/stopped); a bounded deque for recents; an index map per search field.

## P3. Hotel booking (Swiggy SDE-2, Paytm [snippet]) — ★★

- **Functional:** hotels with room types and inventory; search availability by city and date range; book N rooms; cancel with a refund policy.
- **Follow-ups:** prevent double booking under concurrency; dynamic pricing on weekends; idempotent booking retries (Paytm).
- **Entities:** `Hotel`, `RoomType`, `Room`, `Booking`, `DateRange`, `PricingStrategy`, `CancellationPolicy`.
- **Hints:** availability per room type per night (a map `date → count`); book = check every night then decrement every night inside one critical section; refund as a Strategy.

## P4. Gym class booking (PhonePe SDE-1 Jul '25, Flipkart, Meesho) — ★★

- **Functional:** tiers Platinum, Gold and Silver with different booking limits; admin creates classes (type, time, capacity); users book; a FIFO waitlist when a class is full; cancellation allowed until 30 minutes before start; must be thread-safe.
- **Follow-ups:** promote from the waitlist on cancel and notify; tier-specific early access; recurring classes.
- **Entities:** `User`, `Tier`, `GymClass`, `Booking`, `Waitlist`, `BookingService`, `Clock`.
- **Hints:** tier rules as a Strategy / policy map; a per-class keyed mutex; waitlist promotion in the same critical section as cancellation; inject the clock for the 30-minute rule.

## P5. Git-lite version control (Razorpay) — ★★★

- **Functional:** `init`, `add(path, content)`, `commit(message)`, `log`, `branch(name)`, `checkout(name)`, `diff(commitA, commitB)`.
- **Follow-ups:** `merge` with conflict detection (same file changed on both sides); `revert`; storage deduplication.
- **Entities:** `Repository`, `Blob` (content-addressed), `Tree`/`Snapshot`, `Commit` (parent pointers), `Branch` (named pointer), `HEAD`, `StagingArea`.
- **Hints:** commits are immutable and point to a snapshot map `path → blobId`; branches are just refs; merge base = lowest common ancestor on the commit graph; Command pattern for CLI verbs.

## P6. Payment ledger (double-entry) (Razorpay, low-reliability source) — ★★★

- **Functional:** accounts (merchant, customer, fees, escrow); post a transaction as balanced debit/credit entries; balance query; history per account.
- **Follow-ups:** idempotent posting; reversal (never delete); reconciliation against an external bank statement.
- **Entities:** `Account`, `JournalEntry` (immutable), `Transaction` (a set of entries that sum to zero), `Ledger`, `IdempotencyStore`.
- **Hints:** validate Σ debits = Σ credits before committing; amounts as `bigint` paise; balance = fold over entries (or a cached running balance updated atomically); reversal = a new transaction with the signs swapped.

## P7. Inventory management (Walmart '26) — ★★

- **Functional:** warehouses with SKU stock; add stock; **reserve** stock for an order (with expiry); confirm or release a reservation; transfer between warehouses.
- **Follow-ups:** low-stock alerts; pick the nearest warehouse that can fulfil the order; sync counts to a storefront.
- **Entities:** `Warehouse`, `Sku`, `StockItem` (onHand, reserved), `Reservation`, `InventoryService`.
- **Hints:** available = onHand − reserved; Observer for low-stock and sync events; Strategy for warehouse selection; optimistic locking with versions on `StockItem`.

## P8. Coupon / offer engine (Swiggy aggregator [snippet]; Paytm cashback [snippet]) — ★★

- **Functional:** define coupons with rules (min cart value, category, first order only, user tier, validity window, usage limit per user); list eligible coupons for a cart; apply the best one.
- **Follow-ups:** stackable vs exclusive coupons; cashback credited after delivery; a global budget cap per campaign.
- **Entities:** `Coupon`, `Rule` (Specification), `DiscountCalculator`, `Cart`, `UsageTracker`.
- **Hints:** `And`/`Or`/`Not` composite rules; Strategy for discount types (flat, percent with cap, BOGO); return *why* a coupon is ineligible.

## P9. Shopping cart with offers / checkout (Upstox SDE-2 [snippet], Goldman '26) — ★★

- **Functional:** add and remove items; quantity limits; price the cart with offers (buy 2 get 1, bundle price); checkout creates an order; order states.
- **Follow-ups:** price changed between add-to-cart and checkout; stock reservation at checkout; payment failure rollback.
- **Entities:** `Product`, `Cart`, `CartItem`, `Offer`, `PriceCalculator`, `Order`, `OrderStateMachine`.
- **Hints:** a pricing pipeline (Chain of Responsibility: base → item offers → cart offers → tax); State for the order; snapshot prices into the order.

## P10. Cricket scoreboard (Cricinfo) — ★★

- **Functional:** teams and players; record ball-by-ball events (runs, wide, no-ball, wicket); show the live scorecard (runs, wickets, overs, batter and bowler stats); switch innings; decide the result.
- **Follow-ups:** undo the last ball; different formats (T20, ODI) with different overs; live subscribers.
- **Entities:** `Match`, `Innings`, `Over`, `Ball` (event), `Team`, `Player`, `BattingStats`, `BowlingStats`.
- **Hints:** event-sourced ball log, with stats derived from events (undo = pop the event); Strategy for format rules; Observer for live updates; careful extras logic (a wide doesn't count as a ball).

## P11. Car parking with EV charging — ★★

- **Functional:** a parking lot with regular and EV spots; EV spots have chargers with power levels; charge a parking fee plus an energy fee; charger states (free, charging, faulty).
- **Follow-ups:** reserve an EV spot in advance; idle fee after charging completes; load balancing across chargers.
- **Entities:** `ParkingLot`, `Spot`, `Charger`, `ChargingSession`, `Ticket`, `FeeCalculator`.
- **Hints:** reuse your §9 Parking Lot and extend it without edits (the real test); State for chargers; composite fee = parking Strategy + energy Strategy.

## P12. Online auction — ★★

- **Functional:** sellers list items with a reserve price and end time; buyers place bids (must beat the current highest by a minimum increment); the auction closes at the end time and the winner is declared.
- **Follow-ups:** proxy (automatic) bidding up to a maximum; anti-sniping (extend the end time on late bids); concurrent bids.
- **Entities:** `Auction`, `Item`, `Bid`, `User`, `AuctionService`, `Clock`, `Scheduler`.
- **Hints:** State (scheduled → live → closed); Observer to notify outbid users; per-auction lock for bids; injected clock plus a scheduler to close auctions.

## P13. Online voting / poll system — ★

- **Functional:** create polls with options and a deadline; users vote once (or up to K choices); live results; close the poll.
- **Follow-ups:** anonymous vs identified voting; ranked-choice counting; changing your vote before the deadline.
- **Entities:** `Poll`, `Option`, `Vote`, `User`, `PollService`, `CountingStrategy`.
- **Hints:** one-vote invariant via a set of `(pollId, userId)`; Strategy for counting (plurality, ranked choice); result caching.

## P14. URL shortener (LLD view) (Microsoft SDE-2 [snippet], Goldman '26, Razorpay) — ★★

- **Functional:** shorten a long URL (optional custom alias); resolve a short code; expiry; click count.
- **Follow-ups:** a different ID-generation scheme; per-user quotas; analytics by day.
- **Entities:** `ShortLink`, `IdGenerator`, `LinkRepository`, `ShortenerService`, `ClickCounter`.
- **Hints:** `IdGenerator` Strategy (counter + base62, hash + collision check, random with retry); alias collisions; lazy expiry on read.

## P15. Traffic signal controller (Goldman '26) — ★

- **Functional:** an intersection with 4 approaches; cycle through green, yellow and red with configurable durations; conflicting directions must never be green together.
- **Follow-ups:** pedestrian button; emergency vehicle override; timing that adapts to queue length.
- **Entities:** `Intersection`, `Signal`, `Phase`, `Controller`, `TimingStrategy`, `Clock`.
- **Hints:** State pattern for phases; an invariant check on every transition; Strategy for timing; a tick-driven simulation with a fake clock.

## P16. Restaurant table reservation (PhonePe [snippet], Walmart) — ★★

- **Functional:** `registerRestaurant` (city, cuisine, tables with sizes, opening hours); `searchRestaurant` (city, cuisine, name prefix, rating); `bookTable(restaurant, party size, slot)`; cancel.
- **Follow-ups:** best-fit table selection (smallest table that fits); combining tables; no-show policy.
- **Entities:** `Restaurant`, `Table`, `Slot`, `Reservation`, `SearchService`, `TableAllocationStrategy`.
- **Hints:** Specification filters for search; availability map `(table, slot) → reservation`; Strategy for table choice.

## P17. Learning management system (with course registration) (Flipkart course registration) — ★★

- **Follow-ups:** prerequisites; drop deadline; instructor dashboards.
- **Entities:** `Course`, `Lesson`, `Enrollment`, `Student`, `Instructor`, `Waitlist`, `ProgressTracker`.

## P18. Personal expense tracker — ★

- **Functional:** add expenses with category, amount and date; monthly budgets per category; reports (total by category, by month); alert when a budget is exceeded.
- **Follow-ups:** recurring expenses; multiple currencies; CSV export.
- **Entities:** `Expense`, `Category`, `Budget`, `Report`, `ExpenseRepository`, `AlertService`.
- **Hints:** Observer for budget alerts; Strategy for report grouping; integer paise.

## P19. Key-value store with transactions (Razorpay in-memory DB variant) — ★★★

- **Functional:** `set`, `get`, `delete`, `count(value)`; `begin`, `commit`, `rollback` with **nested** transactions.
- **Follow-ups:** TTL per key; typed values; snapshot reads while another transaction writes.
- **Entities:** `Store`, `Transaction` (a layer of changes), `TransactionStack`, `Command` parser.
- **Hints:** a stack of change maps (a tombstone for delete); reads go top-down through the stack; commit merges into the parent; keep a `value → count` index updated incrementally.

## P20. Spreadsheet (and Excel-like autofill, Microsoft '26) — ★★★

- **Functional:** set a cell to a number or a formula (`=A1+B2`, `=SUM(A1:A3)`); get a cell's value; update dependents when a cell changes; detect cycles.
- **Follow-ups:** autofill a pattern (1, 2, 3 → 4, 5; Mon, Tue → Wed); undo; new functions.
- **Entities:** `Sheet`, `Cell`, `Formula` (AST), `DependencyGraph`, `Evaluator`, `FunctionRegistry`.
- **Hints:** Interpreter for formulas; a DAG plus topological recomputation (reuse your §13 DAG thinking); a Strategy per autofill pattern detector; a Command for undo.

## P21. Calendar with recurring events (Salesforce '26, Uber "My Calendar" [snippet]) — ★★

- **Functional:** create events (one-off or recurring); invite attendees; accept or decline; find free slots for a set of users; detect conflicts.
- **Follow-ups:** edit "this and following" occurrences; time zones; room booking integration.
- **Entities:** `Event`, `RecurrenceRule`, `Occurrence`, `Attendee`, `Calendar`, `AvailabilityService`.
- **Hints:** expand occurrences within a window; merge busy intervals to find free slots; overrides keyed by the occurrence date (see S9).

## P22. Chat app / group chat (Groww SDE-2 [snippet]) — ★★

- **Functional:** 1:1 and group chats; send messages; unread counts; limits: max groups per admin, max group memberships per user; admin adds or removes members.
- **Follow-ups:** read receipts; message edit and delete; mute a group.
- **Entities:** `User`, `Conversation`, `Group`, `Membership`, `Message`, `ChatService`.
- **Hints:** Mediator (a conversation delivers to members); an explicit `Membership` entity for the limits; a per-user last-read pointer for unread counts.

## P23. Document permissions / ACL (Google-Docs-like sharing) — ★★

- **Functional:** users, groups, documents in folders; roles owner, editor, commenter, viewer; share with a user or group; permissions inherited from folders; `canEdit(user, doc)`.
- **Follow-ups:** link sharing ("anyone with link can view"); expiring shares; an audit log of access changes.
- **Entities:** `Principal` (user/group), `Resource` (folder/doc, Composite), `Role`, `Grant`, `AccessEvaluator`.
- **Hints:** role hierarchy as an ordered list; effective permission = max over direct grants + group grants + inherited grants; Chain of Responsibility or Specification for evaluation; cache with invalidation on grant changes.

## P24. Circuit breaker library — ★★

- **Functional:** wrap an async function; states CLOSED, OPEN and HALF_OPEN; open after N failures (or a failure rate over a window); after a cooldown, allow trial calls; close on success.
- **Follow-ups:** per-endpoint breakers; a fallback function; metrics and event hooks.
- **Entities:** `CircuitBreaker`, `BreakerState` (State pattern), `FailurePolicy`, `Clock`, `BreakerRegistry`.
- **Hints:** §7.10 explains the pattern. The practice is to package it as a reusable, generic, well-tested library with an injected clock and exhaustive state-transition tests.

## P25. Retry library — ★★

- **Functional:** `retry(fn, options)` with max attempts, backoff (fixed, exponential, exponential with full jitter), a retryable-error predicate, and an overall timeout.
- **Follow-ups:** cancellation via `AbortSignal`; a retry budget shared across calls; composition with the circuit breaker.
- **Entities:** `RetryPolicy`, `BackoffStrategy`, `Sleeper` (injectable), `RetryContext`.
- **Hints:** Strategy for backoff; inject randomness and the sleeper so tests are deterministic; never retry non-idempotent operations without a key.

## P26. Customer support ticketing (Atlassian P40, Aug '25) — ★★

- **Functional:** customers raise tickets (type, priority); agents with skills; auto-assign tickets to available agents; resolve; customers rate agents; leaderboard of agents by rating.
- **Follow-ups:** a different assignment strategy (round robin, least loaded, skill match); SLA breach escalation; reopening.
- **Entities:** `Ticket`, `Agent`, `Customer`, `Assignment`, `AssignmentStrategy`, `RatingBoard`.
- **Hints:** State for the ticket; Strategy for assignment; average rating kept as (sum, count); ties broken deterministically. Tests are expected (Atlassian).

## P27. Price alerts and trailing stop-loss (Upstox SDE-2 [snippet]) — ★★★

- **Functional:** users set price alerts (above/below) per symbol; a trailing stop-loss order follows the market up by a fixed amount or percentage and triggers a sell when the price falls to the trail level; a price tick stream feeds the system.
- **Follow-ups:** out-of-order ticks; exactly-once triggering; thousands of alerts per symbol.
- **Entities:** `PriceTick`, `Alert`, `TrailingStopOrder`, `AlertBook` (per symbol), `OrderService`, `Notifier`.
- **Hints:** Observer on ticks; heaps per symbol for above/below alerts; the trailing order's high-water mark only ever increases; mark it triggered before calling the order service.

## P28. Train–platform scheduling (Uber SDE-2 [snippet]) — ★★★

- **Functional:** a station with P platforms; trains with arrival and departure times; assign each train a platform; if none is free, the train waits in a queue; query which train is on a platform at time t.
- **Follow-ups:** delays that shift a schedule; platform preferences by train type; concurrent arrivals.
- **Entities:** `Station`, `Platform`, `Train`, `Assignment`, `Scheduler`, `WaitQueue`.
- **Hints:** a min-heap of platform free times; a sorted interval list per platform for time queries; a demoable concurrent version with an async queue and one lock.

## P29. Bank payout controller (Meesho [snippet]) — ★★★

- **Functional:** pay merchants through 3 banks; each bank has its own limits, fees and success rates; route each payout; retry on failure with a different bank; track payout status.
- **Follow-ups:** a bank outage (circuit breaker); daily limits per bank; idempotent payout API.
- **Entities:** `Payout`, `Bank` (adapter), `RoutingStrategy`, `PayoutService`, `RetryPolicy`, `IdempotencyStore`.
- **Hints:** Adapter per bank; Strategy for routing (cheapest, highest success rate); a fallback chain; State for the payout (initiated → processing → success/failed).

## P30. App version management / staged rollouts (PhonePe Sep '25) — ★★

- **Functional:** upload app versions with minimum OS/device support; define a rollout (percentage, beta users, region); `checkForUpdate(device)` returns the right version; mandatory vs optional updates.
- **Follow-ups:** halt a rollout; roll back; A/B two versions.
- **Entities:** `AppVersion`, `Device`, `RolloutPlan`, `RolloutStrategy`, `CompatibilityChecker`, `UpdateService`.
- **Hints:** Strategy per rollout type; deterministic bucketing (hash of deviceId mod 100), never random per call; a Specification for compatibility.
