title: "6.9 Memento"

## Intent

Capture an object's internal state as a snapshot so that it can be restored later, **without exposing that state** to the code that stores the snapshot.

## Problem

The order-notes editor in your trading terminal needs **undo/redo**. The editor state is more than text: it includes the cursor position (and in real editors, selection, formatting, and so on). You could have an undo manager read and write the editor's fields directly, but then the undo manager is coupled to the editor's internals, and any code holding a snapshot could tamper with it.

The three roles are:

- **Originator** (`Editor`): creates snapshots and is the only one who can read them.
- **Memento** (`Snapshot`): an opaque token.
- **Caretaker** (`History`): decides *when* to save and restore, but can't look inside.

## TypeScript implementation

TypeScript has no "friend" classes, so how do we keep the snapshot opaque? One clean trick: the snapshot object exposes only metadata, and the real state lives in a **module-private `WeakMap`** that only the editor uses. When a snapshot is garbage-collected, its entry disappears too.

```ts
interface EditorState {
  text: string;
  cursor: number;
}

// The memento: only harmless metadata is visible.
class Snapshot {
  constructor(readonly label: string, readonly version: number) {}
}

// Private to this module: only Editor reads and writes it.
const vault = new WeakMap<Snapshot, EditorState>();

class Editor {
  private state: EditorState = { text: '', cursor: 0 };
  private version = 0;

  type(s: string): void {
    const { text, cursor } = this.state;
    this.state = { text: text.slice(0, cursor) + s + text.slice(cursor), cursor: cursor + s.length };
  }

  moveTo(pos: number): void {
    this.state.cursor = Math.max(0, Math.min(pos, this.state.text.length));
  }

  save(label: string): Snapshot {
    const snap = new Snapshot(label, ++this.version);
    vault.set(snap, structuredClone(this.state)); // deep copy: later edits can't change the snapshot
    return snap;
  }

  restore(snap: Snapshot): void {
    const saved = vault.get(snap);
    if (!saved) throw new Error(`unknown snapshot ${snap.label}`);
    this.state = structuredClone(saved);
  }

  render(): string {
    return `text="${this.state.text}" cursor=${this.state.cursor}`;
  }
}

// Caretaker: stores snapshots, never inspects them.
class History {
  private undoStack: Snapshot[] = [];
  private redoStack: Snapshot[] = [];

  constructor(private readonly editor: Editor, private readonly limit = 50) {}

  /** Call before every change. */
  checkpoint(label: string): void {
    this.undoStack.push(this.editor.save(label));
    if (this.undoStack.length > this.limit) this.undoStack.shift();
    this.redoStack.length = 0;
  }

  undo(): void {
    const snap = this.undoStack.pop();
    if (!snap) return console.log('nothing to undo');
    this.redoStack.push(this.editor.save(`redo of ${snap.label}`));
    this.editor.restore(snap);
    console.log(`undo "${snap.label}" -> ${this.editor.render()}`);
  }

  redo(): void {
    const snap = this.redoStack.pop();
    if (!snap) return console.log('nothing to redo');
    this.undoStack.push(this.editor.save(`undo of ${snap.label}`));
    this.editor.restore(snap);
    console.log(`redo -> ${this.editor.render()}`);
  }

  get depth(): number {
    return this.undoStack.length;
  }
}

const editor = new Editor();
const history = new History(editor);

history.checkpoint('type Buy INFY');
editor.type('Buy INFY');
history.checkpoint('type qty');
editor.type(' 10');
history.checkpoint('prefix AMO');
editor.moveTo(0);
editor.type('AMO ');
console.log(`now  -> ${editor.render()}`);

history.undo();
history.undo();
history.redo();

history.checkpoint('type price');
editor.type('@1500');
console.log(`now  -> ${editor.render()}`);
history.redo();
console.log(`undo depth: ${history.depth}`);

try {
  editor.restore(new Snapshot('forged', 99));
} catch (err) {
  console.log(`error: ${(err as Error).message}`);
}
```

```text
now  -> text="AMO Buy INFY 10" cursor=4
undo "prefix AMO" -> text="Buy INFY 10" cursor=11
undo "type qty" -> text="Buy INFY" cursor=8
redo -> text="Buy INFY 10" cursor=11
now  -> text="Buy INFY 10@1500" cursor=16
nothing to redo
undo depth: 3
error: unknown snapshot forged
```

A forged snapshot is rejected because only the editor's `vault` knows real ones. Other options for opacity are `#private` fields with a static accessor, or simply exporting only a type with no readable fields (`type Snapshot = { readonly __brand: unique symbol }`).

## When to use / when NOT to use

**Use it when**
- You need undo, checkpoints, or "rollback to last good state", and the state is easier to *copy* than to *invert*.
- Encapsulation matters: callers shouldn't read or modify internals.

**Don't use it when**
- The state is huge (a 50 MB document). Full snapshots eat memory, so store diffs or use Command with inverse operations.
- A simple inverse operation exists (`qty 10 → 25` can be undone by setting it back to 10). Command alone is lighter.

## Pitfalls

- **Shallow copies.** `{ ...state }` shares nested arrays and objects, so a later edit silently mutates the snapshot. Use `structuredClone` or immutable updates.
- **Unbounded memory.** Cap the history (`limit`) or use diff-based snapshots.
- **Snapshots of references to external resources** (open sockets, DB connections) can't be restored meaningfully.
- **Versioning.** Persisted snapshots break when the state shape changes. Add a schema version.

## Related patterns

- **Memento + Command.** A command saves a memento before executing and restores it on undo. This is the easy path when an inverse is hard to write.
- **Memento vs Prototype.** Both copy state. A prototype creates a new *usable object*, while a memento is an *opaque snapshot* for restoring the same object.
- **Event sourcing** is the "store every change" alternative. State is rebuilt by replaying events, and periodic snapshots (mementos!) speed it up.
- Redux DevTools time-travel is mementos of immutable state.

## Where it shows up in LLD interview problems

- **Text editor / notepad undo-redo.**
- **Games:** save points / checkpoints.
- **Form wizards:** "back" restores the previous step's state.
- **Configuration management:** rollback to the last known good config.
- **Chess:** undo a move (or use Command with inverse moves).

*How to say it:* "Editor state is small, so I'll snapshot it. The `Editor` creates opaque `Snapshot`s, and `History` holds two stacks without seeing inside. I deep-clone on save and restore, and cap history at 50 entries."

## Quick check

1. Who can read a memento's contents?
2. When is Command-with-inverse better than Memento?
3. Why `structuredClone` instead of spreading?

<details>
<summary>Answer</summary>

1. Only the originator (the editor). The caretaker just stores and hands back snapshots.
2. When state is large and each operation has a cheap, reliable inverse. Storing the inverse is much smaller than full snapshots.
3. Spread is shallow, so nested objects would be shared and later edits would corrupt the snapshot. `structuredClone` deep-copies.

</details>
