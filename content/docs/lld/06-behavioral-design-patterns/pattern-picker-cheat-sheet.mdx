---
title: "6.14 Pattern picker cheat sheet"
---

| If the interviewer's problem has... | Reach for | Say this |
|---|---|---|
| "Fee / price / discount rule varies by type or plan" | **Strategy** | "Pricing behind a `FeeStrategy`, picked from a registry." |
| "Split equally / exactly / by percentage" | **Strategy** | "`SplitStrategy` per split type, validated per strategy." |
| "Notify users when price crosses X / order is filled" | **Observer** (in-process) or **Pub/Sub** (across services) | "Typed events, and subscribers can unsubscribe." |
| "Undo / redo" | **Command** (+ **Memento** if inverses are hard) | "Two stacks. A new command clears redo." |
| "Queue requests, schedule them, retry them" | **Command** | "Requests are objects, so they can be queued and persisted." |
| "Machine with modes: idle, has money, dispensing" | **State** | "Each state is a class and illegal actions throw." |
| "Lifecycle with allowed transitions only" | **State** (table-driven) | "Transition table typed with `Record`." |
| "Series of checks, any can reject" | **Chain of Responsibility** | "Validators linked in one place, cheap checks first." |
| "Approval by amount: manager → director → CFO" | **Chain of Responsibility** | "Each approver handles within its limit, otherwise escalates." |
| "Dispense ₹2000/₹500/₹100 notes" | **Chain of Responsibility** | "Each note handler takes what it can and passes the rest." |
| "Same steps, different details per source/format" | **Template Method** (or Strategy for steps) | "Skeleton in the base class, `parse` per source." |
| "Iterate paginated / tree / huge data" | **Iterator** (generators, async generators) | "`for await` over an async generator hides the cursors." |
| "Many objects talking to each other" (chat, auction, ATC) | **Mediator** | "Colleagues only know the mediator, and rules live there." |
| "Save and restore state, checkpoints" | **Memento** | "Opaque snapshots, deep-cloned, capped history." |
| "New report or tax over fixed product types" | **Visitor** / **union + switch** | "Operations outside the types, exhaustive checking." |
| "Optional collaborator, lots of `if (x)` checks" | **Null Object** | "Neutral implementation chosen once at the boundary." |
| "User-defined rules like `price > 100 AND ...`" | **Interpreter** | "Parse once to an expression tree, then evaluate per event." |

> **Interview habit.** Name the pattern *after* you describe the problem, not before. "The fee depends on the plan and plans will keep changing, **so** I'll use a Strategy" sounds like design. "Let's use Strategy here" sounds like memorization.
