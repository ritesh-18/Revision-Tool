---
title: "6.13 Comparison of all behavioral patterns"
---

| Pattern | Question it answers | Core mechanism | TS-idiomatic form | Typical LLD use | Main risk |
|---|---|---|---|---|---|
| Strategy | *How* should this step be done? | Composition: context holds an interchangeable algorithm | Function type or interface + registry `Record<Key, Strategy>` | Parking fee, split rules, pricing, payment | The choice logic just moves elsewhere |
| Observer | *Who* needs to know when this happens? | Subject keeps a list of subscribers and notifies them | Typed event map + `on()` returning unsubscribe | Stock alerts, notifications | Leaks, hidden flow, cascades |
| Command | How do I store, queue, or undo a *request*? | Request as an object with `execute`/`undo` | Class per command, or serializable action objects | Undo in editors, AMO queue, remote control | Fake undo for irreversible actions |
| State | What am I *allowed* to do right now? | Context delegates to a current-state object that swaps itself | State classes, or a `Record<Status, Record<Action, Status>>` table | Vending machine, elevator, order lifecycle | Transitions scattered, races |
| Chain of Responsibility | *Who* should handle or reject this? | Linked handlers, each may stop or pass | Middleware `(ctx, next) => Promise<void>` | Pre-trade checks, ATM, approvals, logging | Request falls off the end, order bugs |
| Template Method | What's the *fixed skeleton*, and which steps vary? | Base class algorithm with abstract steps and hooks | Abstract class, or a function taking step functions | Importers, report generation | Fragile base class, no `final` |
| Iterator | How do I *walk* this without knowing its structure? | `next()` protocol | `[Symbol.iterator]`, generators, async generators | Pagination, trees, custom collections | One-shot generators, N+1 calls |
| Mediator | Who *coordinates* these peers? | Central object holds interaction rules | Class with colleague callbacks | Chat room, auction, ATC, matching engine | God object |
| Memento | How do I *snapshot and restore* without exposing internals? | Originator creates opaque snapshots, caretaker stores them | `WeakMap` vault + `structuredClone` | Editor undo, game checkpoints | Memory, shallow copies |
| Visitor | How do I add *operations* over a stable set of types? | Double dispatch via `accept(visitor)` | Discriminated union + exhaustive `switch` | Tax/fees per instrument, AST, file system | Adding a new type is expensive |
| Null Object | How do I avoid `null` checks for "nothing to do"? | Do-nothing implementation of the interface | Frozen constant + `?? NULL_X` | No-op logger, no discount, opted-out notifier | Hides real errors |
| Interpreter | How do I evaluate a *small language*? | Grammar rules become a composite tree with `evaluate` | Recursive-descent parser + expression classes or union | Alert rules, calculators, filters | Grammar grows beyond hand-written code |

**Look-alikes, side by side**

| Pair | The one-line difference |
|---|---|
| Strategy vs State | Client picks the strategy. States replace each other. |
| Strategy vs Template Method | Composition and runtime swap vs inheritance and fixed skeleton. |
| Command vs Strategy | A specific request that can be stored or undone vs an interchangeable algorithm. |
| Observer vs Mediator | Broadcast to unknown listeners vs coordination with rules among known peers. |
| Observer vs Pub/Sub | Subscribers attach to the subject vs a broker/topic decouples both sides (often async, distributed). |
| Chain of Responsibility vs Decorator | May stop the request vs always delegates and adds behavior. |
| Memento vs Command undo | Snapshot the state vs store the inverse operation. |
| Visitor vs union `switch` | Classes with double dispatch vs data with exhaustive narrowing. Same "new operation is cheap" property. |
| Iterator vs Observable | Pull (consumer asks) vs push (producer sends). |
