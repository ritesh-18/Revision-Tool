## Chapter recap

Six case studies, four recurring skills:

1. **Pick the right data structure and say why.** The leaderboard chose a sorted array + hash map over a heap because it needed rank lookups and updates, not only top-K. The rental service chose per-vehicle booking lists over a global calendar because overlap queries are per vehicle. Always name the trade-off.

2. **Model the lifecycle explicitly.** The ATM's `State` pattern and the FlipMed booking's `Confirmed → Cancelled → (Promoted)` path both encode the rules about what is allowed when. A free-floating `status` string with unchecked transitions is a bug waiting to happen.

3. **Recursive structures.** The file system's `Composite` pattern collapsed `du`, `find` and `tree` into three lines of recursion each. The ATM's `CashDispenser` walked a list of denominations in order — the same Chain of Responsibility idea. When you see a "part–whole hierarchy", reach for Composite.

4. **Correctness under concurrent requests.** Every problem had a race condition buried in it: the leaderboard's lost update, FlipMed's double booking, the file system's torn `du`, the ATM's concurrent debit, the rental's double hold. The patterns are always the same: claim a resource atomically before you `await`, use the store's own atomic operation (`ZINCRBY`, `SET NX`, `UPDATE … WHERE`), or add a readers-writer lock.

**Patterns used across this chapter:**

| Pattern | Where |
|---|---|
| Strategy | Leaderboard scoring, FlipMed ranking, Vehicle Rental pricing |
| Observer | FlipMed notifications |
| Composite | File System nodes |
| Command + Memento | Text Editor commands |
| State | ATM lifecycle |
| Chain of Responsibility | ATM cash dispenser denominations |
| Decorator | Vehicle Rental surge pricing |
| Repository | FlipMed, Rental (thin data-access layer) |

## Practice exercises

1. **Leaderboard:** add a `Segment` concept (e.g. "Mumbai users") so `topK` can be scoped to a segment. Make `record` fan out to both the all-segment and per-segment boards in O(log N) each.

2. **FlipMed:** implement `MostPopularFirst` as a third ranking strategy. Add a `OFFERED` status to the waitlist (doctor sends an offer; patient has 15 minutes to accept before the slot goes to the next person).

3. **File System:** implement cached sizes so `du` is O(1) instead of O(subtree). Verify the invariant with a property test that compares the cached result against the recursive result.

4. **Text Editor:** group three commands into a single undoable `MacroCommand` (e.g. "find and replace all" as one undo step). Verify that undoing the macro restores the exact original text.

5. **ATM:** add a `MaintenanceState` that rejects all user actions and can only be entered/exited by an admin. Implement a `timeout` that ejects the card after 30 seconds of inactivity using the injected `Clock`.

6. **Vehicle Rental:** add a `RefundPolicy` interface with `Full` (100 % refund before 24 h), `Partial` (50 % within 24 h) and `None` (no refund after start). Wire it into `cancelBooking` and return the refund amount.
