---
title: "8. How to Crack an LLD / Machine-Coding Round"
---

By now you know the principles and the patterns. This chapter is about the round itself: a fixed amount of time, a vague problem statement, an interviewer who is scoring you on a rubric you can't see, and a demo at the end that either runs or doesn't. Plenty of engineers who know SOLID cold still fail these rounds. They usually fail because of *process*, not knowledge: they skip clarification, over-design, run out of time with nothing that runs, or code in silence.

So treat this chapter as a playbook. It gives you a repeatable framework with time budgets, a project skeleton you can type from memory in five minutes, and a full worked example (a Library Management System) written as if you were solving it live, checkpoint by checkpoint.

**What you'll learn**

- The two round formats (whiteboard/discussion LLD and machine coding) and how Indian product companies run them
- A step-by-step framework with minute-by-minute budgets for a 60-minute and a 120-minute round
- A standard TypeScript project layout, naming conventions and a copy-paste starter kit (in-memory repository, error hierarchy, ID generator, clock)
- A complete worked example, *Library Management System*, told as a live interview: clarifying questions, entities, class diagram, runnable code, demo, tests and extensions
- How interviewers score you, and what "strong hire" and "no hire" submissions look like side by side
- The most common mistakes, and recovery tactics for when you're stuck or out of time
- How to present your code in the last 15–30 minutes, answer "how would you extend…?" questions, and talk about concurrency in TypeScript compared with Java
- A one-page checklist to print and pin above your desk
