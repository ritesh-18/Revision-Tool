When the clock starts, you don't want to be deciding folder names. Use the same layout every time:

```text
library-management/
├── src/
│   ├── enums/            member-tier.ts, copy-status.ts, hold-status.ts
│   ├── models/           book.ts, book-copy.ts, member.ts, loan.ts, hold.ts
│   ├── repositories/     in-memory.repository.ts, loan.repository.ts, ...
│   ├── services/         catalog.service.ts, loan.service.ts, hold.service.ts
│   ├── strategies/       fine/fine.strategy.ts, fine/per-day.fine.ts
│   ├── specifications/   specification.ts, book.specs.ts
│   ├── observers/        event-bus.ts, email.notifier.ts
│   ├── exceptions/       library.error.ts (base + subclasses)
│   ├── common/           clock.ts, id-generator.ts
│   ├── app.ts            composition root: wires repos + services
│   └── main.ts           driver / demo
├── test/                 loan.service.test.ts ...
├── package.json          "start": "tsx src/main.ts"
└── tsconfig.json         strict: true
```

Layering rules, which interviewers look for even if they never say so:

- **models** hold data plus invariants (a `BookCopy` refuses an illegal status change). No knowledge of repositories.
- **repositories** store and look up. No business rules.
- **services** orchestrate use cases: load entities, check rules, call strategies, save, publish events.
- **strategies / specifications / observers** are the plug-in points.
- **app.ts** is the only place that calls `new` on services. That's dependency inversion without a DI framework.
- **main.ts** only talks to services.

## 8.3.1 Naming conventions

| Thing | Convention | Example |
|---|---|---|
| Files | kebab-case with role suffix | `loan.service.ts`, `per-day.fine.ts` |
| Classes | PascalCase noun | `LoanService`, `BookCopy` |
| Interfaces | PascalCase, no `I` prefix, named by role | `FineStrategy`, `Clock`, `Repository<T>` |
| Implementations | Adjective + role | `PerDayFine`, `FakeClock`, `InMemoryRepository` |
| Enums | PascalCase type, PascalCase members, UPPER string values | `CopyStatus.OnLoan = 'ON_LOAN'` |
| Methods | verb phrase in the domain's language | `checkout`, `returnCopy`, `placeHold` |
| Booleans | `is/has/can` | `isActive`, `hasOutstandingFine` |
| Errors | `SomethingError`, plus a stable `code` | `LoanLimitError` / `LOAN_LIMIT` |
| Money | name the unit | `amountRupees`, `feePaise` |

## 8.3.2 The copy-paste starter kit

These pieces show up in almost every machine-coding problem. Practise typing them until it takes under five minutes. Two small decisions in here earn points:

- **Clock and IdGenerator are injected.** Your demo and tests become deterministic, and you can "fast-forward 17 days" to test fines without sleeping.
- **Errors carry a `code`.** A future HTTP layer can map codes to status codes without parsing messages.

```ts
// ---------- common/clock.ts ----------
const DAY_MS = 24 * 60 * 60 * 1000;

interface Clock {
  now(): Date;
}

class SystemClock implements Clock {
  now(): Date {
    return new Date();
  }
}

class FakeClock implements Clock {
  #ms: number;
  constructor(isoStart: string) {
    this.#ms = Date.parse(isoStart);
    if (Number.isNaN(this.#ms)) throw new RangeError(`Bad start date: ${isoStart}`);
  }
  now(): Date {
    return new Date(this.#ms);
  }
  advanceDays(days: number): void {
    this.#ms += days * DAY_MS;
  }
}

// ---------- common/id-generator.ts ----------
interface IdGenerator {
  next(prefix: string): string;
}

class SequentialIdGenerator implements IdGenerator {
  readonly #counters = new Map<string, number>();
  next(prefix: string): string {
    const n = (this.#counters.get(prefix) ?? 0) + 1;
    this.#counters.set(prefix, n);
    return `${prefix}-${n}`;
  }
}

// ---------- exceptions/app.error.ts ----------
class AppError extends Error {
  constructor(
    readonly code: string,
    message: string,
  ) {
    super(message);
    this.name = new.target.name;
  }
}

class ValidationError extends AppError {
  constructor(message: string) {
    super('VALIDATION', message);
  }
}

class NotFoundError extends AppError {
  constructor(entity: string, id: string) {
    super('NOT_FOUND', `${entity} ${id} not found`);
  }
}

class ConflictError extends AppError {
  constructor(message: string) {
    super('CONFLICT', message);
  }
}

// ---------- repositories/in-memory.repository.ts ----------
interface Entity {
  readonly id: string;
}

class InMemoryRepository<T extends Entity> {
  protected readonly items = new Map<string, T>();

  constructor(private readonly entityName: string) {}

  save(item: T): T {
    this.items.set(item.id, item);
    return item;
  }

  findById(id: string): T | undefined {
    return this.items.get(id);
  }

  getById(id: string): T {
    const item = this.items.get(id);
    if (!item) throw new NotFoundError(this.entityName, id);
    return item;
  }

  exists(id: string): boolean {
    return this.items.has(id);
  }

  findAll(): T[] {
    return [...this.items.values()];
  }

  findWhere(predicate: (item: T) => boolean): T[] {
    return this.findAll().filter(predicate);
  }

  delete(id: string): boolean {
    return this.items.delete(id);
  }
}

// ---------- common/validate.ts ----------
function requireNonEmpty(value: string, field: string): string {
  const trimmed = value.trim();
  if (!trimmed) throw new ValidationError(`${field} must not be empty`);
  return trimmed;
}

function requirePositiveInt(value: number, field: string): number {
  if (!Number.isInteger(value) || value <= 0) {
    throw new ValidationError(`${field} must be a positive integer, got ${value}`);
  }
  return value;
}

// ---------- quick smoke test of the kit ----------
class Tag implements Entity {
  constructor(
    readonly id: string,
    readonly label: string,
  ) {}
}

const ids = new SequentialIdGenerator();
const clock = new FakeClock('2026-01-01T00:00:00Z');
const tags = new InMemoryRepository<Tag>('Tag');

tags.save(new Tag(ids.next('TAG'), requireNonEmpty('  urgent ', 'label')));
tags.save(new Tag(ids.next('TAG'), 'later'));
console.log(`ids: ${tags.findAll().map((t) => `${t.id}=${t.label}`).join(', ')}`);

clock.advanceDays(3);
console.log(`clock: ${clock.now().toISOString().slice(0, 10)}`);

for (const action of [
  () => tags.getById('TAG-9'),
  () => requirePositiveInt(0, 'quantity'),
  () => requireNonEmpty('   ', 'title'),
]) {
  try {
    action();
  } catch (err) {
    if (err instanceof AppError) console.log(`${err.name} [${err.code}] ${err.message}`);
    else throw err;
  }
}
console.log(`real clock available: ${new SystemClock() instanceof Object}`);
```

```text
ids: TAG-1=urgent, TAG-2=later
clock: 2026-01-04
NotFoundError [NOT_FOUND] Tag TAG-9 not found
ValidationError [VALIDATION] quantity must be a positive integer, got 0
ValidationError [VALIDATION] title must not be empty
real clock available: true
```

A few notes on the kit:

- `this.name = new.target.name` means every subclass reports its own name automatically, so `LoanLimitError` prints as `LoanLimitError` without extra code.
- `getById` throws while `findById` returns `undefined`. Having both removes a lot of `if (!x) throw` noise from services.
- `findWhere` is a scan: O(n). Say so in the review, and mention that a real system would add an index (a `Map<isbn, copyId[]>`) or push the filter to the database.
- If you have a real repo, add `package.json` with `tsx` or `ts-node` so `npm start` runs the demo. Check it runs in the first ten minutes, not the last.
