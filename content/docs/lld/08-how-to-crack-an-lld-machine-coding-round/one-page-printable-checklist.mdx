---
title: "8.8 One-page printable checklist"
---

```text
┌──────────────────────── LLD / MACHINE-CODING CHECKLIST ────────────────────────┐
│ BEFORE THE ROUND                                                               │
│ [ ] Know the format (whiteboard 45-60 / machine coding 90-150) + language rules │
│ [ ] IDE ready; "hello world" in TypeScript runs (tsx/ts-node) in < 1 minute    │
│ [ ] Starter kit typed from memory: Clock, IdGenerator, errors, InMemoryRepo    │
│                                                                                │
│ 0-10 MIN  CLARIFY + SCOPE                                                      │
│ [ ] Actors, 3-5 core use cases, lifecycle of main entity                       │
│ [ ] Limits, money rules, time rules, duplicates, ordering (FIFO? priority?)    │
│ [ ] Concurrency expected? Driver or command parser? Tests expected?            │
│ [ ] Write IN / OUT / ASSUMPTIONS; read them back                               │
│                                                                                │
│ 10-25 MIN  DESIGN                                                              │
│ [ ] Nouns -> entities (identity + lifecycle?)  Verbs -> service methods        │
│ [ ] Split "type" from "instance" (Book/BookCopy, Show/Seat, Vehicle/Spot)      │
│ [ ] Reference by ID; 8-12 boxes; enums; plug-in interfaces                     │
│ [ ] Patterns only on named axes of change (Strategy/Observer/Spec/State/Cmd)   │
│ [ ] Service signatures written before code                                     │
│                                                                                │
│ 25-75 MIN  BUILD                                                               │
│ [ ] Skeleton in <= 8 min: enums, models, repos, services, app.ts, main.ts      │
│ [ ] ONE flow end-to-end + driver line, then the next flow                      │
│ [ ] Models guard transitions; services check rules in a clear order            │
│ [ ] Typed errors with codes; no null-for-failure; no magic numbers             │
│ [ ] Something runs by 60% of the time                                          │
│                                                                                │
│ 75-90 MIN  HARDEN                                                              │
│ [ ] STOP adding features at 80%                                                │
│ [ ] Validations: empty, negative, unknown id, illegal state, limits            │
│ [ ] Edge cases: last item, boundary dates, duplicates, repeat actions          │
│ [ ] Critical sections identified (guarded or explained)                        │
│ [ ] Demo in numbered scenes incl. errors; 4-8 PASS/FAIL assertions             │
│                                                                                │
│ REVIEW                                                                         │
│ [ ] 1-sentence summary -> run demo -> layers -> core method -> trade-offs      │
│ [ ] Extensions: restate -> locate -> list edits -> side effects                │
│ [ ] Concurrency: await-point races, per-key mutex, DB conditional update,      │
│     optimistic versions, idempotency; Java equivalents if asked                │
│ [ ] Say what you'd do with more time (parked list)                             │
│                                                                                │
│ ALWAYS: think aloud, announce checkpoints, prefer a clean subset over a buggy  │
│ whole.                                                                         │
└────────────────────────────────────────────────────────────────────────────────┘
```
