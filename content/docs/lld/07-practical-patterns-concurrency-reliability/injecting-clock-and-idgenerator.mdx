---
title: "7.6 Injecting Clock and IdGenerator"
---

## Intuition

`Date.now()` and `crypto.randomUUID()` are **hidden inputs**. Any rule that involves time ("quote valid for 30 s", "hold for 5 min", "rate limit per minute") becomes untestable, or needs flaky `sleep`s, if the code reads the real clock directly. Treat time and identity like any other dependency: **inject them**.

```ts
interface Clock {
  now(): number; // epoch ms
}
class SystemClock implements Clock {
  now(): number {
    return Date.now();
  }
}
class FakeClock implements Clock {
  constructor(private t: number) {}
  now(): number {
    return this.t;
  }
  advance(ms: number): void {
    this.t += ms;
  }
}

interface IdGenerator {
  next(): string;
}
class UuidGenerator implements IdGenerator {
  next(): string {
    return crypto.randomUUID(); // production
  }
}
class SequentialIdGenerator implements IdGenerator {
  private n = 0;
  constructor(private readonly prefix: string) {}
  next(): string {
    return `${this.prefix}-${String(++this.n).padStart(4, '0')}`;
  }
}

interface Quote {
  id: string;
  symbol: string;
  pricePaise: number;
  expiresAt: number;
}

class QuoteService {
  private readonly quotes = new Map<string, Quote>();
  constructor(
    private readonly clock: Clock,
    private readonly ids: IdGenerator,
    private readonly validForMs = 30_000,
  ) {}

  create(symbol: string, pricePaise: number): Quote {
    const q: Quote = { id: this.ids.next(), symbol, pricePaise, expiresAt: this.clock.now() + this.validForMs };
    this.quotes.set(q.id, q);
    return q;
  }

  accept(id: string): string {
    const q = this.quotes.get(id);
    if (!q) return `${id}: unknown quote`;
    const now = this.clock.now();
    if (now >= q.expiresAt) return `${id}: expired ${(now - q.expiresAt) / 1000}s ago`;
    this.quotes.delete(id);
    return `${id}: accepted ${q.symbol} @ ${q.pricePaise}`;
  }
}

// Production wiring would be: new QuoteService(new SystemClock(), new UuidGenerator())
const productionDeps: [Clock, IdGenerator] = [new SystemClock(), new UuidGenerator()];
console.log(`production deps: ${productionDeps.map(d => d.constructor.name).join(', ')}`);

const clock = new FakeClock(Date.UTC(2026, 0, 5, 3, 45, 0)); // 09:15 IST market open
const quotes = new QuoteService(clock, new SequentialIdGenerator('Q'));
const q1 = quotes.create('INFY', 150_000);
const q2 = quotes.create('TCS', 400_000);
console.log(`${q1.id} expires at ${new Date(q1.expiresAt).toISOString()}`);

clock.advance(29_999);
console.log(quotes.accept(q1.id));
clock.advance(1);
console.log(quotes.accept(q2.id));
clock.advance(4_000);
console.log(quotes.accept(q2.id));
console.log(quotes.accept(q1.id));
```

```text
production deps: SystemClock, UuidGenerator
Q-0001 expires at 2026-01-05T03:45:30.000Z
Q-0001: accepted INFY @ 150000
Q-0002: expired 0s ago
Q-0002: expired 4s ago
Q-0001: unknown quote
```

The boundary test (29,999 ms is valid, 30,000 ms has expired) runs in microseconds and gives the same answer every time. Try writing *that* with `setTimeout`.

## Pitfalls

- **`new Date()` inside entities.** Pass `now` in, or give the entity a clock.
- **Boundary ambiguity.** Decide on `>=` or `>` for expiry, write it down, and test both sides.
- **Sequential ids in production.** They're guessable (an enumeration attack). Use them in tests only, or use ULIDs/UUIDv7 when you want ids that sort by time.

## How to say it in an interview

> "Time and ids are dependencies, so I inject a `Clock` and an `IdGenerator`. Tests use a `FakeClock` that I advance by hand, so the 30-second expiry is tested exactly at the boundary without sleeping."
