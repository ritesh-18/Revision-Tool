---
title: "7. Practical Patterns, Concurrency & Reliability"
---

The GoF chapters taught you the *vocabulary*. This chapter is about what an SDE-2 interviewer is really looking for once you've drawn the class diagram: can your code survive two requests arriving at the same moment? Does a retry charge the customer twice? Can you test a "hold expires after 5 minutes" rule without waiting 5 minutes? Does your money add up to the last paisa?

You've already built Redis caches, BullMQ workers, idempotency keys and circuit breakers at work. Here we rebuild each of them **from scratch, in memory, in TypeScript**. That's exactly what a machine-coding round asks for, and it's also how you show you understand the tools rather than just calling them.

**What you'll learn**

- How to lay out a machine-coding solution in layers (models → repositories → services → strategies → driver) so it stays readable at the 90-minute mark
- A generic in-memory repository with Specification objects for queries
- Constructor injection, ports, and a tiny DI container / composition root
- Typed domain events, an in-process event bus, and the transactional outbox
- `Result` types vs exceptions, and a clean error hierarchy
- Injecting `Clock` and `IdGenerator` so tests are deterministic
- Money in integer paise with `bigint`, explicit rounding, and fair allocation
- **Concurrency in JS/TS**: where races really happen, and how to fix them with an async mutex, a semaphore, per-key locks, optimistic locking, TTL holds, idempotency keys and atomic synchronous sections, plus how Java/Go engineers solve the same problems
- Rate limiters (fixed window, sliding log, sliding counter, token bucket, leaky bucket)
- Retry with exponential backoff and jitter, and a circuit breaker state machine
- LRU, LFU and TTL caches; cache-aside vs write-through; single-flight
- A delayed priority job queue with retries and a dead-letter queue
- Observability hooks, and a checklist of "SDE-2 signals"
