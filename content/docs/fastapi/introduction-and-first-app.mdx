FastAPI is a Python web framework for building HTTP APIs. It is small, and most of its power comes from two libraries it stands on and one language feature it reads very carefully:

- **Starlette** does the web part: the ASGI interface, routing, `Request` and `Response` objects, middleware, WebSockets, background tasks and the test client.
- **Pydantic** does the data part: parsing and validating incoming data, and serializing outgoing data.
- **Type hints** are the glue. FastAPI reads your function signature once, at import time, and turns every annotated parameter into "where to find this value, how to convert it, and how to validate it". The same information becomes the OpenAPI schema and the interactive docs.

So FastAPI's own code is mostly a translator: it turns a Python function signature into a request-parsing plan and an API description. Everything on this page was run on **CPython 3.14.6** with **FastAPI 0.143.0**, **Pydantic 2.14.1** and **Starlette 1.8.0**.

## The three layers

<Mermaid chart={`flowchart TB
  C["HTTP client<br/>browser, curl, another service"] --> U["ASGI server: uvicorn<br/>sockets, HTTP parsing"]
  U --> S["Starlette<br/>routing, Request, Response, middleware"]
  S --> F["FastAPI<br/>reads signatures, builds validation plans, OpenAPI"]
  F --> P["Pydantic<br/>validate input, serialize output"]
  F --> E["Your endpoint function"]`} />

- **uvicorn** is not part of FastAPI. It is the server process that owns the sockets, parses raw HTTP bytes and calls your app through the ASGI interface. The next chapter, [ASGI and the request lifecycle](/docs/fastapi/asgi-and-the-request-lifecycle), builds that interface by hand.
- **Starlette** turns ASGI messages into `Request` objects and picks the route.
- **FastAPI** subclasses Starlette (`FastAPI` is a `Starlette` app, `APIRoute` is a Starlette `Route`) and adds the signature-driven layer.
- **Pydantic** is called by FastAPI on the way in (request validation) and on the way out (response serialization). See [Pydantic and runtime validation](/docs/python/pydantic-and-runtime-validation) for how it works on its own.

## Why FastAPI exists

Before FastAPI, the two common choices were Flask and Django. Both are good, and both were designed before Python had type hints or `async`/`await`.

| | Flask | Django (+ DRF) | FastAPI |
|---|---|---|---|
| Server interface | WSGI (sync) | WSGI, ASGI added later | ASGI (async first) |
| Request validation | by hand, or a plugin | DRF serializers (a separate class per shape) | from type hints and Pydantic models |
| API docs | plugin | plugin | OpenAPI and Swagger UI built in |
| Editor support for request data | `request.json["x"]` is untyped | serializer fields are untyped | parameters are typed, so autocomplete works |
| Batteries | minimal | ORM, admin, auth, templates, migrations | minimal, bring your own ORM and auth |
| Best fit | small sites and services | full web products with an admin | JSON APIs, microservices, AI backends |

The core idea is **one declaration, many uses**. In Flask, the shape of a request lives in three places: the code that reads it, the code that validates it, and the docs. They drift apart. Compare the same endpoint:

```python
# Flask: shape described by hand, validation by hand, docs elsewhere
@app.post("/books")
def create_book():
    data = request.get_json()
    if not isinstance(data.get("year"), int) or not 1450 <= data["year"] <= 2100:
        return {"error": "year must be an int between 1450 and 2100"}, 400
    if not data.get("title"):
        return {"error": "title is required"}, 400
    ...
```

```python
# FastAPI: the type is the parser, the validator and the documentation
class BookIn(BaseModel):
    title: str = Field(min_length=1)
    author: str
    year: int = Field(ge=1450, le=2100)

@app.post("/books", status_code=201)
async def create_book(book: BookIn) -> Book:
    ...
```

In the FastAPI version, `BookIn` is used four times: to parse the JSON body, to validate it, to give your editor a typed `book` object, and to write the request schema into OpenAPI. Change the model and all four change together.

The other reason is **async**. Flask and classic Django are WSGI: one request occupies one worker thread for its whole life, including the time it spends waiting on a database or another API. FastAPI is ASGI, so one process can keep thousands of slow requests in flight on one event loop. That matters a lot for AI backends, where a single request may wait 20 seconds for an LLM. See [asyncio](/docs/python/asyncio) for how the event loop works.

<Callout title="What FastAPI does not give you">
There is no ORM, no admin site, no user model and no migrations. You pick SQLAlchemy (see [Databases with SQLAlchemy](/docs/fastapi/databases-with-sqlalchemy)), write your own auth (see [Authentication and security](/docs/fastapi/authentication-and-security)) and choose your own layout (see [Project structure and settings](/docs/fastapi/project-structure-and-settings)). That is the price of being small.
</Callout>

## Installing with uv

[uv](https://docs.astral.sh/uv/) creates the project, the virtual environment and the lockfile in one tool:

```bash

cd hello-api
uv add "fastapi[standard]"
```

The `[standard]` extra is what turns the library into a working toolkit:

| Package | Why it is there |
|---|---|
| `fastapi-cli` | the `fastapi dev` and `fastapi run` commands |
| `uvicorn` (with `httptools`, `watchfiles`, `websockets`) | the ASGI server, a fast HTTP parser, auto-reload, WebSocket support |
| `python-multipart` | parsing form data and file uploads |
| `email-validator` | Pydantic's `EmailStr` |
| `httpx` | required by `TestClient` |
| `jinja2` | HTML templates |
| `pydantic-settings` | settings from environment variables |

Plain `uv add fastapi` installs only FastAPI, Starlette and Pydantic. That is what you want inside a library, but for an application, install `[standard]`. Without it, the `fastapi` command, form parsing and the test client all fail with "please install" errors. For more on environments and lockfiles, see [Packaging and environments](/docs/python/packaging-and-environments).

## The first app

```python title="main.py"
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}


@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}
```

Three things already happen that you didn't write code for:

1. `item_id` appears in the path template `/items/{item_id}`, so FastAPI takes it from the URL and converts the string `"42"` to the int `42`.
2. `q` is not in the path and is a simple type, so it becomes a query parameter. Its default of `None` makes it optional.
3. The returned `dict` is converted to JSON with the right `Content-Type`.

`fastapi` is a thin command-line wrapper around uvicorn. It finds the `FastAPI()` object in your file, builds the import string `main:app`, and starts uvicorn with sensible defaults:

| | `fastapi dev` | `fastapi run` |
|---|---|---|
| Meant for | your laptop | production, containers |
| Auto-reload on file change | on (a watcher process restarts the server) | off |
| Default host | `127.0.0.1`, only reachable from your machine | `0.0.0.0`, reachable from the network |
| Workers | 1 | 1, or `--workers N` for N processes |
| Roughly equivalent to | `uvicorn main:app --reload` | `uvicorn main:app --host 0.0.0.0` |

<Callout type="warn">
Never run `fastapi dev` in production. The reloader is a second process that watches the file system, which costs CPU and can restart your server in the middle of requests. Production setups (workers, proxies, containers) are covered in [Deployment and performance](/docs/fastapi/deployment-and-performance).

## The generated docs: `/docs`, `/redoc` and `/openapi.json`

Every FastAPI app ships three extra routes:

| URL | What it serves |
|---|---|
| `/openapi.json` | the **OpenAPI 3.1** description of your API, generated from your routes and types |
| `/docs` | Swagger UI, an interactive page where you can send requests |
| `/redoc` | ReDoc, a read-only reference page |

The two HTML pages are tiny. They contain no API information at all, only a `<script>` that loads the viewer from a CDN and points it at `/openapi.json`:

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI(title="Hello API", version="0.1.0")


@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}


client = TestClient(app)
for path in ["/docs", "/redoc"]:
    r = client.get(path)
    print(path, r.status_code, r.headers["content-type"], len(r.text), "bytes")

html = client.get("/docs").text
print([line.strip() for line in html.splitlines() if "swagger-ui" in line or "openapi.json" in line])
```

```text title="Output"
/docs 200 text/html; charset=utf-8 1008 bytes
/redoc 200 text/html; charset=utf-8 890 bytes
['<link type="text/css" rel="stylesheet" href="https://cdn.jsdelivr.net/npm/swagger-ui-dist@5/swagger-ui.css">', '<div id="swagger-ui">', '<script src="https://cdn.jsdelivr.net/npm/swagger-ui-dist@5/swagger-ui-bundle.js"></script>', "url: '/openapi.json',", '"dom_id": "#swagger-ui",']
```

```python
import json
spec = client.get("/openapi.json").json()
print(spec["openapi"], list(spec))
print(json.dumps(spec["paths"]["/items/{item_id}"], indent=2))
```

```text title="Output (short objects collapsed onto one line)"
      {

      },

        }

    "responses": {
      "200": {

        "content": { "application/json": { "schema": {} } }
      },

          }
        }
      }
    }
  }

```

Every piece maps back to the signature:

- `"summary": "Read Item"` comes from the function name `read_item`.
- `item_id` is `in: path`, `required: true`, `type: integer`, because of `item_id: int` and the `{item_id}` in the path.
- `q` is `in: query`, `required: false`, `string or null`, because of `q: str | None = None`.
- The `422` response is added to every route that takes parameters, because any of them can fail validation.
- The `200` schema is empty (`{}`) because we didn't declare a return type. Add `-> SomeModel` and it fills in (see [Responses, errors and status codes](/docs/fastapi/responses-errors-and-status-codes)).

Because the schema is a standard format, other tools can consume it: client generators for TypeScript and other languages, contract tests, API gateways, and LLM tool definitions. The backend lesson [OpenAPI](/docs/backend-first-principles/29-openapi) covers the format itself.

The schema is generated lazily on the first request to `/openapi.json` and cached in `app.openapi_schema`. To hide the docs (for example on a public production API), turn the URLs off:

```python
app = FastAPI(docs_url=None, redoc_url=None, openapi_url=None)
```

## How a decorator registers a route

`@app.get("/items/{item_id}")` looks like magic, but it is an ordinary [decorator factory](/docs/python/decorators). `app.get(path)` returns a decorator. The decorator registers the function and then **returns the very same function**, unwrapped:

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()

def hello(name: str = "world"):
    return {"hello": name}

decorator = app.get("/hello")                # step 1: app.get(...) builds a decorator
print(type(decorator).__name__, decorator.__name__)
returned = decorator(hello)                  # step 2: applying it registers the route
print("same function back:", returned is hello)

# the same thing without decorator syntax
def bye():
    return {"bye": True}
app.add_api_route("/bye", bye, methods=["GET"])

for route in app.routes:
    print(f"{type(route).__name__:<10} {route.path:<22} {sorted(route.methods)}")

client = TestClient(app)
print(client.get("/hello", params={"name": "ada"}).json())
print(client.get("/bye").json())
print(hello("direct call"))                  # still a plain function
```

```text title="Output"
function decorator
same function back: True
Route      /openapi.json          ['GET', 'HEAD']
Route      /docs                  ['GET', 'HEAD']
Route      /docs/oauth2-redirect  ['GET', 'HEAD']
Route      /redoc                 ['GET', 'HEAD']
APIRoute   /hello                 ['GET']
APIRoute   /bye                   ['GET']
{'hello': 'ada'}
{'bye': True}
{'hello': 'direct call'}
```

What happens inside, step by step:

<Mermaid chart={`sequenceDiagram
  participant M as Your module
  participant A as FastAPI app
  participant R as APIRouter
  participant RT as APIRoute
  M->>A: app.get with path
  A-->>M: decorator function
  M->>A: decorator applied to hello
  A->>R: add_api_route with path, hello, methods
  R->>RT: APIRoute constructor
  RT->>RT: compile path into a regex
  RT->>RT: inspect signature, build the dependant
  RT->>RT: build response field from return type
  RT->>RT: wrap handler as an ASGI app
  R->>R: append route to router.routes
  A-->>M: return hello unchanged`} />

1. `app.get("/hello")` delegates to `app.router.get(...)`, which calls `router.api_route("/hello", methods=["GET"], ...)`. That returns an inner function literally named `decorator`, with your options captured in its closure.
2. When the decorator is applied, it calls `router.add_api_route(...)`, which constructs an `APIRoute`.
3. The `APIRoute` constructor does all the expensive work **once**: it compiles the path into a regular expression, inspects the function signature to decide where each parameter comes from (this record is called the **dependant**), builds Pydantic validators for them, and builds a response serializer from the return annotation.
4. The route is appended to `app.router.routes`. On each request, the router walks this list **in order** and takes the first match.
5. The decorator returns your function untouched. You can still call `hello()` directly and unit-test it like any other function.

Two consequences follow:

- **Mistakes in a signature fail at import time, not at request time.** If you annotate a parameter with a type FastAPI can't handle, the decorator raises before the server even starts. The next chapter shows this.
- **Order matters.** A route declared earlier wins. `/users/{user_id}` declared before `/users/me` captures `me` as a user id. See [Path, query and body parameters](/docs/fastapi/path-query-and-body-parameters).

For the general idea of mapping URLs to handlers, see the backend lesson [Routing](/docs/backend-first-principles/06-routing).

## A quick tour

Here is a small API that touches most of Part 1: a request body model, validation, a response model, status codes and errors. Each feature gets its own chapter later, so focus on the shape.

```python
from fastapi import FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

app = FastAPI(title="Bookshelf")


class BookIn(BaseModel):
    title: str = Field(min_length=1)
    author: str
    year: int = Field(ge=1450, le=2100)


class Book(BookIn):
    id: int


BOOKS: dict[int, Book] = {}


@app.post("/books", status_code=201, tags=["books"])
async def create_book(book: BookIn) -> Book:
    """Add a book to the shelf."""
    new = Book(id=len(BOOKS) + 1, **book.model_dump())
    BOOKS[new.id] = new
    return new


@app.get("/books", tags=["books"])
async def list_books(limit: int = 10) -> list[Book]:
    return list(BOOKS.values())[:limit]


@app.get("/books/{book_id}", tags=["books"])
async def get_book(book_id: int) -> Book:
    if book_id not in BOOKS:
        raise HTTPException(status_code=404, detail="Book not found")
    return BOOKS[book_id]


c = TestClient(app)
r = c.post("/books", json={"title": "Dune", "author": "Frank Herbert", "year": 1965})
print(r.status_code, r.json())
r = c.post("/books", json={"title": "", "author": "X", "year": 3000})
print(r.status_code, r.json())
print(c.get("/books").json())
r = c.get("/books/99"); print(r.status_code, r.json())
r = c.get("/nope"); print(r.status_code, r.json())
r = c.delete("/books/1"); print(r.status_code, r.json(), r.headers.get("allow"))
op = c.get("/openapi.json").json()["paths"]["/books"]["post"]
print(op["summary"], "|", op["description"], "|", op["tags"], "|", list(op["responses"]))
```

```text title="Output"
201 {'title': 'Dune', 'author': 'Frank Herbert', 'year': 1965, 'id': 1}
422 {'detail': [{'type': 'string_too_short', 'loc': ['body', 'title'], 'msg': 'String should have at least 1 character', 'input': '', 'ctx': {'min_length': 1}}, {'type': 'less_than_equal', 'loc': ['body', 'year'], 'msg': 'Input should be less than or equal to 2100', 'input': 3000, 'ctx': {'le': 2100}}]}
[{'title': 'Dune', 'author': 'Frank Herbert', 'year': 1965, 'id': 1}]
404 {'detail': 'Book not found'}
404 {'detail': 'Not Found'}
405 {'detail': 'Method Not Allowed'} GET
Create Book | Add a book to the shelf. | ['books'] | ['201', '422']
```

Reading the output:

- **201**: `book: BookIn` is a Pydantic model, so FastAPI read it from the JSON body. The return type `-> Book` controls the response shape and the documented schema.
- **422**: both problems are reported at once, each with a `loc` (where), `msg` (what) and `type` (a machine-readable code). The handler never ran.
- **404 "Book not found"** came from our `HTTPException`. **404 "Not Found"** came from the router, because no route matched `/nope`.
- **405** came from the router as well: the path `/books/1` exists but not for `DELETE`. Starlette adds an `Allow: GET` header, as HTTP requires.
- The docstring became the operation's `description`, and `tags` group operations in Swagger UI.

`TestClient` calls the app in-process through the ASGI interface, with no network and no server. It is how most examples in these notes are run, and the [Testing](/docs/fastapi/testing) chapter covers it in depth.

## Traps

- **Installing `fastapi` without `[standard]`** in an application. The `fastapi` command, forms, file uploads and `TestClient` all need the extra packages.
- **Running `fastapi dev` in production.** It binds to `127.0.0.1` (unreachable inside a container) and runs a file watcher. Use `fastapi run` or a proper process setup.
- **Thinking the decorator wraps your function.** It doesn't. It registers the function and returns it unchanged, so calling `create_book(...)` directly skips validation entirely.
- **Declaring a catch-all route before a specific one.** Routes match in declaration order, so the first match wins.
- **Leaving `/docs` open on an internal or admin API** you don't want to advertise. Set `docs_url=None`, `redoc_url=None` and `openapi_url=None`, or protect them.
- **Expecting `/docs` to work offline.** Swagger UI's JavaScript and CSS load from a CDN. In an air-gapped network you have to self-host those assets.
- **Returning data without a return type or `response_model`.** It works, but the docs show an empty schema and nothing stops you from leaking fields. See [Responses, errors and status codes](/docs/fastapi/responses-errors-and-status-codes).

## Summary

- FastAPI = **Starlette** (ASGI, routing, requests, responses) + **Pydantic** (validation, serialization) + **type hints** (the single source of truth that drives both, plus the docs).
- It exists to remove the duplication between parsing, validation and documentation, and to be async-native for IO-heavy services.
- Install an application with `uv add "fastapi[standard]"`. Develop with `fastapi dev` (reload, localhost) and run with `fastapi run` (no reload, `0.0.0.0`).
- `/openapi.json` is generated from your routes and types. `/docs` and `/redoc` are thin HTML viewers over it.
- `@app.get(...)` is a decorator factory. It builds an `APIRoute`, analyses the signature once at import time, appends the route to an ordered list, and returns your function unchanged.
- Invalid input gets an automatic **422** before your code runs. Your handler only ever sees typed, validated values.
